# Phase 3 复习手册：并发 · JUC · 线程池

> **用法**：通读 45 min。线程池 7 参数 + AQS + volatile/synchronized 是必考点。

---

## 一、并发基础三要素

| 要素 | 含义 | 手段 |
|------|------|------|
| 原子性 | 不可分割 | synchronized、Lock、CAS |
| 可见性 | 一个线程改，其他线程能看见 | volatile、synchronized、final |
| 有序性 | 禁止指令重排 | volatile、happens-before |

### happens-before（无需死记，理解传递）

- 程序次序规则、锁规则、volatile 写→读、线程 start/join、传递性

---

## 二、synchronized

### 锁升级（JDK 6+，偏向锁可 `-XX:-UseBiasedLocking` 关闭）

```
无锁 → 偏向锁（同一线程反复进）→ 轻量级锁（CAS 竞争）→ 重量级锁（OS Mutex）
```

| 用法 | 锁对象 |
|------|--------|
| 实例方法 | 当前实例 `this` |
| 静态方法 | 类的 Class 对象 |
| 代码块 | 括号内指定对象 |

**与 Lock**：synchronized JVM 层面自动释放；ReentrantLock 可中断、可超时、公平锁、多 Condition。

---

## 三、volatile

- **可见性**：写立即刷到主存，读从主存读
- **禁止重排**：内存屏障
- **不保证原子性**：`i++` 不行

**经典：DCL 单例**

```java
private volatile static Singleton inst;
static Singleton get() {
    if (inst == null) {
        synchronized (Singleton.class) {
            if (inst == null) inst = new Singleton(); // volatile 防重排
        }
    }
    return inst;
}
```

---

## 四、CAS 与 ABA

- **CAS**：Compare And Swap，CPU 原子指令，乐观锁基础
- **ABA**：值 A→B→A，CAS 以为没变 → `AtomicStampedReference` 加版本号

**LongAdder**：高并发计数，分段累加，比 `AtomicLong` 吞吐高。

---

## 五、AQS（AbstractQueuedSynchronizer）

JUC 基石：`ReentrantLock`、`Semaphore`、`CountDownLatch`、`CyclicBarrier`、线程池 worker 都基于 AQS。

```
state（int）+ CLH 双向队列
├─ state=0 无人占，CAS 获取
├─ 失败 → 入队 park 阻塞
└─ release → 唤醒后继
```

| 组件 | state 含义 |
|------|------------|
| ReentrantLock | 0 未锁，>0 重入次数 |
| Semaphore | 剩余许可数 |
| CountDownLatch | 剩余计数 |

## 六、常用 JUC 工具

| 类 | 场景 |
|----|------|
| ReentrantLock | 需 tryLock、公平、多条件队列 |
| ReadWriteLock | 读多写少 |
| Semaphore | 限流、连接池大小 |
| CountDownLatch | 等多线程完成（一次性） |
| CyclicBarrier | 多线程互相等到齐（可循环） |
| Phaser | 更灵活的分阶段屏障 |

## 七、线程池 ThreadPoolExecutor

### 7 参数

```java
new ThreadPoolExecutor(
    corePoolSize,      // 核心线程数
    maximumPoolSize,   // 最大线程数
    keepAliveTime,     // 非核心线程空闲存活时间
    unit,
    workQueue,         // 任务队列
    threadFactory,
    handler            // 拒绝策略
);
```

### 执行流程

```
1. 线程数 < core → 新建核心线程执行
2. 否则任务入队
3. 队列满且线程数 < max → 新建非核心线程
4. 否则 → 拒绝策略
```

### 队列选型

| 队列 | 特点 | 场景 |
|------|------|------|
| ArrayBlockingQueue | 有界数组 | **生产推荐**，防 OOM |
| LinkedBlockingQueue | 可有界/默认极大 | 注意默认容量 ≈ Integer.MAX_VALUE |
| SynchronousQueue | 不存任务，直接交接 | 线程数 ≈ max，Cached 风格 |
| PriorityBlockingQueue | 优先级 | 定时/优先级任务 |

### 拒绝策略

| 策略 | 行为 |
|------|------|
| AbortPolicy | 抛异常（默认） |
| CallerRunsPolicy | 调用者线程执行（**降级、背压**） |
| DiscardPolicy | 静默丢弃 |
| DiscardOldestPolicy | 丢队列最老 |

**为什么不推荐 `Executors` 工厂**：
- `newFixedThreadPool` / `newSingleThreadExecutor` → 无界 `LinkedBlockingQueue`，任务堆积 OOM
- `newCachedThreadPool` → max 无限，线程爆炸

### 线程池隔离

- 不同业务**不同线程池**（订单 / 通知 / 查询），避免互相拖死
- 参数按：**CPU 密集 ≈ N+1；IO 密集 ≈ 2N 或按 RT 估算**

```
线程数 ≈ 核心数 × (1 + 等待时间/计算时间)
```

### CompletableFuture

```java
CompletableFuture.supplyAsync(() -> fetch(), executor)
    .thenApply(r -> transform(r))
    .thenCombine(other, (a, b) -> merge(a, b))
    .exceptionally(ex -> fallback);
```

**要点**：指定自己的 `executor`，别全用默认 `ForkJoinPool`。

## 八、ThreadLocal

- 每个线程一份副本，**线程隔离**
- **内存泄漏**：ThreadLocalMap 的 Entry 弱引用 key，强引用 value；线程池复用线程不销毁 → value 泄漏
- **解决**：用完 `remove()`；线程池场景尤其注意

---

## 九、死锁

**四个必要条件**：互斥、占有且等待、不可抢占、循环等待。

**排查**：`jstack` 看 `Found one Java-level deadlock`。

**避免**：固定加锁顺序、tryLock 超时、缩小锁粒度。

---

## 十、虚拟线程（Java 21）

- **轻量**，大量创建；阻塞 IO 时自动 unmount，不占用 OS 线程
- **适合**：IO 密集（HTTP、DB、RPC）
- **不适合**：CPU 密集、大量 synchronized 块（pin 到载体线程）、native 阻塞

```java
Executors.newVirtualThreadPerTaskExecutor();
```

## 十一、面试速答

| 问 | 答 |
|----|-----|
| synchronized 和 ReentrantLock？ | 前者 JVM 自动；后者 API 灵活、可中断公平、多 Condition |
| volatile 能保证原子吗？ | 不能，只可见+有序 |
| 线程池如何设参数？ | 有界队列+按业务隔离；IO/CPU 公式；拒绝策略 CallerRuns 做背压 |
| AQS 是什么？ | 状态变量+CLH 队列，JUC 锁和同步器基础 |
| ThreadLocal 泄漏？ | 线程池复用线程，Entry 强引用 value，用完 remove |

## 十二、易错点

- [ ] `@Async` 默认线程池可能不适合生产，要自定义
- [ ] 事务在异步线程里**失效**（新线程无 Spring 事务上下文）
- [ ] `parallelStream` 和业务线程池混用要小心 common pool 争用
- [ ] 锁粒度：能无锁就无锁，能读写锁就别互斥锁
