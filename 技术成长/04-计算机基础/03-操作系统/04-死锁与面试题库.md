# 第四章：死锁与面试题库

> **阅读目标**：掌握死锁条件与处理策略，会用 jstack 排查 Java 死锁，巩固 OS 综合面试题。
>
> **建议用时**：通读 60 min + 模拟 jstack 分析一次。

---

## 一、死锁定义

两个或多个进程/线程 **循环等待** 对方持有的资源，永久阻塞。

**经典例子**：

```
线程 A：持有 lock1，等待 lock2
线程 B：持有 lock2，等待 lock1
```

---

## 二、死锁四个必要条件

| 条件 | 含义 | 破坏方式 |
|------|------|----------|
| 互斥 | 资源一次只一持有者 | 资源可共享（有时不可） |
| 占有且等待 | 持部分资源并等更多 | 一次性申请所有 |
| 不可抢占 | 只能自愿释放 | 允许抢占（OS 级） |
| 循环等待 | 环状等待链 | 资源有序分配 |

**四者同时成立才死锁**；破坏任一即可预防。

---

## 三、处理策略

### 3.1 预防（Prevention）

- **按序加锁**：所有线程先 lock1 再 lock2
- **一次性分配**：申请全部资源才执行
- **无锁编程**：CAS、不可变对象

### 3.2 避免（Avoidance）

**银行家算法**：分配前模拟是否仍 **安全状态**（能找到完成序列）。

**特点**：需知道最大需求；进程数少时可用；实际 OS 少用。

### 3.3 检测与恢复

周期性 **资源分配图** 判环 → 杀进程/回滚。

**数据库**：检测死锁 → 回滚代价小的事务。

### 3.4 鸵鸟策略

偶尔死锁，重启；需监控告警。

## 四、Java 死锁

### 4.1 典型代码

```java
Object a = new Object(), b = new Object();

// Thread1: synchronized(a) { synchronized(b) {} }
// Thread2: synchronized(b) { synchronized(a) {} }
```

### 4.2 排查 jstack

```bash
jstack <pid> | grep -A 20 "deadlock"
```

输出示例：

```
Found one Java-level deadlock:
"Thread-1":
  waiting to lock monitor 0x... (object 0x..., a java.lang.Object),
  which is held by "Thread-0"
...
```

### 4.3 预防实践

- **固定加锁顺序** + 文档化
- **tryLock 超时** `ReentrantLock.tryLock(timeout)`
- **缩小锁粒度**、读写锁
- **避免嵌套锁**
- 用 **并发容器** 代替 synchronized Map

### 4.4 数据库死锁

InnoDB 行锁交叉更新 → 一方回滚；应用 **重试** + 短事务 + 同序访问行。

## 五、活锁与饥饿

| | 死锁 | 活锁 | 饥饿 |
|--|------|------|------|
| 状态 | 都不动 | 互相谦让反复变 | 某线程永远轮不到 |
| 例子 | AB-BA 锁 | 两人 corridor 让路 | 低优先级永不调度 |

## 六、同步原语（OS 视角）

| 原语 | 说明 |
|------|------|
| Mutex | 互斥锁 |
| Semaphore | 计数信号量 |
| RWLock | 读多写少 |
| Condition | 条件变量，配合 Mutex |
| Spinlock | 自旋，临界区极短 |

**Java 映射**：`synchronized`、`ReentrantLock`、`Semaphore`、`ReadWriteLock`、`wait/notify`。

## 七、综合面试题库

### 7.1 进程线程

**Q1：多进程 vs 多线程服务器？**  
多进程隔离好、内存大；多线程共享数据快但需同步；Java 常用多线程 + 线程池。

**Q2：用户线程和内核线程？**  
1:1（Java 传统）、M:N（虚拟线程多对少载体）。

**Q3：僵尸进程？**  
子进程结束父未 wait → 占 PID；父应 wait 或 SIGCHLD 处理。

### 7.2 内存

**Q4：缺页中断流程？**  
MMU 发现 present=0 → trap → OS 分配页框或 swap in → 更新页表 → 返回指令重试。

**Q5：为什么 Linux 用伙伴系统+slab？**  
伙伴分配页框；slab 缓存常用对象（inode）减碎片。

### 7.3 IO

**Q6：同步非阻塞和异步区别？**  
同步非阻塞：read 立即返回 EAGAIN，仍自己读；异步：内核读完回调。

**Q7：Netty 比 Tomcat BIO 优势？**  
少线程扛高并发、内存池、灵活 Pipeline。

### 7.4 死锁

**Q8：银行家算法安全状态？**  
存在安全序列使所有进程可完成。

**Q9：如何设计转账避免死锁？**  
按账户 ID 排序加锁；或单线程串行化热点账户。

**Q10：MySQL 死锁日志怎么看？**  
`SHOW ENGINE INNODB STATUS`；LATEST DETECTED DEADLOCK。

## 十三、读写锁与饥饿

**读优先**：读多写少但写可能饥饿。**写优先**或 **公平锁** 缓解。

Java `ReentrantReadWriteLock` 非公平默认；`StampedLock` 乐观读适合读极多。

## 十四、哲学家就餐代码（Java）

```java
Semaphore table = new Semaphore(4); // 最多 4 人同时就餐

void philosopher(int id) throws InterruptedException {
    table.acquire();
    try {
        pickLeft(id);
        pickRight(id);
        eat();
    } finally {
        putDown(id);
        table.release();
    }
}
```

或 **按序拿筷子**：`min(id, left)` 先拿。

## 十五、数据库与分布式锁

| 机制 | 死锁检测 |
|------|----------|
| InnoDB | 自动检测回滚代价小事务 |
| Redis Redisson | watchdog 续期，非 OS 死锁 |

## 十八、面试扩展 Q11–Q15

**Q11：活锁例子？**  
两线程 tryLock 失败退避随机化。

**Q12：优先级反转？**  
低优先级持锁，高优先级等锁，中优先级抢占低 → 解法优先级继承。

**Q13：自旋锁适用？**  
临界区 < 2 上下文切换时间；多核；Java `AtomicInteger` 自旋在 synchronized 升级前。

**Q14：银行家算法为何少用？**  
需预知 max need，进程动态变化难。

**Q15：Java 有死锁检测吗？**  
JVM 不自动破 deadlock；靠 jstack；数据库有。

## 二十、定时锁尝试（tryLock 模式）

```java
if (lock.tryLock(500, TimeUnit.MILLISECONDS)) {
    try {
        // 业务
    } finally {
        lock.unlock();
    }
} else {
    throw new BusinessException("系统繁忙");
}
```

避免无限等锁；配合 **锁顺序** 仍防死锁。

## 二十二、分布式死锁 vs 本地死锁

| | 本地 | 分布式 |
|--|------|--------|
| 检测 | jstack | 难 |

## 二十三、LockSupport 与 park/unpark

```java
LockSupport.park();
LockSupport.unpark(thread);
```

`AbstractQueuedSynchronizer` 底层；比 wait/notify 语义清晰（无需先持锁）。
