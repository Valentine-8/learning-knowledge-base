## 1. 生产故障案例

### 案例 1：磁盘满导致服务不可用

| 项 | 内容 |
|----|------|
| 现象 | 应用写日志失败，MySQL 无法写入 |
| 根因 | `/var/log` 未轮转，30 天积累 200GB |
| 修复 | 紧急清理 + logrotate + 监控告警 |
| 预防 | df 告警 85%；日志按大小轮转 |

### 案例 2：too many open files

| 项 | 内容 |
|----|------|
| 现象 | Java 报 IOException: Too many open files |
| 根因 | ulimit 1024，高并发 HTTP 连接未释放 |
| 修复 | limits.conf 65535；修复连接泄漏 |
| 预防 | 启动脚本 set ulimit；监控 FD 数 |

### 案例 3：LOAD 飙高但 CPU 空闲

| 项 | 内容 |
|----|------|
| 现象 | load 50，16 核，CPU %wa 60% |
| 根因 | 慢磁盘 + 大量随机读，MySQL 未命中缓冲 |
| 修复 | 加内存、优化 SQL、换 SSD |
| 预防 | iostat 监控 %util |

### 案例 4：CLOSE_WAIT 堆积

| 项 | 内容 |
|----|------|
| 现象 | 连接数万，新请求失败 |
| 根因 | HttpClient 未 close response body |
| 修复 | try-with-resources / finally close |
| 预防 | 监控 CLOSE_WAIT 数量 |

### 案例 5：OOM Killer 杀 Java

| 项 | 内容 |
|----|------|
| 现象 | 进程莫名消失，dmesg 有 OOM kill |
| 根因 | 容器 limit 2G，堆设 2G 无 native 余量 |
| 修复 | -Xmx 为 limit 70%；留 metaspace/direct memory |
| 预防 | 监控 cgroup memory，堆+非堆 < limit |

## 3. 排障场景题

**Q：网站突然 502，你怎么查？**

1. curl 本地/远程复现
2. Nginx error log
3. 后端进程存活、端口监听
4. ss 看连接状态
5. 应用日志异常栈
6. 资源 CPU/内存/磁盘

**Q：Java 服务内存持续增长？**

1. jmap -histo 看对象
2. MAT/VisualVM 分析 heap dump
3. 查 DirectMemory、Metaspace
4. 连接池/缓存是否无界
5. GC 日志 Full GC 是否频繁
