## 1. 三大支柱

| 支柱 | 回答什么 | 典型工具 |
|------|----------|----------|
| Metrics | 系统好不好？趋势？ | Prometheus + Grafana |
| Logging | 发生了什么？ | ELK、Loki |
| Tracing | 慢在哪一环？ | SkyWalking、Jaeger、Zipkin |

**Profiling**（持续剖析）是第四支柱：CPU/内存热点（Async Profiler、Pyroscope）。

---

## 2. Java 集成栈

```
Spring Boot Actuator
    └── Micrometer
            ├── Prometheus Registry → /actuator/prometheus
            ├── SkyWalking Agent（字节码增强）
            └── Logback JSON + traceId MDC
```

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus,metrics
  metrics:
    tags:
      application: ${spring.application.name}
```

---

## 3. Prometheus 速查

```promql
# QPS
rate(http_server_requests_seconds_count[5m])

# P99 延迟
histogram_quantile(0.99, rate(http_server_requests_seconds_bucket[5m]))

# JVM 堆使用
jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"}

# CPU
process_cpu_usage
```

## 4. 日志关联

```xml
<!-- logback 输出 traceId -->
<pattern>%d{ISO8601} [%thread] [%X{traceId}] %-5level %logger - %msg%n</pattern>
```

SkyWalking / Sleuth 自动注入 traceId 到 MDC。

## 5. 告警原则

| 原则 | 说明 |
|------|------|
|  actionable | 收到告警必须能行动 |
| 少而精 | 避免告警疲劳 |
| SLO 驱动 | 基于用户体验指标 |
| 分级 | P0 电话 / P1  IM / P2 工单 |

## 6. 黄金信号（Google SRE）

| 信号 | 指标 |
|------|------|
| Latency | P50/P99 延迟 |
| Traffic | QPS |
| Errors | 错误率 |
| Saturation | CPU/内存/连接池饱和度 |

## 7. 面试 5 分钟

| 问 | 答 |
|----|-----|
| 可观测性和监控区别？ | 观测是可探索未知问题；监控是已知指标告警 |
| Metrics 和 Logs 区别？ | 指标是数值时序；日志是离散事件 |
| Trace 如何跨服务？ | traceId 透传 HTTP Header / MQ |
| RED 方法？ | Rate、Errors、Duration |
| USE 方法？ | Utilization、Saturation、Errors（资源） |
