## 1. 生产故障案例

### 案例 1：容器频繁 OOMKilled

| 项 | 内容 |
|----|------|
| 现象 | Pod/容器重启，exit 137 |
| 根因 | limit 512M，未设 -Xmx，JDK 默认堆过大 |
| 修复 | `-XX:MaxRAMPercentage=70` 或显式 -Xmx384m |
| 预防 | 镜像模板统一 JAVA_OPTS；监控 working set |

### 案例 2：docker stop 丢请求

| 项 | 内容 |
|----|------|
| 根因 | 无 graceful shutdown，10s 内未处理完 |
| 修复 | Spring graceful + 加大 stop grace period |
| 预防 | 负载均衡先摘流量再 stop |

### 案例 3：镜像 1.2GB

| 项 | 内容 |
|----|------|
| 根因 | 单阶段，含 JDK+Maven+target |
| 修复 | 多阶段 + jre-alpine |
| 预防 | CI 检查镜像大小门禁 |

### 案例 4：Compose 连不上 MySQL

| 项 | 内容 |
|----|------|
| 根因 | `jdbc:mysql://127.0.0.1:3306` |
| 修复 | 改为服务名 `mysql:3306` |
| 预防 | docker profile 专用配置 |

### 案例 5：层缓存失效 CI 慢

| 项 | 内容 |
|----|------|
| 根因 | `COPY . .` 在第一行 |
| 修复 | 先 COPY pom.xml 再 dependency:go-offline |

## 3. 参考答案精选

**Q2 Docker vs VM**：共享内核、秒级启动、镜像 MB 级；隔离弱于 VM。

**Q23 容器 JVM 堆**：JDK11+ Container Support；MaxRAMPercentage 或 -Xmx 约为 limit 70%。

**Q25 OOMKilled vs Java OOM**：前者 cgroup 超限被内核杀（137）；后者堆溢出抛 OutOfMemoryError。

**Q34 dockershim**：K8s 通过 CRI 对接 containerd/CRI-O，不再绑定 Docker 引擎。
