## 1. 生产故障案例

### 案例 1：发布后全站 502

| 项 | 内容 |
|----|------|
| 现象 | 部署新版本 Java 后 Nginx 502 |
| 根因 | Docker 网络仍用 `127.0.0.1:8080`，应改为 `app:8080` |
| 修复 | 改 upstream + `nginx -t && reload` |
| 预防 | Compose/K8s 用服务名；发布 checklist |

### 案例 2：偶发 504 超时

| 项 | 内容 |
|----|------|
| 现象 | 导出 Excel 接口 504 |
| 根因 | `proxy_read_timeout` 默认 60s，导出需 3 min |
| 修复 | 该 location `proxy_read_timeout 300s`；更好异步导出 + 轮询 |
| 预防 | 长任务异步化；网关超时分 location |

### 案例 3：WebSocket 频繁断开

| 项 | 内容 |
|----|------|
| 现象 | 聊天 60s 断连 |
| 根因 | 缺升级头 + `proxy_read_timeout 60s` |
| 修复 | 加 Upgrade/Connection，`proxy_read_timeout 3600s` |
| 预防 | WebSocket 单独 location 模板 |

### 案例 4：HTTPS 重定向循环

| 项 | 内容 |
|----|------|
| 现象 | 浏览器 ERR_TOO_MANY_REDIRECTS |
| 根因 | Nginx 443→http 后端，Spring Security 强制 https 但未识别 X-Forwarded-Proto |
| 修复 | `forward-headers-strategy: framework` + Nginx 设 `X-Forwarded-Proto` |
| 预防 | 内网 HTTP 终结 SSL 的标准配置清单 |

### 案例 5：上传 413 Request Entity Too Large

| 项 | 内容 |
|----|------|
| 根因 | Nginx `client_max_body_size` 1m，Spring multipart 10m |
| 修复 | 两处对齐为 50m |

### 案例 6：ip_hash 扩容后会话丢失

| 项 | 内容 |
|----|------|
| 根因 | 新增节点导致 hash 环变化 |
| 修复 | 改 JWT + Redis Session；或 consistent hash |
| 预防 | 无状态设计 |

## 3. 参考答案要点（精选）

**Q3 高并发原因**

多 Worker + 事件驱动（epoll）+ 非阻塞 IO；单 Worker 单线程避免锁；静态文件 sendfile 零拷贝。

**Q10 proxy_pass slash**

`location /api/` + `proxy_pass http://x/` → `/api/user` → `/user`。无尾部 slash 则 URI 原样转发。

**Q12 502 vs 504**

502：无效网关（连接拒、空响应、协议错）。504：`proxy_read_timeout` 内上游无完整响应。

**Q36 真实 IP**

Nginx 设 `X-Forwarded-For` / `X-Real-IP`；Spring `forward-headers-strategy: framework` 或 `RemoteIpValve`。

**Q50 全链路**

DNS → LB → Nginx TLS → location → upstream 选节点 → proxy → Tomcat/Netty → Filter 链 → Controller → JSON → Nginx 回写 → 客户端。
