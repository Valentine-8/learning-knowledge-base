## 1. 排障命令速查

```bash
# 事件（第一时间看）
kubectl get events -n prod --sort-by='.lastTimestamp'

# Pod 状态
kubectl get pods -n prod -o wide
kubectl describe pod <name> -n prod

# 日志
kubectl logs <pod> -n prod -c app --tail=500
kubectl logs <pod> -n prod --previous    # 崩溃前一次

# 进容器
kubectl exec -it <pod> -n prod -- sh

# 临时调试
kubectl run tmp --rm -it --image=busybox -- wget -qO- http://order-app/actuator/health

# 副本与发布
kubectl rollout status deployment/order-app -n prod
kubectl get rs -n prod

# 资源
kubectl top pod -n prod
kubectl describe node
```

## 2. Pod 状态含义

| Status | 含义 |
|--------|------|
| Pending | 调度中、拉镜像、挂 PVC |
| Running | 至少一容器在跑 |
| CrashLoopBackOff | 启动后反复退出 |
| ImagePullBackOff | 镜像拉取失败 |
| OOMKilled | 内存超限 |
| Evicted | 节点压力驱逐 |
| Terminating | 删除中 |

## 3. 生产故障案例

### 案例 1：CrashLoopBackOff

| 步骤 | 操作 |
|------|------|
| 1 | `kubectl logs --previous` |
| 2 | `describe` 看 Last State、Exit Code |
| 3 | 137 → OOM；1 → 应用错误 |

**常见根因**：探针太早、配置错、OOM、缺少 Secret。

### 案例 2：滚动更新卡死

| 根因 | readiness 永不通过 |
| 修复 | 查 Actuator；调 initialDelay；修 DB 连接 |

```bash
kubectl rollout undo deployment/order-app
```

### 案例 3：Ingress 502

| 根因 | Endpoints 空 / Pod not ready |
| 修复 | 修 selector、探针、应用启动 |

### 案例 4：发布后旧连接 502

| 根因 | 无 preStop，流量仍进 terminating Pod |
| 修复 | preStop sleep + graceful shutdown |

### 案例 5：HPA 不生效

| 根因 | 未装 metrics-server；requests 未设 |
| 修复 | 装 metrics-server；设 resources.requests |

### 案例 6：ConfigMap 更新不生效

| 根因 | Pod 未重启，挂载未热更 |
| 修复 | rollout restart；或用 Spring Cloud K8s reload |

## 5. 参考答案精选

**Q6 Pod**：最小调度单元；Init + 主容器 + Sidecar；共享 network namespace。

**Q25 探针**：startup 慢启动保护；readiness 决定是否进 Service；liveness 死则重启。

**Q35 CrashLoop**：logs previous → describe exit code → 探针/配置/OOM/镜像。

**Q40 Docker vs K8s**：Docker 单机容器；K8s 多机编排、自愈、发布、服务发现。
