### P4：CloudCC Site 网关（cc-site-svc）

#### 业务定位
**Experience Cloud 站点边缘 BFF**：无 DB 状态less 代理；站点 token、OpenCall、文件上传下载、微信集成。

#### 技术路线

| 层级 | 选型 |
|------|------|

| 容器 | **Undertow**（排除 Tomcat） |

| 通信 | **RestTemplate** + JWT（HMAC256 `"szyd"`） |
| 模式 | **RPCCatalog** + `BaseService.mainSvcCaller` |

#### 核心链路

```
站点前端 → POST /api/site/getSiteToken
  → 解密站点参数 + domain 查 sysconfig 得 orgId
  → 解析 per-org main-svc / openapi 地址（ServiceUrlManager 缓存）
  → RPC one-main-svc 签发 platform token

业务调用 → POST /api/site/openCall/common
  → 代理到租户 backend 执行自定义类/方法（Salesforce 式 OpenCall）
```

#### 亮点与安全

- **多租户按 orgId 路由** 后端地址（内存缓存 `{orgId}_mainsvcAddress`）
- **站点参数加密**（AES/DES，与 setup-service 站点密钥 **`ccsitecc` 一致**）
- XSS / SQL 注入过滤器
- **无本地 DB**：纯 BFF，故障域小、易水平扩展

#### 高级理解表述（独立负责人版）

> **cc-site-svc 是我从 0 独立实现的服务**：无 DB、纯 BFF，把公网站点和 CloudCC 核心隔开。我实现 getSiteToken 全链路（解密→sysconfig→ServiceUrlManager→RPC）、OpenCall 与文件代理，以及和 setup 一致的 **`ccsitecc` 密钥契约**。这是我大型 SaaS **边缘网关** 经验的代表项目。

### Q1. 为什么 mall 用 MySQL 存向量，AICRM 用 Weaviate？

**A：**

### Q3. Setup 和 Main 为什么要拆？

**A：** Setup 操作低频但复杂（元数据、批量导入），Main 高频交易查询。分离后 **Setup 升级/锁布局** 不影响 CRM 运行时 SLA；权限模型也可分离（仅管理员进 Setup）。

### Q4. 你的 Java 8 WAR 和 Java 17/21 Boot3 经验怎么统一讲？

**A：** 同一 SaaS 产品线 **渐进现代化**：legacy core 求稳；新服务（setup、cloudbb、mall）用新栈。我能在 **Boot3、虚拟线程、Spring Security 6** 与 **遗留 Cayenne/WS session** 之间做 **集成与迁移设计**。

## 四、项目经历面试 Q&A（按项目）

### 4.1 mall 商城

**Q：介绍一下商城项目架构。**  
**A：** 基于 RuoYi-Vue 的模块化单体，Java17+Boot3.5，MySQL+Redis，Vue3 双端。核心链路：商品→购物车→下单（ `@Transactional`）→模拟支付→状态机。扩展了 AI 客服与 MySQL RAG 知识库，OpenAI 兼容接口，支持转人工。

**Q：库存怎么防超卖？**  
**A：** `update ... where stock >= quantity` 乐观扣减，影响行数 0 则失败；订单取消/退款 restoreStock。当前无秒杀；若 QPS 上千会加 Redis 预扣+Lua+异步落库。

**Q：RAG 怎么实现的？为什么不用向量库？**  
**A：** 上传→解析→Chunk→Embedding API→JSON 存 MySQL→检索时余弦相似度 Top-K→拼 system prompt。选型为 **降低运维与依赖**；检索 <100ms 级可接受。Hybrid 关键词 fallback 防 Embedding 失败。

**Q：AI 客服如何转人工？**  
**A：** 会话状态机；关键词或用户请求触发；检查坐席 `maxConcurrent`；waiting 队列；人工消息走同一 session 表。

**Q：如果让你做秒杀怎么设计？**  
**A：** 静态 CDN、按钮 token、Redis 预减库存 Lua、MQ 异步创建订单、DB 乐观锁兜底、限流 Sentinel、热点隔离。

---

### 4.2 AICRM

**Q：多租户怎么实现的？**  
**A：** Registry 库登记租户；每租户独立 PostgreSQL；中间件 `TenantEngineMiddleware` 从 host/token 解析 tenant，路由 DataSource。Widget 公网嵌入单独 CORS 策略。

**Q：WhatsApp 消息怎么接入 AI？**  
**A：** Meta Webhook → FastAPI → 会话入库 → 调 `request_ai_reply` → 可选 KB 检索（Weaviate）→ 回复 API；nurture _campaign 支持营销自动化 handoff。

**Q：与 CloudCC CRM 集成做了什么？**  
**A：** integration API 同步 contacts/deals；出站 `crm_outbound_sync`；Widget 访客提升为 CRM contact。价值是 **AI 层不替换 legacy CRM**。

**Q：为什么后端用 Python 不是 Java？**  
**A：** AI 生态（LangChain、快速迭代）、团队分工；Monorepo 内 sales-agent 可 Java 对接。ToB 看交付速度 + AI 库成熟度。

### 4.3 cloudbb — **代理商（你的模块）**

**Q：你在 CloudBB 做了什么？**  
**A：** **经销商子系统**，不是整站。代理商管理、返佣规则、折扣码、`AgentRebateServiceImpl` 拉 appstore 订单算佣、月度定时汇总。代码在 `controller/sellingagent` 包。

**Q：返佣怎么算？**  
**A：** 阶梯规则 + `RebateCalculator`；写 `BbAgentRebateDetail`；`MonthlyRebateScheduleConfig` 汇总。重点 **订单幂等**，不重复计佣。

**Q：和 appstore 怎么交互？**  
**A：** HTTP 拉订单；失败重试/对账。本服务不持有支付状态。

**Q：整个 CloudBB 架构？**  
**A：** 一句：教育内容中台 PG+Mongo。**我深度只在渠道返佣域**。

### 4.4 cc-site-svc — **你独立实现**

**Q：site-svc 是谁做的？**  
**A：** **我独立从 0 完成**整个服务：无 DB 的 BFF，getSiteToken、OpenCall、文件代理、ServiceUrlManager 多租户路由、安全过滤器。

**Q：为什么不做进 main-svc？**
