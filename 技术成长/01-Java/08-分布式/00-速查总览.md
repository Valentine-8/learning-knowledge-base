## 1. CAP 与 BASE

```
分布式系统必须接受 P（分区容错）
        │
   ┌────┴────┐
   ▼         ▼
  CP        AP
强一致     高可用
短暂不可用  短暂不一致
ZK/etcd    Eureka/Cassandra
```

**BASE**：基本可用 + 软状态 + **最终一致**（互联网业务主流）。

## 2. 分布式事务选型

| 方案 | 一致性 | 侵入 |
|------|--------|------|
| 2PC | 强 | 协调者单点、阻塞 |
| TCC | 最终 | 业务三接口 |
| Saga | 最终 | 补偿链 |
| 本地消息表 | 最终 | 同库事务 |
| Seata AT | 最终 | undo_log，较透明 |
| **推荐思路** | 能避免就避免；**最终一致 + 补偿/MQ** | |

## 3. 分布式锁 / ID（概要）

| 锁 | 特点 |
|----|------|
| Redis | 快；主从切换边界见 Redis 专题 |
| ZK 临时顺序节点 | 强一致；性能/运维成本高 |
| DB 唯一索引 | 简单慢 |

| ID | 特点 |
|----|------|
| 雪花 Snowflake | 趋势递增，依赖时钟/机器 ID |
| 号段 | DB/Redis 批量取段，性能高 |
| UUID | 无序，索引不友好 |

**Redis 锁细节** → [Redis/04](../../02-数据与中间件/03-Redis/04-分布式锁与并发.md)

## 4. 限流 · 熔断 · 降级

| 概念 | 一句话 |
|------|--------|
| **限流** | 控制 QPS（令牌桶/漏桶/滑动窗口） |
| **熔断** | 下游故障 → 快速失败 → 半开探测 |
| **降级** | 关非核心，返回兜底 |

**Sentinel**：滑动窗口 + 规则热更新（见 [04 章](./04-限流熔断降级.md)）。

## 6. ZooKeeper 要点

- **CP** 系统；Leader 选举期间可能不可用
- **临时节点** session 断开自动删 → 注册/锁
- **顺序节点** → 公平锁、队列
- **Watcher** 一次性；Curator 封装重试与 PathChildrenCache

详见 [06 章](./06-ZooKeeper与注册中心.md)。

## 8. 高频面试 5 题

| 问 | 答 |
|----|-----|
| CAP 怎么选？ | 必 P；CP 强一致；AP 高可用最终一致 |
| 分布式事务能不用吗？ | 优先本地事务 + MQ 最终一致 |
| 接口幂等？ | 唯一键、Token、状态机 |
| 限流算法？ | 令牌桶允许突发；漏桶平滑 |
| ZK 为何 CP？ | 写入走 Leader，少数派不可写 |
