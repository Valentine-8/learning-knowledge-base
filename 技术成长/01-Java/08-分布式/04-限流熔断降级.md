# 04 · 限流 · 熔断 · 降级

> **目标读者**：7 年 Java 后端，能讲清限流算法、熔断状态机，并分层使用 Sentinel / Gateway / Nginx。
> **预计阅读**：50 min · **难度**：★★★★

---

## 1. 三板斧关系

```
流量过大 ──► 限流（主动拒绝）
下游故障 ──► 熔断（快速失败，防雪崩）
资源不足 ──► 降级（关非核心，保核心）
```

三者配合 **保护自身与依赖**，是微服务稳定性基石。

---

## 2. 限流

### 2.1 为什么限流

- 防止突发流量打垮服务
- 公平分配资源
- 为依赖（DB、第三方 API）设上限

### 2.2 常见算法

| 算法 | 原理 | 特点 |
|------|------|------|
| **固定窗口** | 每分钟最多 N 次 | 实现简单；窗口边界 **双倍突发** |
| **滑动窗口** | 细分时间片统计 | 更平滑；Sentinel 采用 |
| **漏桶 Leaky Bucket** | 恒定速率出水 | 输出平滑；无法应对合理突发 |
| **令牌桶 Token Bucket** | 恒定速率放令牌，有令牌则过 | **允许突发**；Guava RateLimiter |

```
令牌桶：桶容量 B，速率 r 放令牌
  请求消耗 1 令牌；无令牌则等待或拒绝
```

### 2.3 限流维度

| 维度 | 示例 |
|------|------|
| QPS | 接口每秒 1000 |
| 并发线程 | 同时 50 个调用 |
| 用户/IP | 防刷 |
| 热点参数 | 某商品 ID 限购 |

## 3. 熔断

### 3.1 雪崩

服务 A → B → C，C 慢 → B 线程堵满 → A 堵满 → **级联故障**。

### 3.2 熔断器状态机

```
    失败率/慢调用超阈值
 closed ─────────────────► open（直接失败）
   ▲                         │
   │                         │ 超时后
   │                         ▼
   └──── 探测成功 ───── half-open（放行少量）
              探测失败 ──► open
```

| 状态 | 行为 |
|------|------|
| **closed** | 正常调用，统计失败率 |
| **open** | 快速失败，不调用下游 |
| **half-open** | 放试探请求，成功则 closed |

### 3.3 Hystrix（维护模式）

- 线程池隔离 / 信号量隔离
- 已停更，新项目用 **Sentinel** 或 **Resilience4j**

## 4. 降级

| 类型 | 示例 |
|------|------|
| 功能降级 | 关推荐、关评论，保下单 |
| 读降级 | 缓存兜底、返回默认值 |
| 写降级 | 异步 MQ 排队 |
| 人工开关 | 配置中心 `feature.xxx=false` |

**与熔断区别**：降级是 **主动** 减功能；熔断是 **被动** 保护（下游坏了才跳）。

## 5. Sentinel 实战要点

阿里开源，**流量控制 + 熔断降级 + 系统保护 + 热点参数**。

```
请求 → Slot Chain（NodeSelector → ClusterBuilder → Statistic → Flow → Degrade）
```

### 5.1 流控规则

```java
@SentinelResource(value = "createOrder", blockHandler = "handleBlock")
public Order create(CreateCmd cmd) { }

public Order handleBlock(CreateCmd cmd, BlockException ex) {
    throw new BizException("系统繁忙");
}
```

| 流控效果 | 说明 |
|----------|------|
| 直接拒绝 | 默认 |
| Warm Up | 冷启动预热 |
| 排队等待 | 匀速器 |

### 5.2 熔断规则

| 策略 | 说明 |
|------|------|
| 慢调用比例 | RT > 阈值的比例达线 |
| 异常比例 | 异常占比 |
| 异常数 | 窗口内异常次数 |

### 5.3 与 Feign / Gateway

- Feign + Sentinel：对 `@FeignClient` 资源名配规则
- Gateway：`gw-flow` 网关层限流

详见 [SpringCloud/06-Sentinel与Seata](../05-SpringCloud/06-Sentinel与Seata.md)。

## 6. 分层治理

| 层级 | 工具 | 作用 |
|------|------|------|
| CDN / WAF | 云厂商 | 大流量、攻击 |
| Nginx | `limit_req` | 入口 IP 限流 |
| Gateway | Sentinel gw | 按路由/API |
| 服务 | `@SentinelResource` | 方法级、热点 |
| 依赖 | Feign 熔断 | 保护调用方线程 |

**原则**：能在 **靠近入口** 限的不要全打到 DB。

## 7. Resilience4j（了解）

Spring Cloud 生态轻量替代：

- RateLimiter、CircuitBreaker、Bulkhead、Retry
- 函数式 API，无 Agent

新项目若不用 Alibaba 栈可考虑。

## 8. 生产案例

**案例**：大促未限流，DB 连接池耗尽全站 500。

**修复**：

- Gateway 全局限 QPS
- 核心接口 Sentinel 热点参数限流
- 非核心功能配置降级开关
- DB 连接池 + 线程池隔离

## 9. 面试题精选

**Q：令牌桶和漏桶区别？**  
A：令牌桶允许一定突发（桶内令牌）；漏桶输出速率严格恒定。

**Q：熔断和超时区别？**  
A：超时单次调用放弃；熔断是统计下游整体健康，一段时间内 **直接短路**。

**Q：限流返回 429 还是 200+ 业务码？**  
A：HTTP 429 语义清晰；国内很多用 200 + code，网关层建议 429。

## 10. 本章小结

- **限流**防流量；**熔断**防故障扩散；**降级**保核心。
- Sentinel **滑动窗口 + 规则热更新** 是 Java 微服务主流。
- 分层：Nginx → Gateway → 服务 → 依赖。
