# 04 · 测试策略与覆盖率

> **预计阅读**：80 min

---

## 1. 测试金字塔（再强调）

```
70% 单元 + 20% 集成 + 10% E2E（比例参考，非教条）
```

| 层级 | 测什么 | 工具 |
|------|--------|------|
| 单元 | 领域逻辑、纯函数 | JUnit + Mockito |
| 集成 | DB、MQ、Spring 上下文 | Spring Test + Testcontainers |
| E2E | 全链路 UI/API | Selenium、Postman、Playwright |
| 契约 | 服务间接口 | Pact、Spring Cloud Contract |

---

## 2. 测什么 / 不测什么

### 应该测

- 核心业务规则（定价、库存、权限）
- 边界与异常分支
- 公共组件与工具类
- Bug 修复回归用例

### 不必测

- Getter/Setter（Lombok 生成）
- 框架本身（Spring 已测）
- 简单 CRUD 无逻辑（可选）
- 第三方 SDK 封装一层胶水

---

## 3. TDD 工作流

```
1. 红：写失败测试
2. 绿：最小实现通过
3. 重构：优化结构，测试仍绿
```

**适用**：复杂领域逻辑、算法。
**不必教条**：遗留代码可先补测试再改。

---

## 4. 覆盖率 JaCoCo

```xml
<plugin>
  <groupId>org.jacoco</groupId>
  <artifactId>jacoco-maven-plugin</artifactId>
  <executions>
    <execution>
      <goals><goal>prepare-agent</goal></goals>
    </execution>
    <execution>
      <id>report</id>
      <phase>test</phase>
      <goals><goal>report</goal></goals>
    </execution>
  </executions>
</plugin>
```

| 指标 | 含义 |
|------|------|
| 行覆盖 | 执行过的行 |
| 分支覆盖 | if/switch 分支 |
| 方法覆盖 | 调用的方法 |

**门禁**：核心模块分支覆盖 ≥ 70%（团队自定），**不追求 100%**。

---

## 5. 测试命名与组织

```
类名：OrderServiceTest / OrderControllerIT
方法：should_xxx_when_yyy / createOrder_withInvalidStock_throws
目录：src/test/java 镜像 main 包结构
```

---

## 6. CI 集成

```yaml
- run: mvn verify
- run: mvn jacoco:check   # 可选门禁
```

- PR 必跑单测
- 集成测试可 nightly 或 merge 前
-  flaky 测试零容忍（修或删）

---

## 7. 测试替身（Test Double）

| 类型 | 说明 |
|------|------|
| Dummy | 占位参数 |
| Stub | 固定返回值 |
| Mock | 验证交互 |
| Fake | 简化实现（内存 DB） |
| Spy | 部分真实部分 mock |

---

## 8. 7 年工程师测试观

- 推动团队**测试文化**，不是个人 hero
- Review 要求核心路径有测试
- 重构前**先补测试**（ characterization test）
- 性能测试、混沌测试与功能测试分工

---

## 9. 反模式

- [ ] 覆盖率崇拜，断言 meaningless
- [ ] 集成测试过多导致 CI 30 min+
- [ ] 测试依赖执行顺序
- [ ] 生产数据拷到测试
- [ ] 从不维护过时测试（删或修）
