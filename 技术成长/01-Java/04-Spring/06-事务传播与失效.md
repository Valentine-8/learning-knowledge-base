# 06 · 事务传播与失效

> **目标读者**：精通 7 种传播行为、隔离级别、失效场景与源码（TransactionInterceptor），能设计事务边界。
> **预计阅读**：60 min · **难度**：★★★★★

---

## 1. 声明式事务

```java
@Service
public class OrderService {
    @Transactional(rollbackFor = Exception.class)
    public Order createOrder(CreateOrderCmd cmd) {
        Order order = orderMapper.insert(...);
        inventoryClient.deduct(...);  // 远程调用慎放事务内
        return order;
    }
}
```

**原理**：`@EnableTransactionManagement` → `AnnotationTransactionAttributeSource` → AOP 代理 → `TransactionInterceptor.invoke`。

## 2. 七种传播行为

| 传播 | 含义 | 典型场景 |
|------|------|----------|
| **REQUIRED**（默认） | 有事务加入，无则新建 | 一般业务 |
| **SUPPORTS** | 有则加入，无则非事务执行 | 查询可选 |
| **MANDATORY** | 必须在事务内，否则异常 | 强制被调方在事务中 |
| **REQUIRES_NEW** | 挂起当前，**总是新建** | 独立日志、审计不受外层回滚 |
| **NOT_SUPPORTED** | 挂起当前，非事务执行 | 调不支持事务的组件 |
| **NEVER** | 非事务，有事务则异常 | 禁止在事务中 |
| **NESTED** | 嵌套保存点，外层回滚全回滚；内层回滚仅滚保存点 | 部分失败可单独回滚（需 JDBC 保存点） |

### 2.1 REQUIRED vs REQUIRES_NEW

```java
@Transactional
public void outer() {
    repo.insertA();
    innerService.log();  // REQUIRES_NEW
    throw new RuntimeException();  // outer 回滚，log 已提交独立事务
}

@Transactional(propagation = Propagation.REQUIRES_NEW)
public void log() {
    auditRepo.insert(...);
}
```

### 2.2 NESTED

```java
@Transactional
public void outer() {
    repo.step1();
    try {
        innerService.nestedOp();  // NESTED
    } catch (Exception e) {
        // nestedOp 回滚到保存点，outer 可继续
    }
    repo.step2();
}
```

**注意**：NESTED 依赖底层 **Savepoint**；部分 JTA 不支持。

## 3. 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|------------|------|
| READ_UNCOMMITTED | 可能 | 可能 | 可能 |
| READ_COMMITTED | 否 | 可能 | 可能 |
| REPEATABLE_READ | 否 | 否 | 可能* |
| SERIALIZABLE | 否 | 否 | 否 |

*MySQL InnoDB RR + MVCC 多数场景防幻读。

```java
@Transactional(isolation = Isolation.READ_COMMITTED)
```

**默认**：使用数据库默认（MySQL InnoDB RR，PG RC）。

---

## 4. rollback 规则

| 异常 | 默认 |
|------|------|
| RuntimeException / Error | **回滚** |
| Checked Exception | **不回滚** |

```java
@Transactional(rollbackFor = Exception.class)  // 所有异常回滚
@Transactional(noRollbackFor = BizException.class)  // 指定不回滚
```

**异常被 catch 吞掉** → 不回滚：

```java
@Transactional
public void bad() {
    try {
        mapper.update();
    } catch (Exception e) {
        log.error("", e);  // 未抛出，事务提交！
    }
}
```

## 5. 失效场景（必背 7 条）

| # | 场景 | 原因 |
|---|------|------|
| 1 | **方法非 public** | AOP 无法代理 public 以外 |
| 2 | **同类自调用** | 绕过代理 |
| 3 | **异常被捕获未抛出** | 事务管理器不知失败 |
| 4 | **checked 异常未配 rollbackFor** | 默认提交 |
| 5 | **方法 final/static** | CGLIB 无法覆盖 |
| 6 | **Bean 未被代理** | 非 Spring 管理、类无接口且未 CGLIB |
| 7 | **错误异常类型** | 如抛 Error 子类特殊处理 |

**数据库层**：MyISAM 不支持事务；多数据源需 `@Transactional` 指定 `transactionManager`。

## 6. 事务与连接

- 一个事务 **一个 Connection**（线程绑定 `TransactionSynchronizationManager`）
- 同一事务内多次 `@Transactional` REQUIRED 共用连接
- **连接池**：事务结束归还连接，勿在事务外持有 Connection

## 7. 编程式事务

```java
@Service
public class OrderService {
    private final TransactionTemplate txTemplate;

    public OrderService(PlatformTransactionManager tm) {
        this.txTemplate = new TransactionTemplate(tm);
    }

    public Order create() {
        return txTemplate.execute(status -> {
            // 业务
            return order;
        });
    }
}
```

适合细粒度控制；多数用声明式。

## 8. 大事务问题

| 问题 | 解决 |
|------|------|
| 事务内 RPC 慢 | RPC 移出事务；本地消息表 |
| 事务内大批量循环 | 分批 + 独立事务 |
| 长事务锁表 | 缩短边界；乐观锁 |
| 只读仍开写事务 | `@Transactional(readOnly = true)` 优化 |

```java
@Transactional(readOnly = true)
public List<Order> list() { ... }
```

## 9. 多数据源

```java
@Configuration
public class DataSourceConfig {
    @Bean @Primary
    public DataSource orderDs() { ... }

    @Bean
    public DataSource reportDs() { ... }

    @Bean
    public PlatformTransactionManager orderTxManager(@Qualifier("orderDs") DataSource ds) {
        return new DataSourceTransactionManager(ds);
    }
}

@Transactional(transactionManager = "orderTxManager")
public void create() { }
```

**注意**：`@Transactional` 不能跨两个不同 TM 的 **同一方法** 原子提交 → 分布式事务（Seata）或最终一致。

## 10. 面试题

| 问 | 答 |
|----|-----|
| REQUIRED 和 REQUIRES_NEW？ | 加入 vs 独立新事务 |
| NESTED 和 REQUIRES_NEW？ | 保存点嵌套 vs 完全独立连接 |
| 事务实现原理？ | AOP + TransactionManager + 线程绑定 Connection |
| 只读事务好处？ |  hint 优化、只读连接（部分驱动） |
| 同类调用如何解决？ | 注入 self、拆分 Service、AopContext |

## 11. 传播行为组合实战

### 场景：下单 + 写审计日志（日志必须落库）

```java
@Service
@RequiredArgsConstructor
public class OrderService {
    private final OrderMapper orderMapper;
    private final AuditService auditService;

    @Transactional(rollbackFor = Exception.class)
    public void placeOrder(OrderCmd cmd) {
        orderMapper.insert(cmd.toOrder());
        auditService.record("ORDER_CREATED", cmd.getOrderId()); // REQUIRES_NEW
        // 若此处抛异常，订单回滚，审计日志已提交
    }
}

@Service
public class AuditService {
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void record(String action, Long bizId) {
        auditMapper.insert(...);
    }
}
```

### 场景：批量导入部分失败

```java
@Transactional
public void importBatch(List<Row> rows) {
    for (Row row : rows) {
        try {
            innerService.importOne(row);  // NESTED
        } catch (Exception e) {
            log.warn("skip row {}", row.getId(), e);
        }
    }
}

@Transactional(propagation = Propagation.NESTED)
public void importOne(Row row) {
    mapper.insert(row);
}
```

## 12. TransactionSynchronization 回调

```java
@Transactional
public void create() {
    orderMapper.insert(order);
    TransactionSynchronizationManager.registerSynchronization(new TransactionSynchronization() {
        @Override
        public void afterCommit() {
            mq.send(orderCreatedEvent);  // 事务提交后再发 MQ，防消息先消费查不到数据
        }
    });
}
```

**Outbox 模式** 更可靠：同事务写 outbox 表 + 定时投递。
