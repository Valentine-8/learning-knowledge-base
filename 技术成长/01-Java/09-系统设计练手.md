## 通用模板（每题都走这 6 步）

```
1. 澄清需求     → 功能、QPS、延迟、一致性、多租户？
2. 容量估算     → 存储、带宽、峰值 QPS（数量级即可）
3. 架构图       → 客户端 → 网关 → 服务 → 缓存/DB/MQ
4. 核心流程     → 1 条主链路 sequence（登录/下单/检索）
5. 数据模型     → 3～5 张核心表 / 索引
6. 风险与演进   → 单点、热点、降级、分库分表时机
```

## 题 1：Experience Site BFF（结合 cc-site-svc）

**题干**：设计公网 Experience Site 网关，多租户按 org 路由到不同 CRM 后端，支持站点 Token 与 OpenCall 代理。

| 步骤 | 要点（参考答案骨架） |
|------|----------------------|
| 需求 | 无状态 BFF；getSiteToken；OpenCall/文件代理；XSS/SQL 过滤 |
| 估算 | 【填】租户数 N；Token QPS；文件上传带宽 |
| 架构 | Nginx → site-svc 集群 → sysconfig 查 org → ServiceUrlManager 缓存 backend → RPC main-svc |
| 核心 API | `POST /api/site/getSiteToken`；`POST /api/site/openCall/common` |
| 数据 | **BFF 无 DB**；配置来自 config center；内存缓存 `{orgId}_mainsvcAddress` + TTL |
| 难点 | 站点参数 AES 解密；org 变更缓存失效；OpenCall 鉴权不能越权 |
| 你的亮点 | 你 **独立实现** 过；可讲 ccsitecc 与 Setup 契约 |

**自测**：☐ 能画架构图 ☐ 能讲 Token 链路 ☐ 能讲为何无 DB

## 题 2：多租户 AI CRM（结合 FollowUpAI）

**题干**：SaaS AI CRM，每租户数据隔离，支持 Web + Widget 嵌入 + 知识库 RAG + WhatsApp Webhook。

| 步骤 | 要点 |
|------|------|
| 需求 | 租户隔离；CRM CRUD；KB 向量检索；Widget 跨域；外部 CRM 同步 |
| 估算 | 【填】租户数；每租户用户数；KB 文档量；日消息量 |
| 架构 | React → API Gateway → FastAPI → Registry DB + **每租户 PG**；Weaviate；Redis 队列 |
| 核心 API | `/api/tenants`；`/api/contacts`；`/api/kb/search`；`/widget/chat` |
| 数据 | registry.tenants；tenant_db 独立 schema/DB；kb_chunks + vector_id |
| 难点 | TenantEngineMiddleware 路由；Widget CORS 白名单；Webhook 验签；LLM 配额 |
| 你的亮点 | Registry + 独立 DB；AI 辅助开发 + 人工 Review 鉴权 |

**自测**：☐ 能讲租户路由 ☐ 能讲 RAG 链路 ☐ 能讲 Widget 安全

## 题 3：轻量 RAG 智能客服（结合 mall）

**题干**：商城客服，上传 PDF/Word 做知识库，AI 回答 + 转人工，不引入独立向量库。

| 步骤 | 要点 |
|------|------|
| 需求 | 文档 <10 万 chunk；MySQL 部署；转人工；防幻觉 |
| 架构 | Vue → Spring Boot → MySQL(业务+向量 JSON) → OpenAI API |
| 流程 | 上传→PDFBox→Chunk→Embedding→存 JSON→查询余弦 TopK→prompt→回复 |
| 数据 | kb_document；kb_chunk(embedding_json)；chat_session(state) |
| 难点 | Chunk overlap；相似度阈值；状态机 AI→waiting→human；异步回复 |
| 演进 | 量大上 Pgvector/Weaviate；加重排；MQ 异步 Embedding |

**自测**：☐ 能讲为何 MySQL ☐ 能讲状态机 ☐ 能讲转人工
