# 01 · 微服务组件全景

> **预计阅读**：50 min · **难度**：★★★★

---

## 1. 为什么 Spring Cloud

单体 → 按 **限界上下文** 拆微服务后需要：

| 问题 | 组件 |
|------|------|
| 服务在哪？ | 注册中心 Nacos |
| 配置怎么改？ | 配置中心 Nacos Config |
| 外部怎么进？ | Gateway |
| 服务间怎么调？ | OpenFeign |
| 实例选哪个？ | LoadBalancer |
| 挂了怎么办？ | Sentinel 熔断 |
| 跨库事务？ | Seata / 最终一致 |

---

## 2. 典型请求链路

```
用户 → Gateway:443/order/1
  → 路由 order-service
  → LoadBalancer 选 10.0.1.5:8080
  → order-service 内 Feign 调 pay-service
  → Sentinel 统计 RT/异常
  → 返回 JSON
```

---

## 3. Spring Cloud 生态图

```
Spring Cloud Commons（抽象）
├── DiscoveryClient      → Nacos/Eureka/Consul
├── LoadBalancerClient   → Spring Cloud LoadBalancer
├── CircuitBreaker       → Sentinel/Resilience4j
└── Config               → Nacos Config

Spring Cloud Gateway（网关）
Spring Cloud OpenFeign（RPC HTTP）
Spring Cloud Alibaba（Nacos/Sentinel/Seata）
```

---

## 4. 注册中心对比

| | Nacos | Eureka | Consul |
|---|-------|--------|--------|
| 配置中心 | ✅ | ❌（需 Config Server） | ✅ |
| 健康检查 | TCP/HTTP/自定义 | 客户端心跳 | TTL/check |
| CAP | 可 AP 可 CP | AP | CP |
| 国内 | 主流 | 维护模式 | 少 |

**7 年面试**：答 **Nacos 注册+配置一体**，Eureka 进入维护。

---

## 5. 网关对比

| | Spring Cloud Gateway | Nginx | Kong/APISIX |
|---|---------------------|-------|-------------|
| 语言 | Java WebFlux | C | Lua/OpenResty |
| 动态路由 | ✅ 与注册中心 | 改 conf reload | ✅ |
| 业务 Filter | Java 代码 | lua/少 | 插件 |
| 性能 | 中 | 极高 | 高 |

**常见**：Nginx/Ingress 做 SSL + 静态，Gateway 做 **鉴权、路由、聚合**。

---

## 6. 服务拆分原则

- 按 **DDD 限界上下文**，非按表拆
- 避免 **分布式单体**（拆完仍紧耦合）
- 数据 **各服务私有库**，通过 API/MQ 协作
- 先 **粗粒度**，再演进

---

## 7. 与 gRPC 分工

| 场景 | 选型 |
|------|------|
| 对外 REST、BFF | Gateway + MVC |
| Java 间 CRUD 调用 | OpenFeign |
| 高性能内部、多语言 | gRPC |

---

## 8. /bootstrap 与 cloud 配置

Spring Boot 2.4+ 默认不加载 bootstrap.yml；Nacos 需：

```yaml
# application.yml
spring:
  config:
    import: optional:nacos:order-service.yaml
```

或引入 `spring-cloud-starter-bootstrap`（旧方式）。
