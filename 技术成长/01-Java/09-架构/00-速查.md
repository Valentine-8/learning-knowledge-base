## 1. 高并发三板斧

```
缓存 → 异步 → 池化
  + 无状态（水平扩展）
  + 限流 · 熔断 · 降级
```

| 手段 | 典型实现 |
|------|----------|
| 缓存 | Caffeine 本地 + Redis 分布式 |
| 异步 | MQ 削峰、CompletableFuture |
| 池化 | 连接池、线程池 |
| 读写分离 | 主写从读，注意复制延迟 |
| CDN | 静态资源边缘加速 |

## 2. 高可用要点

| 概念 | 说明 |
|------|------|
| RPO | 可容忍数据丢失量 |
| RTO | 可容忍恢复时间 |
| 多活 | 同城/异地双活，流量切换 |
| 混沌工程 | 主动注入故障验证韧性 |
| 预案 | 降级开关、熔断阈值、限流规则 |

## 3. DDD 核心（面试版）

| 概念 | 一句话 |
|------|--------|
| 限界上下文 | 业务边界，一套模型 |
| 实体 | 有 ID，可变 |
| 值对象 | 无 ID，不可变 |
| 聚合 | 一致性边界，根实体统一入口 |
| 领域事件 | 上下文内解耦 |
| 防腐层 ACL | 外部模型转换 |

**微服务拆分**：按业务能力/限界上下文，不是按表拆。

## 4. 设计模式场景

| 模式 | 场景 |
|------|------|
| 策略 | 支付渠道、促销规则 |
| 模板方法 | 固定流程可变步骤 |
| 责任链 | Filter、审批流 |
| 观察者 | Spring Event |
| 代理 | AOP、RPC |
| 工厂 | 多实现创建 |

**原则**：能简单就别模式。

## 5. API 设计

- REST：资源名词 + HTTP 动词 + 语义化状态码
- 幂等：PUT/DELETE 天然；POST 用幂等键
- 分页：cursor 优于深 offset
- 错误：业务码 + 可读 message，不泄露堆栈

---

## 6. 系统设计 8 步

```
1. 需求澄清（QPS、数据量、一致性）
2. 估算（存储、带宽、机器）
3. 高层架构图
4. 核心时序
5. 数据模型 / 存储选型
6. 瓶颈扩展（缓存、分片、MQ）
7. 可靠性（冗余、监控）
8. 权衡与演进
```

## 7. 面试速答

| 问 | 答 |
|----|-----|
| 高并发怎么设计？ | 澄清指标→三板斧→无状态→限流熔断→读写分离分片 |
| DDD 和微服务？ | 限界上下文映射服务边界；聚合定事务边界 |
| 缓存一致性？ | 先更 DB 删缓存；延迟双删；Canal 订阅 |
| 如何拆微服务？ | 按业务域；数据归属清晰；避免分布式单体 |

## 8. 易错 checklist

- [ ] 过早微服务，团队维护不起
- [ ] 跨服务分布式事务滥用
- [ ] 设计不考虑运维监控
- [ ] 只谈技术不谈成本排期
