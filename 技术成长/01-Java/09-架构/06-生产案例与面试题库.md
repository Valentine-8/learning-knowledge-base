## 1. 生产故障案例

### 案例 1：缓存与 DB 不一致

| 项 | 内容 |
|----|------|
| 现象 | 用户看到旧库存，超卖 |
| 根因 | 先删缓存后写 DB，并发读回填旧值 |
| 修复 | 先写 DB 再删缓存；关键库存走 DB 乐观锁 |
| 预防 | 缓存策略评审 checklist |

### 案例 2：秒杀打垮数据库

| 项 | 内容 |
|----|------|
| 现象 | 大促 DB CPU 100% |
| 根因 | 无前置限流，请求直达 DB |
| 修复 | Redis 预减 + MQ 异步 + 网关限流 |
| 预防 | 全链路压测 + 降级预案 |

### 案例 3：微服务拆分过细

| 项 | 内容 |
|----|------|
| 现象 | 一次下单 15 次 RPC，P99 飙升 |
| 根因 | 按表拆服务，链路过长 |
| 修复 | 合并订单-订单项上下文；批量接口 |
| 预防 | 按 DDD 限界上下文拆分 |

### 案例 4：分布式事务滥用

| 项 | 内容 |
|----|------|
| 现象 | Seata 超时导致大面积回滚 |
| 根因 | 跨 5 服务强一致 2PC |
| 修复 | 本地消息表 + 最终一致 |
| 预防 | 默认最终一致，强一致需 ADR |

### 案例 5：Feed 热点大 V

| 项 | 内容 |
|----|------|
| 现象 | 发推延迟，粉丝 timeline 更新慢 |
| 根因 | 推模式扇出过大 |
| 修复 | 大 V 改拉；异步 fan-out |
| 预防 | 粉丝数阈值策略 |

### 案例 6：API 无幂等重复下单

| 项 | 内容 |
|----|------|
| 现象 | 用户连点产生 duplicate order |
| 根因 | POST 无幂等键 |
| 修复 | Idempotency-Key + Redis 去重 |
| 预防 | 创建类接口强制幂等 |

## 3. 参考答案速览

| 问 | 核心答法 |
|----|----------|
| 高并发 | 澄清指标→缓存异步池化→无状态→限流熔断→数据层扩展 |
| 缓存一致性 | Cache Aside 先更 DB 删缓存；延迟双删；Canal |
| 拆微服务 | 限界上下文；数据归属；避免链路过长 |
| 秒杀 | 静态化+Redis 预减+MQ+限流；DB 最终一致 |
