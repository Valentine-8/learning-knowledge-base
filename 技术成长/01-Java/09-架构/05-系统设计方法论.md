# 05 · 系统设计方法论

> **预计阅读**：90 min

---

## 1. 面试题本质

45 分钟系统设计题考的是：

```
需求理解 → 架构权衡 → 数量估算 → 瓶颈分析 → 可靠性 → 清晰表达
```

不是背「短链用 Base62」这么简单，要能讲**为什么**、**代价**、**演进路径**。

---

## 2. 标准答题框架（8 步）

```
1. 需求澄清（5 min）
2. 容量估算（5 min）
3. 高层设计（10 min）
4. 核心流程 / 时序（10 min）
5. 数据模型与存储（10 min）
6. 深入瓶颈与扩展（10 min）
7. 可靠性 / 监控（5 min）
8. 总结权衡与 MVP（5 min）
```

**技巧**：边画边讲；主动说 trade-off；留时间给追问。

---

## 3. 需求澄清清单

| 问题 | 影响 |
|------|------|
| 日活 / QPS 峰值 | 架构规模 |
| 读写比 | 缓存、读写分离 |
| 数据量级、增长 | 分片、归档 |
| 延迟要求 | 同步 vs 异步 |
| 一致性要求 | 强一致 / 最终一致 |
| 可用性几个 9 | 冗余、多活 |

**示例**：「设计 Twitter」→ 先问：读多写少？粉丝上限？是否需要 timeline 排序？

---

## 4. 容量估算（Back-of-envelope）

```
QPS = DAU × 人均请求 / 86400 × 峰值系数（2～10）
存储 = 记录数 × 单条大小 × 副本数
带宽 = QPS × 平均响应大小
机器 ≈ QPS / 单核处理能力（粗估）
```

**例**：1 亿 DAU，每人 10 次/天 → 约 1.2 万 QPS 均值，峰值 5 万。

估算不必精确，展示**数量级思维**即可。

---

## 5. 高层架构模板

```
Client → CDN → LB → API Gateway → 微服务集群 → 缓存 / DB / MQ / ES
                                              ↓
                                         对象存储 / 日志 / 监控
```

组件按需裁剪：小系统不需要全上。

---

## 6. 经典题要点

### 6.1 短链服务

| 点 | 方案 |
|----|------|
| 发号 | 哈希（冲突重试）/ 雪花 ID + Base62 |
| 存储 | KV（Redis + MySQL） |
| 跳转 | 301（SEO）/ 302（统计） |
| 扩展 | 分片、缓存热点 |

### 6.2 秒杀

```
静态化页面 → Redis 预减库存 → MQ 异步下单 → DB 最终扣减
+ 限流 + 验证码 + 排队
```

**关键**：避免 DB 成为瓶颈；超卖用 Lua 原子扣减或 DB 乐观锁。

### 6.3 Feed 流

| 模式 | 说明 |
|------|------|
| 推 | 写扩散，适合粉丝少 |
| 拉 | 读扩散，适合大 V |
| 推拉结合 | 普通用户推，大 V 拉 |

热点：多级缓存、扇出异步化。

### 6.4 即时通讯

- 长连接：WebSocket
- 消息序：单聊 seq、群聊分区
- 离线：消息存储 + 拉取同步
- 已读：独立状态表或位图

### 6.5 分布式定时任务

- 时间轮 / 延迟队列
- 选主（ZK / Redis）
- 分片执行 + 幂等

### 6.6 分布式 ID

- 雪花：趋势递增、依赖时钟
- 号段：DB 批量取号
- UUID：无序，索引不友好

---

## 7. 数据建模思路

1. 核心实体与关系
2. 访问模式（点查 / 范围 / 聚合）
3. 索引与分片键
4. 冷热分离、归档

**SQL vs NoSQL**：结构化 + 事务 → MySQL；高吞吐 KV → Redis/Dynamo 思想；搜索 → ES。

---

## 8. 可靠性设计

| 维度 | 措施 |
|------|------|
| 单点 | 多实例、主从 |
| 数据 | 备份、跨区复制 |
| 依赖 | 熔断、超时、降级 |
| 发布 | 灰度、回滚 |
| 观测 | 指标、链路、日志 |

---

## 9. ADR 与技术方案文档

```
背景 → 目标/非目标 → 方案对比 → 选定方案 → 风险与回滚 → 监控指标
```

7 年工程师要能**写方案、评风险、给数据**，不是堆名词。详见 [工程素养/01-CodeReview与技术方案](../../00-通用/工程素养/01-CodeReview与技术方案.md)。

## 10. 常见扣分点

- [ ] 不问需求直接开画
- [ ] 只堆组件不讲数据流
- [ ] 忽略单点与故障场景
- [ ] 无法估算规模
- [ ] 说不出 MVP 与二期演进
