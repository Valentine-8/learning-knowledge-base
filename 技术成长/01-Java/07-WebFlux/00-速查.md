# WebFlux · 速查

> 10 分钟复习。深入见 [01～04 章](./README.md)。

---

## 1. 响应式宣言

```
异步 + 非阻塞 + 背压（Backpressure）
```

适合 **IO 密集、高并发连接**，不是 CPU 密集计算。

---

## 2. Reactor 类型

| 类型 | 元素数 |
|------|--------|
| `Mono<T>` | 0～1 |
| `Flux<T>` | 0～N |

```java
Mono.just("hello")
Flux.range(1, 10)
```

---

## 3. 常用操作

```java
map / flatMap / filter / zip / collectList
subscribe(onNext, onError, onComplete)
block()  // 测试用，生产 Web 线程避免
```

---

## 4. WebFlux 栈

```
Netty（默认）+ WebFlux + Reactor + (可选 R2DBC)
```

对比 MVC：`Tomcat + Servlet + 阻塞 IO`

---

## 5. 核心组件

| 组件 | 作用 |
|------|------|
| `@RestController` | 返回 Mono/Flux |
| `WebClient` | 非阻塞 HTTP 客户端 |
| `RouterFunction` | 函数式路由 |
| Spring Cloud Gateway | 基于 WebFlux 网关 |

---

## 6. 选型速记

| 选 WebFlux | 选 MVC |
|------------|--------|
| 高并发 IO | 团队熟悉阻塞模型 |
| 全链路 reactive | 阻塞 JDBC/MyBatis 为主 |
| Gateway 场景 | 业务 CRUD 为主 |
| | Java 21 虚拟线程后 IO 阻塞成本降低 |

---

## 7. 面试速答

| 问 | 答 |
|----|-----|
| 背压是什么？ | 消费者控制生产者速率 |
| block() 为何慎用？ | 阻塞 event loop 线程 |
| WebFlux 一定更快？ | 不一定；阻塞栈+虚拟线程可能更简单 |
| Gateway 为何用 WebFlux？ | 高并发连接、非阻塞代理 |
