# 11 · 模型微调入门（LoRA / QLoRA）

> **能力层**：L5 建设者　**难度**：★★★★　**预计工时**：16h
> **一句话**：当 prompt 和 RAG 都满足不了需求（要固化特定风格、领域能力、私有格式），才考虑微调。本篇教你**判断该不该微调**，以及用 LoRA/QLoRA 低成本微调一个开源模型。
> **前置**：[05-RAG](./05-RAG系统工程化实战.md)、[10-本地部署](./10-本地模型部署与推理优化.md)、[08-评测](./08-AI可观测与评测.md)。Python 基础（微调生态在 Python）。

## 一、先泼冷水：90% 的需求不该微调

**Java 工程师最容易犯的错**：一有 AI 需求就想微调。实际上微调是"最后手段"。

### 决策优先级（务必背下来，面试必问）
```
1. Prompt 工程    ← 先试，最快最便宜（改行为/格式）
2. RAG            ← 需要外部/私有/实时知识（[05]）
3. 微调(Fine-tune)← 前两者都不够：要固化风格/领域语气/私有输出格式，且有足够高质量数据
4. 预训练         ← 几乎不用，成本极高
```

| 需求 | 用什么 | 为什么 |
|------|--------|--------|
| "回答基于我们公司文档" | **RAG** | 知识型、要实时更新，微调解决不了 |
| "输出更简洁专业" | **Prompt** | 改指令即可 |
| "总用固定的病历/工单格式，且样本很多" | **微调** | 格式/风格固化，prompt 太长 |
| "掌握某垂直领域黑话/语气" | **微调** | 领域能力内化 |
| "知识实时变" | **RAG，不是微调** | 微调是静态快照，改知识要重训 |

> **微调改的是模型的"能力和风格"，不是"知识库"。要新知识用 RAG。** 这句话面试能加分。

## 二、微调类型

| 类型 | 说明 | 成本 |
|------|------|------|
| 全参数微调(Full FT) | 更新所有参数 | 极高，要大量 GPU |
| **LoRA** | 冻结原模型，只训练注入的低秩小矩阵 | 低，单卡可做 |
| **QLoRA** | LoRA + 4bit 量化基座 | 更低，消费级 GPU 可做 |
| Prefix/P-Tuning | 只训练少量前缀参数 | 低 |

**PEFT（Parameter-Efficient Fine-Tuning）** = 参数高效微调统称，LoRA 是其代表。

### LoRA 原理（面试点，讲清即可）
大模型权重矩阵 W 很大。LoRA 不动 W，而是训练两个小矩阵 A、B（低秩），用 `W + B·A` 近似微调后的权重。因为 A、B 参数量极小（可能只有原模型的 0.1%~1%），所以：
- 训练快、省显存
- 产出一个小小的 **LoRA 适配器（adapter）**，几十 MB，可插拔
- 一个基座模型 + 多个 LoRA adapter = 多个"专家"，按需切换

**QLoRA** = 把基座模型 4bit 量化加载（省显存，见 [10-量化](./10-本地模型部署与推理优化.md)）再上 LoRA，让 7B/13B 模型能在单张消费级显卡微调。

## 三、微调全流程

```
1. 明确目标 + 定评估集（先有评估，才知道微调有没有用）
2. 构建训练数据集（最难、最重要，决定成败）
3. 选基座模型（[10] 选型，通常选 Instruct 版）
4. 训练（LoRA/QLoRA，调超参）
5. 评估（对比微调前后，[08] 评估集）
6. 合并/部署 adapter（[10] Ollama/vLLM 加载）
7. 持续监控（[08] 防漂移）
```

### 3.1 数据集构建（成败关键，80% 精力在这）
质量 >> 数量。指令微调常用格式：
```json
{"instruction": "把下面客诉转成标准工单", "input": "你们的东西太烂了...", "output": "{\"type\":\"质量投诉\",\"priority\":\"HIGH\",...}"}
```
要点：
- **高质量 + 多样性 + 覆盖边界**，几百~几千条精标常胜过几万条脏数据
- 输出格式统一（尤其结构化输出场景）
- 划分 train/eval，别用训练数据评估
- 数据脱敏（[09-安全](./09-LLM安全与合规.md)）

### 3.2 训练（LLaMA-Factory，最省心）
不用手写训练代码，用成熟框架：
```bash
# LLaMA-Factory：图形界面/命令行，支持 Qwen/Llama 等 + LoRA/QLoRA
llamafactory-cli train \
  --model_name_or_path Qwen/Qwen2.5-7B-Instruct \
  --dataset my_ticket_data \
  --finetuning_type lora \
  --lora_rank 8 \
  --quantization_bit 4 \        # QLoRA
  --learning_rate 1e-4 \
  --num_train_epochs 3 \
  --output_dir ./lora-ticket
```

关键超参：
- `lora_rank`（r）：秩，8/16 常用，越大容量越大越易过拟合
- `learning_rate`：1e-4 量级
- `epochs`：2~3 常见，太多会过拟合
- 关注 loss 曲线：train loss 降但 eval loss 升 = 过拟合

### 3.3 部署
```bash
# 合并 adapter 到基座，导出 GGUF 给 Ollama（见 10）
# 或 vLLM 直接加载 LoRA adapter（支持多 adapter 热切换）
```

## 五、常见坑

| 坑 | 现象 | 解法 |
|----|------|------|
| 该用 RAG 却微调 | 花大钱知识还是旧 | 知识型需求用 RAG |
| 数据质量差 | 微调后更糟 | 精标少量 > 海量脏数据 |
| 没评估集 | 不知道有没有变好 | 先建评估集再微调 |
| 过拟合 | 训练集好、新样本崩 | 减 epoch/rank、加数据多样性、看 eval loss |
| 灾难性遗忘 | 学了新的忘了通用能力 | 混入通用数据、控制训练强度 |
| 全参微调爆显存 | OOM | 用 QLoRA |
| 微调当银弹 | 期望过高 | 认清微调改风格/能力，不改知识 |

## 六、面试考点

- **Q：Prompt / RAG / 微调怎么选？**
  A：优先级 Prompt→RAG→微调。改行为用 prompt；补知识（尤其实时/私有）用 RAG；固化风格/领域能力且有高质量数据用微调；微调不解决知识实时更新。
- **Q：LoRA 原理？为什么省资源？**
  A：冻结原权重，只训练注入的低秩小矩阵 A/B，用 W+BA 近似微调。参数量极小，训练快省显存，产出可插拔的小 adapter。
- **Q：QLoRA 是什么？**
  A：LoRA + 4bit 量化加载基座，进一步降显存，让大模型在消费级 GPU 上可微调。
- **Q：微调最难的是什么？**
  A：数据集。高质量、多样、覆盖边界、格式统一的数据决定成败，质量远比数量重要。
- **Q：什么是灾难性遗忘？**
  A：微调新任务导致模型丢失原有通用能力；对策是混入通用数据、控制训练强度。
