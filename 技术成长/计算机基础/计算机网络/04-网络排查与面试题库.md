> **建议用时**：通读 60 min + 实操 curl -v 一次 HTTPS 请求。

## 一、排查工具箱

### 1.1 curl

```bash
#  verbose：看 DNS、TCP、TLS、HTTP
curl -v https://api.example.com/health

# 只测 TTFB
curl -o /dev/null -s -w "dns:%{time_namelookup} connect:%{time_connect} tls:%{time_appconnect} ttfb:%{time_starttransfer}\n" https://example.com

# 指定方法、Header、body
curl -X POST -H "Content-Type: application/json" -d '{"id":1}' https://api.example.com/users

# 跟随重定向
curl -L -I https://example.com
```

### 1.2 dig / nslookup

```bash
dig www.example.com A
dig @8.8.8.8 api.example.com
```

### 1.3 ping / traceroute

```bash
ping -c 4 8.8.8.8
tracert www.example.com   # Windows
traceroute www.example.com # Linux
```

**注意**：ping ICMP 可能被防火墙禁；HTTP 问题仍需 curl。

### 1.4 telnet / nc

```bash
# 测端口通否
telnet host 443
nc -zv host 443
```

### 1.5 tcpdump / Wireshark

```bash
tcpdump -i any port 443 -w capture.pcap
```

分析三次握手、TLS ClientHello、HTTP 明文（HTTPS 需解密 key log）。

### 1.6 浏览器 DevTools

Network：瀑布图、Timing（Queueing、Stalled、DNS、SSL、TTFB）、Disable cache。

## 二、分层排查法

```
1. 应用层：HTTP 状态码、业务错误码、日志
2. 传输层：连接 reset、timeout、TIME_WAIT
3. 网络层：路由、防火墙、安全组
4. DNS：解析是否正确、是否劫持
5. 客户端：代理、VPN、Hosts
```

**示例：502 Bad Gateway**

- Nginx 日志：`upstream timed out` → 后端慢或挂
- 直连后端 bypass 网关 → 定位网关还是应用

---

## 三、常见问题与原因

| 现象 | 可能原因 | 排查 |
|------|----------|------|
| Connection refused | 端口未监听、防火墙 | nc、telnet |
| Connection timed out | 路由/安全组/服务挂 | traceroute、日志 |
| Connection reset | 对端 RST、负载满 | tcpdump |
| SSL handshake failed | 证书、TLS 版本、SNI | curl -v、openssl s_client |
| 413 | body 超限 | 调整 server/tomcat max-http-post-size |
| 504 | 网关 read timeout | 调大 timeout 或优化后端 |

### 3.1 openssl 测 TLS

```bash
openssl s_client -connect www.example.com:443 -servername www.example.com
```

查看证书链、协议版本、cipher。

## 四、Linux 网络状态

```bash
# 连接统计
ss -s
ss -tan | head

# TIME_WAIT 计数
ss -tan state time-wait | wc -l

# 监听端口
ss -tlnp
```

| 状态 | 含义 |
|------|------|
| ESTABLISHED | 正常通信 |
| TIME_WAIT | 主动关闭等待 |
| CLOSE_WAIT | 等应用 close |
| SYN_SENT | 连接中 |

## 五、Java 网络配置

### 5.1 连接池（OkHttp 示例）

```java
OkHttpClient client = new OkHttpClient.Builder()
    .connectTimeout(3, TimeUnit.SECONDS)
    .readTimeout(10, TimeUnit.SECONDS)
    .writeTimeout(10, TimeUnit.SECONDS)
    .connectionPool(new ConnectionPool(50, 5, TimeUnit.MINUTES))
    .build();
```

**Keep-Alive**：复用 TCP，减少握手；注意 **每主机连接数** 限制。

### 5.2 Feign / RestTemplate

分层超时：**connect**（TCP）≠ **read**（等响应 body）。

```yaml
feign:
  client:
    config:
      default:
        connectTimeout: 3000
        readTimeout: 10000
```

### 5.3 Tomcat

```yaml
server:
  tomcat:
    max-connections: 8192
    accept-count: 100
    threads:
      max: 200
```

**线程打满** → 新连接排队或拒绝。

### 5.4 Dubbo / gRPC

- 超时、重试（**非幂等禁重试**）
- 连接数、序列化大小
- 链路追踪 traceId 传递

## 九、综合面试题库

### 9.1 TCP/IP

**Q1：三次握手能否两次？**  
不能可靠同步 seq 并确认双方能力；历史 SYN 需 ISN 机制配合。

**Q2：已经建立了连接，客户端突然故障？**  
TCP **保活 Keepalive** 探测；应用层心跳更常见。

**Q3：滑动窗口为 0 怎么办？**  
发送方暂停，定时 **窗口探测** 报文。

**Q4：拥塞窗口和接收窗口共同约束发送？**  
有效窗口 = min(cwnd, rwnd)。

### 9.2 HTTP/HTTPS

**Q5：POST 比 GET 安全吗？**  
都不加密则都不安全；HTTPS 下都加密；POST 不在 URL 里暴露参数但日志仍可能记 body。

**Q6：Cookie 存在哪？**  
浏览器管理；可 HttpOnly 禁 JS 读。

**Q7：Token 放 Header 还是 Cookie？**  
Header Authorization：防 CSRF 简单但 XSS 偷 token；Cookie HttpOnly 防 XSS 读但需 CSRF 防护。

### 9.3 综合

**Q8：短连接 vs 长连接？**  
短：简单，握手多；长：高 QPS 必池化。

**Q9：如何设计一个短 URL 服务？**  
哈希/发号、301/302、缓存、读多写少、库分片（系统设计延伸）。

**Q10：两个服务器时间差导致 HTTPS 失败？**  
证书 not yet valid / expired，NTP 同步。

## 十五、连接池参数调优

**OkHttp**：

- `maxIdleConnections`：空闲连接数
- `keepAliveDuration`：保活时间

**HikariCP**（数据库）：

- `maximumPoolSize` ≈ CPU×2 + disk（IO 型更大）
- `connectionTimeout` 获取连接等待

**现象**：线程 BLOCKED 在 getConnection → 池太小或慢 SQL。

## 十八、Mock 面试扩展

**Q11：SYN flood 原理与防御？**  
伪造源 IP 发 SYN 占半连接队列；SYN Cookie、限速、防火墙。

**Q12：为什么需要 TIME_WAIT 不能改成 0？**  
丢最后 ACK 时对端重 FIN 需响应；旧包干扰新连接。

**Q13：HTTP 长连接谁决定关闭？**  
任一方 Connection: close 或超时；Keep-Alive timeout 默认较短需调。

## 二十一、MTU 与 MSS 路径问题

**PMTU 黑洞**：ICMP 禁止 → TCP 永远不达有效 MSS → 挂起。解法：TCP MSS clamp、降低接口 MTU。

**Docker**：overlay 网络 MTU 1450，低于以太网 1500，跨网段需注意。
