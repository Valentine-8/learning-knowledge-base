## 二、TCP（面试重中之重）

### 三次握手

```
C → SYN → S
C ← SYN+ACK ← S
C → ACK → S
```

**为什么三次**：双方确认各自收发能力；防历史重复 SYN。

### 四次挥手

```
C → FIN → S
C ← ACK ← S
C ← FIN ← S
C → ACK → S（TIME_WAIT 2MSL）
```

**TIME_WAIT**：保证最后 ACK 可达、旧连接包消散。

### 可靠传输

- 序号、确认、重传
- 滑动窗口、流量控制
- **拥塞控制**：慢开始、拥塞避免、快重传、快恢复

### TCP vs UDP

| | TCP | UDP |
|--|-----|-----|
| 连接 | 面向连接 | 无连接 |
| 可靠 | 是 | 否 |
| 场景 | HTTP、RPC、DB | DNS、视频、游戏状态 |

## 三、HTTP

| 版本 | 特点 |
|------|------|
| HTTP/1.1 | 持久连接、管道化；队头阻塞 |
| HTTP/2 | 多路复用、头部压缩、服务端推送 |
| HTTP/3 | 基于 **QUIC(UDP)**，解决传输层阻塞 |

**常用方法**：GET（幂等）、POST、PUT、DELETE、PATCH。

**状态码**：200、301/302、400、401、403、404、500、502、503。

**Header**：Cache-Control、ETag、Cookie、Authorization、Content-Type。

---

## 四、HTTPS 与 TLS

```
HTTP over TLS
握手：协商算法 → 证书验证 → 密钥交换 → 对称加密传数据
```

| 概念 | 说明 |
|------|------|
| 对称加密 | AES，快，传数据 |
| 非对称加密 | RSA/ECDHE，握手 |
| 证书 | CA 签发，防中间人 |
| HSTS | 强制 HTTPS |

**TLS 1.2 vs 1.3**：1.3 握手更快、套件更安全。

---

## 五、从 URL 到页面（经典题）

```
DNS 解析 → TCP 连接 → TLS 握手 → HTTP 请求
→ 服务器处理 → 响应 → 浏览器渲染
```

## 六、实战相关

- **连接池**：HTTP Keep-Alive、数据库连接池
- **超时**：connect / read / write 分层设置
- **RPC**：常基于 TCP + 自定义协议或 HTTP/2

## 七、面试速答

| 问 | 答 |
|----|-----|
| 三次握手四次挥手？ | 建立双向确认；关闭需双方分别关闭写 |
| GET 和 POST？ | 语义：GET 幂等取资源；POST 提交；实际差别在用法和规范 |
| HTTPS 原理？ | TLS 证书验证 + 握手协商密钥 + 对称加密传输 |
| HTTP/2 改进？ | 多路复用、HPACK 压缩、二进制分帧 |
