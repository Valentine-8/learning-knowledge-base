# 第二章：内存管理

> **阅读目标**：掌握虚拟内存、分页分段、置换算法，对照 JVM 堆、Metaspace、Direct Memory 与 GC。
>
> **建议用时**：通读 85 min。

---

## 一、地址空间

### 1.1 逻辑 vs 物理

| 地址 | 说明 |
|------|------|
| 逻辑/虚拟 | 程序看到的地址 |
| 物理 | 实际 RAM 地址 |

**重定位**：编译时、加载时、**运行时**（现代 OS 用运行时 + MMU）。

### 1.2 虚拟内存目的

1. **隔离**：进程互不干扰
2. **比物理内存大**：按需换页
3. **简化链接**：每个进程从 0 或固定布局开始
4. **共享**：共享库、共享内存

---

## 二、分页（Paging）

### 2.1 机制

- 虚拟空间划 **页**（通常 4KB）
- 物理划 **页框**
- **页表**：虚拟页号 → 页框号 + 权限位

**多级页表**：节省页表内存（64 位必多级）。

### 2.2 页表项

| 位 | 含义 |
|----|------|
| Present | 是否在内存 |
| R/W | 读写 |
| U/S | 用户/内核 |
| Accessed | 访问过 |
| Dirty | 写过 |

**缺页中断**：访问不在内存的页 → OS 从磁盘调入或分配。

### 2.3 TLB

**Translation Lookaside Buffer**：页表缓存，命中则免查页表。

**切换进程**：TLB flush 或 ASID 标签。

---

## 三、分段（Segmentation）

按逻辑段：代码、数据、栈、堆；变长 → **外部碎片**。

**Intel x86**：分段 + 分页结合；现代 OS 主要用分页，段平坦模式。

---

## 四、页面置换

### 4.1 何时置换

物理页框满 + 缺页 → 踢出一页。

### 4.2 算法

| 算法 | 思想 | 特点 |
|------|------|------|
| OPT | 最远将来不用 | 理论最优，不可实现 |
| FIFO | 最先进入 | 简单，Belady 异常 |
| LRU | 最久未用 | 接近 OPT，实现贵 |
| Clock | LRU 近似 | 环形 + 访问位 |
| LFU | 最少频次 | 缓存常用 |

**Linux**：近似 LRU（active/inactive 链表）+ 工作集。

### 4.3 抖动 Thrashing

进程工作集 > 物理内存 → 频繁缺页 → CPU 空转换页。

**解决**：减并发进程、加内存、局部性优化。

---

## 五、局部性原理

- **时间局部性**：刚访问的 likely 再访问
- **空间局部性**：相邻地址 likely 访问

**编程**：顺序访问数组快于随机；链表 cache 不友好。

---

## 六、内存分配（堆管理）

### 6.1 用户堆

`malloc/new` →  brk/sbrk 或 mmap；glibc **ptmalloc**、**jemalloc**（Redis）。

**碎片**：内部（分配粒度）、外部（空闲块不连续）。

### 6.2 Java 堆

```
JVM 进程地址空间
├── 栈（每线程）
├── 堆 Heap（对象，GC 管理）
├── Metaspace（类元数据，JDK8+ 替代 PermGen）
├── 代码缓存（JIT）
├── 线程栈
└── Direct Memory（NIO DirectByteBuffer，堆外）
```

---

## 七、JVM 内存与 GC（关联）

### 7.1 分代假设

大多数对象 **朝生夕死** → 新生代 Eden + Survivor；长期存活 → 老年代。

### 7.2 常见 GC

| 收集器 | 场景 |
|--------|------|
| G1 | 默认，Region，可预测停顿 |
| ZGC/Shenandoah | 超低延迟，大堆 |

**OOM 类型**：

- `Java heap space`
- `Metaspace`
- `Direct buffer memory`
- `unable to create new native thread`

### 7.3 堆外内存

DirectByteBuffer 减少拷贝（零拷贝路径）；需限制 `-XX:MaxDirectMemorySize`。

**排查**：NMT `-XX:NativeMemoryTracking=summary`。

---

## 八、Copy-on-Write

**fork** 后子进程共享父页，写时复制 → Redis RDB、Java `Process`  spawn 优化。

---

## 九、大页 Huge Pages

2MB/1GB 大页减少 TLB miss → 数据库、大堆 JVM `-XX:+UseLargePages`。

---

## 十、内存映射 mmap

文件映射到虚拟地址，按需缺页加载 → **MMap 读大文件**、Lucene。

```java
FileChannel channel = FileChannel.open(path, StandardOpenOption.READ);
MappedByteBuffer buf = channel.map(FileChannel.MapMode.READ_ONLY, 0, channel.size());
```

---

## 十一、Swap

内存不足 → 页换出到磁盘 swap；**性能骤降**。

**容器**：K8s limit 超 memory → OOMKill，非 swap。

---

## 十二、面试高频问答

| 问 | 答 |
|----|-----|
| 虚拟内存作用？ | 隔离、扩容、共享、简化链接 |
| 分页和分段？ | 固定页无外部碎片；分段逻辑清晰有外部碎片 |
| LRU 如何实现？ | 硬件难精确；Clock、双向链表+Hash（LRU Cache） |
| TLB 作用？ | 加速虚拟→物理 |
| JVM 内存结构？ | 堆、栈、Metaspace、Direct、PC |
| 堆和栈区别？ | 栈帧局部自动；堆对象 GC；线程各有一份栈 |

---

## 十三、排查命令

```bash
# 进程内存
pmap -x <pid>
cat /proc/<pid>/status | grep -i vm

# Java
jmap -heap <pid>
jcmd <pid> VM.native_memory summary
```

---

## 十四、Inverted Page Table（了解）

某些架构用 **反向页表** 物理页 → 虚拟页，节省大地址空间页表内存。x86 常用多级页表。

---

## 十五、Copy-on-Write 与 fork 深入

父 fork 后父子共享只读页；任一方写 → 缺页 → 复制页框。`String.intern` 等与内存无关但 fork 在 Redis 持久化重要。

---

## 十六、JVM GC 与 OS 交互

- **GC 触发 STW**：所有用户线程停，像调度暂停
- **大页**：减少 TLB miss，`-XX:+UseLargePages`
- **堆外 Direct**：不计堆但计 **进程 RSS**，OOM kill 整个容器

```bash
# 容器 OOMKilled
kubectl describe pod | grep -i oom
```

---

## 十七、内存屏障与 Java（衔接并发）

CPU/编译器重排序 → JMM happens-before → `volatile`、`synchronized` 插入屏障。

OS 无关但面试常连问 **可见性** 与 **缓存一致性 MESI**。

---

## 十八、磁盘与页缓存

读文件先 **page cache**（内核缓存页），再拷贝到用户空间 → **mmap** 可少一次拷贝。

**Write-back**：脏页延迟刷盘，掉电可能丢；数据库 fsync 保证持久。

---

## 十九、容器内存 limit

K8s `resources.limits.memory` 超 **cgroup** 限制 → OOMKill 进程（常 kill Java 容器内 PID 1）。

**调优**：堆 `-Xmx` 留空间给 Metaspace、Direct、线程栈、Native。

经验：**Xmx ≤ limit 的 70~75%**。

---

## 二十、面试扩展

**Q7：分页和分段优缺点？**  
分页：无外部碎片，细粒度；分段：逻辑清晰有外部碎片。x86 段页式结合。

**Q8：Belady 异常？**  
FIFO 增加页框有时缺页更多；LRU 无此问题。

**Q9：Java 对象一定在堆上？**  
逃逸分析后 scalar replacement、栈上分配（JIT 优化，非规范保证）。

---

## 二十二、G1 与 Region（JVM 深入）

G1 把堆划 **Region**（1–32MB），优先回收垃圾最多 Region（Garbage First）。

| 参数 | 含义 |
|------|------|
| -Xms/-Xmx | 堆初/最大值 |
| -XX:MaxMetaspaceSize | 类元数据上限 |
| -XX:MaxDirectMemorySize | DirectBuffer 上限 |
| -XX:+HeapDumpOnOutOfMemoryError | OOM 自动 dump |

**Metaspace OOM**：动态类加载（CGLIB、Groovy、大量反射）→ 查 classloader 泄漏。

---

## 二十三、堆外内存排查步骤

1. `jcmd <pid> VM.native_memory summary`
2. 看 Internal、Thread、Code、GC、Other
3. DirectBuffer：`BufferPoolMXBean`
4. Netty：`PlatformDependent.usedDirectMemory()`

---

## 二十四、页面置换模拟题

**题目**：3 个页框，访问序列 1,2,3,4,1,2,5,1,2,3,4,5，比较 FIFO 与 LRU 缺页次数。

**练手**：手算加深 LRU 直觉；工程里 Redis 近似 LRU 随机采样 5 keys。

---

## 二十五、内存对齐与伪共享

对象头 12/16 字节对齐；`@Contended`（JDK 8）避免缓存行 **false sharing** 多线程写相邻字段。

```java
@Contended
static class Counter { volatile long c; }
```

---

## 二十六、32 位 vs 64 位地址空间

32 位用户态约 2–3GB 可用堆（Windows/Linux 不同）；64 位理论极大，实际 **压缩指针** `-XX:+UseCompressedOops` 堆 < 32GB 时对象引用 32 位。

---

## 二十七、小结

```
虚拟内存 + 页表 + TLB + 缺页中断
置换：LRU/Clock；抖动要加内存或减负载
Java：堆分代 GC、Metaspace、Direct、OOM 分类
局部性：顺序访问、减少大对象
```
