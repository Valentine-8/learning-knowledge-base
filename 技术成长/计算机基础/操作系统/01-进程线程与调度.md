# 第一章：进程线程与调度

> **阅读目标**：理解进程/线程模型、调度算法、IPC，对照 Java Thread、线程池与虚拟线程。
>
> **建议用时**：通读 85 min。

---

## 一、进程与线程

### 1.1 进程（Process）

**定义**：操作系统 **资源分配** 的基本单位，拥有独立虚拟地址空间。

| 组成 | 说明 |
|------|------|
| PCB | 进程控制块：PID、状态、寄存器、内存指针 |
| 代码段 | 程序指令 |
| 数据段 | 全局、静态 |
| 堆 | 动态分配 |
| 栈 | 函数调用、局部变量 |

**Java**：一个 JVM 实例通常是一个 OS 进程；`main` 启动后多线程共享 JVM 堆。

### 1.2 线程（Thread）

**定义**：**CPU 调度** 的基本单位，共享进程地址空间，独有栈、寄存器、PC。

| 对比 | 进程 | 线程 |
|------|------|------|
| 地址空间 | 独立 | 共享 |
| 切换开销 | 大（页表、TLB） | 较小 |
| 通信 | IPC 复杂 | 共享内存+同步 |
| 崩溃 | 隔离 | 一线程错可能拖垮进程 |

### 1.3 协程 / 虚拟线程

| | 内核线程 | 协程/虚拟线程 |
|--|----------|---------------|
| 调度 | OS 内核 | 用户态运行时 |
| 切换 | 内核态 | 用户态，轻量 |
| 阻塞 IO | 占内核线程 | 可 mount 到少量载体线程 |

**Java 21 虚拟线程**：`Executors.newVirtualThreadPerTaskExecutor()`；阻塞 IO 时自动 unmount，高并发 HTTP 友好。

## 二、进程状态与转换

```
        创建
         ↓
      [新建]
         ↓  admit
      [就绪] ←────────── 时间片到/抢占
         ↓ dispatch
      [运行]
         ↓ I/O 请求
      [阻塞] ──I/O 完成──→ 就绪
         ↓
      [终止]
```

**七状态模型**（含挂起）：就绪挂起、阻塞挂起（换出到磁盘）。

---

## 三、上下文切换

**内容**：保存 CPU 寄存器、程序计数器、栈指针 → 加载另一任务。

**代价**：

- 直接：寄存器、内核数据结构
- 间接：Cache/TLB 失效

**优化**：减少切换（协程、批量处理）、绑核（affinity）。

**Java**：线程过多 → 频繁切换 → CPU 飙高但吞吐低；合理 **线程池大小**。

---

## 四、CPU 调度

### 4.1 目标

- 公平性
- CPU 利用率
- 周转时间 / 响应时间 / 等待时间
- 吞吐量

### 4.2 算法

| 算法 | 思想 | 缺点 |
|------|------|------|
| FCFS | 先来先服务 |  convoy 效应 |
| SJF | 短作业优先 | 饥饿 |
| 优先级 | 高优先级先 | 低优先级饥饿 |
| 时间片 RR | 轮转，公平 | 片长选择 |
| 多级反馈队列 | 综合 | 复杂，Linux CFS 类似思想 |

**Linux CFS**：完全公平调度，红黑树按 vruntime 选下一个任务。

### 4.3 抢占

- 时间片用完
- 更高优先级就绪
- 阻塞/唤醒

## 五、进程间通信 IPC

| 方式 | 特点 | 场景 |
|------|------|------|
| 管道 pipe | 半双工，亲缘进程 | shell 管道 |
| 命名管道 FIFO | 无亲缘 | 简单数据流 |
| 消息队列 | 内核缓冲，结构化消息 | 异步通知 |
| 共享内存 | **最快**，需信号量同步 | 大数据 |
| 信号量 | P/V 同步互斥 | 临界区 |
| 信号 signal | 异步事件 | kill -9 |
| Socket | 跨网络 | 微服务、RPC |

**Java 映射**：

- 管道：ProcessBuilder 重定向
- 共享内存：MappedByteBuffer（堆外）
- Socket：RMI、HTTP、MQ
- 信号量：`java.util.concurrent.Semaphore`

## 六、线程同步

### 6.1 临界区问题

互斥访问共享资源 → **互斥锁、读写锁、条件变量**。

### 6.2 用户态 vs 内核态锁

| | 用户态 | 内核态 |
|--|--------|--------|
| 例子 | CAS、自旋短等 | mutex 阻塞 |
| Java | synchronized 偏锁/轻量 | 膨胀后 park |

**synchronized 升级**：无锁 → 偏向 → 轻量 CAS → 重量 monitor。

---

## 七、Java 线程模型

### 7.1 创建与生命周期

```java
Thread t = Thread.ofVirtual().start(() -> { /* task */ });

ExecutorService pool = Executors.newFixedThreadPool(
    Runtime.getRuntime().availableProcessors());
```

**状态**：NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED。

### 7.2 线程池参数

```java
new ThreadPoolExecutor(
    corePoolSize, maximumPoolSize,
    keepAliveTime, unit,
    workQueue,
    threadFactory,
    rejectedExecutionHandler
);
```

**大小经验**：

- CPU 密集 ≈ N+1 核
- IO 密集 ≈ 2N 或按 RT 公式 `N * (1 + W/C)`

### 7.3 ForkJoinPool

分治任务窃取（work-stealing），`parallelStream` 默认共用 common pool。

---

## 八、用户态与内核态

**trap**：系统调用、中断、异常 → 切换内核态。

**为什么分**：保护硬件与内核；用户程序不能直接访问物理内存/设备。

**Java**：文件 IO、网络 read 最终 syscall；NIO 非阻塞减少 **阻塞在内核的线程数**。

---

## 九、多核与 NUMA

- **多核**：真并行；注意 **false sharing**（缓存行）
- **NUMA**：非统一内存访问，本地内存快；大内存服务器绑 NUMA 节点

**Java**：`-XX:+UseNUMA`（G1 可选优化）。

## 十一、实践排查

```bash
# Linux 线程/进程
top -H -p <pid>
jstack <pid>   # Java 线程栈

# Windows
tasklist / taskmgr
```

**CPU 高**：死循环、频繁 GC、锁竞争、线程过多。

## 十二、Linux 线程实现

**NPTL**：Native POSIX Thread Library，1:1 映射内核线程 `clone()`。

```bash
ps -eLf | grep java   # 看线程
top -H -p <pid>
```

**Java 线程名**：`Thread.setName` 便于 jstack 定位。

## 十三、写时复制 fork

```c
pid_t pid = fork();
if (pid == 0) { /* child */ }
```

子进程复制父 PCB，**页表共享物理页**，写时复制。Redis `BGSAVE`、Java `ProcessBuilder` 利用此特性。

## 十四、Real-Time 与 CFS 权重

**nice 值** -20~19：CFS `vruntime` 权重，nice 低者优先。

**Java**：无法直接设 nice，容器 CPU limit 影响 **CFS quota**（cfs_period_us）。

---

## 十五、虚拟线程深入（JDK 21+）

```java
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    IntStream.range(0, 100_000).forEach(i ->
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1));
            return i;
        }));
}
```

**载体线程**（Platform Thread）有限；虚拟线程阻塞 IO 时 **unmount**，不占用载体。

**勿 pin 载体**：synchronized 块内阻塞 IO 可能 pin，改用 ReentrantLock。

---

## 十六、ThreadLocal 与内存泄漏

```java
private static final ThreadLocal<UserContext> CTX = new ThreadLocal<>();
```

线程池 **复用线程** → ThreadLocal 未 `remove()` → 对象泄漏（尤其 Tomcat 线程池）。

**解决**：`finally { CTX.remove(); }`；或 Request 作用域对象。

## 十八、面试扩展

**Q7：守护进程？**  
daemon 线程不阻止 JVM 退出；`setDaemon(true)` 用于后台辅助。

**Q8：线程中断机制？**  
`interrupt()` 设标志；阻塞方法抛 InterruptedException；应恢复中断状态 `Thread.currentThread().interrupt()`。

**Q9：happens-before 与 OS？**  
JMM 是语言层；底层靠内存屏障、锁。不必混为一谈但可提「synchronized 进入退出有 hb」。

## 二十、CFS 与 Java 线程优先级

Java `Thread.setPriority(1-10)` 映射 OS nice，**效果有限**；勿依赖优先级做正确性。

**虚拟线程**：载体线程由 FJP 调度，mount/unmount 对用户透明。

## 二十一、Process vs Thread 资源清单

| 资源 | 进程独有 | 线程共享 |
|------|----------|----------|
| 地址空间 | ✓ | 共享 |
| 文件描述符 | 继承/独立 | 共享 |
| 信号处理 | 独立 | 共享 |
| 堆 | 独立 | 共享 JVM 堆 |
| 栈 | 独立 | 每线程独立栈 |

## 二十二、信号（Linux）与 Java

| 信号 | 作用 |
|------|------|
| SIGKILL 9 | 强杀，不可捕 |
| SIGTERM 15 | 优雅停，Spring 监听 shutdown |
| SIGSTOP | 暂停 |

```java
Runtime.getRuntime().addShutdownHook(new Thread(() -> {
    // 优雅关闭线程池
}));
```

K8s `preStop` + `SIGTERM` →  drain 连接再退出。

---

## 二十三、容器 CPU throttling

cgroup CPU quota 用尽 → **CFS throttling**，线程 Runnable 但无 CPU → 延迟飙。

**现象**：load 不高但 RT 高；`cat /sys/fs/cgroup/.../cpu.stat` 看 throttled_usec。

---

## 二十四、并行度与 Amdahl 定律

加速比受 **串行部分** 限制。8 核满用需任务可并行；锁竞争使扩展性变差。

---

## 二十五、面试手写：生产者消费者

```java
BlockingQueue<Task> q = new ArrayBlockingQueue<>(100);

// producer
q.put(task);

// consumer
Task t = q.take();
```

`put/take` 阻塞，比 wait/notify 简洁。

```
进程：资源容器；线程：执行单元
调度：RR、优先级、Linux CFS
IPC：管道、共享内存、Socket
Java：线程池、虚拟线程、synchronized 升级
```
