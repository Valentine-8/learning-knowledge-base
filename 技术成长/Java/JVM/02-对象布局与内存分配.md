# 02 · 对象布局与内存分配

> **目标读者**：7 年 Java 后端，需能说明对象头、指针压缩、TLAB 与逃逸分析，并在面试中估算对象大小与分配路径。
> **预计阅读**：50 min · **难度**：★★★★

---

## 1. 对象在内存中的布局

```
┌─────────────────────────────────────────┐
│ 对象头 Object Header                     │
│   ├─ Mark Word（哈希/GC 年龄/锁状态）     │
│   └─ Klass Pointer（指向类元数据）        │
│   （数组另有 length）                     │
├─────────────────────────────────────────┤
│ 实例数据 Instance Data（字段，对齐）      │
├─────────────────────────────────────────┤
│ 对齐填充 Padding（8 字节对齐）            │
└─────────────────────────────────────────┘
```

| 部分 | 内容 |
|------|------|
| Mark Word | 哈希码、GC 分代年龄、锁标志、线程持有锁指针等（**64 位约 8B**） |
| Klass Pointer | 指向方法区类元数据；压缩后 **4B** |
| 数组长度 | 4B（仅数组） |

---

## 2. 对象头 Mark Word（64 位示意）

| 锁状态 | 存储内容 |
|--------|----------|
| 无锁 | hashcode、分代年龄、偏向锁标识 |
| 偏向锁 | 线程 ID、Epoch、年龄 |
| 轻量锁 | 指向栈中 Lock Record 的指针 |
| 重量锁 | 指向 Monitor 的指针 |
| GC 标记 | 空或临时数据 |

**分代年龄**：4 bit → 最大 15，超过 `-XX:MaxTenuringThreshold`（默认 15）进老年代。

---

## 3. 指针压缩

```bash
-XX:+UseCompressedOops          # 默认堆 < 32G 开启
-XX:+UseCompressedClassPointers
```

| 指针类型 | 未压缩 | 压缩后 |
|----------|--------|--------|
| 普通对象引用 | 8B | **4B** |
| Class 指针 | 8B | 4B |

**条件**：堆通常 **< 32GB**（2^32 偏移 × 8 对齐）；超过则禁用压缩 Oops。

**估算**：空 Object 约 **12~16B**（头 + 对齐）；`new Integer(1)` 约 16B 头 + 4B int + 对齐。

---

## 4. 内存分配路径

```
new 对象
  ├─ 栈上分配？（逃逸分析 + 标量替换）
  └─ 堆分配
       ├─ TLAB 线程本地缓冲（Eden 内划线程私有块）
       ├─ Eden 区 CAS 分配
       └─ 失败 → 扩展堆或 GC
```

### 4.1 TLAB（Thread Local Allocation Buffer）

| 项 | 说明 |
|----|------|
| 目的 | 减少 Eden 多线程 **CAS 竞争** |
| 机制 | 每个线程在 Eden 预占一块，分配在 TLAB 内无同步 |
| 参数 | `-XX:+UseTLAB`（默认开）、`-XX:TLABSize` |

TLAB 用尽 → 新 TLAB 或直接在 Eden 分配。

### 4.2 大对象

- 超过 `-XX:PretenureSizeThreshold`（Parallel 有效）可能 **直接进老年代**。
- G1 用 `G1HeapRegionSize` 与 Humongous 对象（占多 Region）。

## 5. 逃逸分析（Escape Analysis）

```java
public int calc() {
    Point p = new Point(1, 2);  // p 未逃出方法
    return p.x + p.y;
    // JIT 可能：栈上分配 Point，或标量替换为两个 int
}
```

| 优化 | 说明 |
|------|------|
| 栈上分配 | 对象不发布到堆（实际常结合标量替换） |
| 标量替换 | 拆成局部变量，**无对象头开销** |
| 锁消除 | 若锁仅在同线程，去掉 synchronized |

**前提**：`-XX:+DoEscapeAnalysis`（默认开）；**JIT 编译后**才生效，非解释执行。

**面试**：逃逸分析是 **JIT 优化**，不是 javac 编译期保证。

## 6. 对象访问定位

| 方式 | 说明 |
|------|------|
| 句柄 | 引用 → 句柄池（对象指针+类型指针），GC 移动对象方便 |
| **直接指针** | 引用 → 对象头（HotSpot **采用**） |

---

## 7. 常见类型大小估算

| 类型 | 约大小（压缩 Oops，64 位） |
|------|---------------------------|
| Object | 12~16 B |
| Integer | 16 B |
| Long | 24 B |
| String | 对象 + char[]/byte[]（JDK9+ compact strings） |
| 空 ArrayList | 对象 + Object[] 引用 |

```java
// 工具：JOL (Java Object Layout)
// Maven: org.openjdk.jol:jol-core
System.out.println(ClassLayout.parseInstance(new Object()).toPrintable());
```

## 8. 数组布局

```
[Mark Word][Klass Pointer][array length][elem0][elem1]...
```

- 数组 Klass 指向数组类元数据。
- 多维数组是数组的数组（引用链）。

## 9. 面试要点

| 问 | 答 |
|----|-----|
| 对象结构？ | 头 + 实例数据 + 对齐 |
| 为什么 8 字节对齐？ | CPU 访问效率、Mark Word 等对齐要求 |
| TLAB 作用？ | 线程私有 Eden 片段，减少分配竞争 |
| 逃逸分析？ | 对象未逃出方法 → 栈分配/标量替换/锁消除 |
| 指针压缩条件？ | 堆 < 32G，默认开启 Compressed Oops |
