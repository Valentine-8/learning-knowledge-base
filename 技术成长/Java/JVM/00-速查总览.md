## 1. 运行时数据区

```
┌─────────────────────────────────────────┐
│  线程私有                                │
│  ├─ 程序计数器 PC（唯一不会 OOM）         │
│  ├─ 虚拟机栈（栈帧）                     │  StackOverflow / OOM
│  └─ 本地方法栈                           │
├─────────────────────────────────────────┤
│  线程共享                                │
│  ├─ 堆 Heap（对象、数组）                │  -Xms / -Xmx
│  ├─ 方法区 Metaspace（类元信息）         │  -XX:MetaspaceSize
│  └─ 直接内存 Direct Memory（NIO）        │  -XX:MaxDirectMemorySize
└─────────────────────────────────────────┘
```

---

## 2. 堆分代（经典模型）

```
新生代 Young                    老年代 Old
Eden | S0 | S1        ──►      长期存活 / 大对象
     Minor GC                   Major / Full GC
```

| GC 类型 | 范围 | 频率 | 停顿 |
|---------|------|------|------|
| Minor GC | 新生代 | 高 | 短 |
| Full GC | 整堆 + 元空间等 | 要低 | 长 |

---

## 3. 收集器选型

| 场景 | 推荐 |
|------|------|
| 通用 Web / 微服务 | **G1**（JDK9+ 默认） |
| 超大堆 + 极低延迟 | **ZGC** |
| 批处理吞吐优先 | Parallel GC |
| 客户端小堆 | Serial |

---

## 4. 常用 JVM 参数

```bash
-Xms4g -Xmx4g                          # 堆初始=最大
-XX:+UseG1GC
-XX:MaxGCPauseMillis=200
-XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=512m
-XX:+HeapDumpOnOutOfMemoryError
-Xlog:gc*:file=gc.log:time,uptime,level,tags   # JDK9+
```

---

## 5. OOM 排查四步

```
1. 确认 OOM 类型（heap / metaspace / direct / thread）
2. dump（-HeapDumpOnOOM 或 jmap）
3. MAT：Dominator Tree + Leak Suspects
4. GC Roots 引用链 → 代码修复
```

## 6. 类加载双亲委派

```
自定义 CL → Application CL → Extension CL → Bootstrap CL
        先委派父加载器，父无法加载才自己 load
```

**打破**：SPI（JDBC）、Tomcat WebApp 隔离、热部署。

## 7. 面试 5 分钟版

| 问 | 答 |
|----|-----|
| 堆和栈区别？ | 堆存对象共享；栈存局部变量、方法帧，线程私有 |
| Minor vs Full GC？ | Minor 只收新生代；Full 整堆+元空间 |
| G1 vs CMS？ | G1 分区可预测停顿、无碎片；CMS 并发但有碎片 |
| 何时 ZGC？ | 大堆、P99 延迟敏感 |
| 双亲委派好处？ | 核心类安全、避免重复加载 |

---

## 8. 易错 checklist

- [ ] `-Xms` ≠ `-Xmx` 会动态扩缩堆
- [ ] 生产别乱 `System.gc()`
- [ ] Metaspace 要设 `MaxMetaspaceSize`
- [ ] jmap dump 用 `live` 减小文件
- [ ] 大对象可能直接进老年代
