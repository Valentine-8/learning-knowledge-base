# 05 · 类加载与双亲委派

> **目标读者**：7 年 Java 后端，需能说明类加载生命周期、双亲委派模型、打破委派的典型场景（SPI、Tomcat）。
> **预计阅读**：50 min · **难度**：★★★

---

## 1. 类加载生命周期

```
加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载
       └──────── 连接 Linking ────────┘
```

| 阶段 | 做什么 |
|------|--------|
| **加载** | 读字节流 → 方法区元数据 → 堆中 Class 对象 |
| **验证** | 文件格式、元数据、字节码、符号引用 |
| **准备** | 静态变量赋 **零值**（`static int a = 10` 此时 a=0） |
| **解析** | 符号引用 → 直接引用（类、字段、方法） |
| **初始化** | 执行 `<clinit>()`：静态块 + 静态赋值顺序 |
| **使用** | 正常访问 |
| **卸载** | 类无引用、ClassLoader 可回收、元空间回收 |

---

## 2. 何时触发初始化

```java
// 1. new 实例
new MyClass();

// 2. 访问静态非 final 字段 / 调用静态方法
MyClass.staticMethod();

// 3. 反射
Class.forName("MyClass");

// 4. 子类初始化 → 先初始化父类
class Child extends Parent { }

// 5. main 所在类
// 6. MethodHandle / 接口 default 方法等（JDK8+）
```

**不会初始化**：

```java
// 编译期常量 → 准备阶段已入常量池
static final int X = 1;

// 数组定义不触发元素类初始化
MyClass[] arr = new MyClass[10];

// 类加载器.loadClass 只加载不初始化
loader.loadClass("MyClass");
```

## 3. ClassLoader 层次

```
Bootstrap ClassLoader（C++，null）
    ↑ 父
Platform / Extension ClassLoader（lib/ext 或 modules）
    ↑ 父
Application / App ClassLoader（CLASSPATH）
    ↑ 父
Custom ClassLoader（用户实现）
```

```java
ClassLoader app = Thread.currentThread().getContextClassLoader();
ClassLoader ext = app.getParent();
ClassLoader boot = ext.getParent();  // null（Bootstrap）
```

| 加载器 | 加载范围 |
|--------|----------|
| Bootstrap | `java.*`、核心 lib（JDK9+ 模块化） |
| Platform | `java.se` 等扩展模块 |
| Application | 应用 classpath、jar |
| Custom | 动态加载、插件、热部署 |

## 4. 双亲委派模型

```java
protected Class<?> loadClass(String name, boolean resolve) {
    // 1. 已加载则直接返回
    // 2. 委派 parent.loadClass
    // 3. parent 失败 → findClass 自己加载
}
```

```
请求 load com.app.Service
  → App CL 委派 → Platform → Bootstrap（找不到）
  → Platform 找不到 → App findClass 加载
```

| 好处 | 说明 |
|------|------|
| 安全 | 用户无法替换 `java.lang.String` |
| 避免重复 | 父已加载则子不重复 |
| 统一 | 核心类由 Bootstrap 保证版本 |

## 5. 打破双亲委派

### 5.1 SPI（Service Provider Interface）

```
JDBC：java.sql.Driver 在 Bootstrap
实现：com.mysql.cj.jdbc.Driver 在 App classpath
```

- `DriverManager` 由 Bootstrap 加载，需加载应用 classpath 中的驱动。
- **线程上下文类加载器** `Thread.contextClassLoader` 由 App CL 加载 SPI 实现。

```java
ServiceLoader.load(Driver.class);  // 用 TCCL
```

### 5.2 Tomcat Web 应用隔离

```
Bootstrap
  └── Common（Tomcat 共享）
        └── WebApp1 ClassLoader  → WEB-INF/classes
        └── WebApp2 ClassLoader  → 独立副本
```

- **WebAppClassLoader**：同一类在不同 WAR 各一份，避免冲突。
- 部分类 **先自加载再委派**（如 Servlet API 版本隔离）。

### 5.3 其他

| 场景 | 方式 |
|------|------|
| OSGi | 模块化网状委派 |
| Spring Boot DevTools | RestartClassLoader 热加载 |
| 字节码增强 | Agent `Instrumentation.redefineClasses` |

## 6. 自定义 ClassLoader

```java
public class MyLoader extends ClassLoader {
    @Override
    protected Class<?> findClass(String name) throws ClassNotFoundException {
        byte[] bytes = loadBytesFromFile(name);
        return defineClass(name, bytes, 0, bytes.length);
    }
}
```

**注意**：`defineClass` 可定义类，但无法加载 `java.*`（Bootstrap 负责）。

## 7. JDK9+ 模块系统（了解）

```
module java.base { exports java.lang; }
```

- **强封装**：未 export 包默认不可反射访问。
- **层（Layer）**：模块加载器与 ClassLoader 配合。
- `--add-opens java.base/java.lang=ALL-UNNAMED` 开放反射（框架常用）。

## 8. 类卸载条件

1. 该 Class 所有实例已回收。
2. 加载它的 ClassLoader 已回收。
3. Class 对象无引用。

**Metaspace OOM** 常因 ClassLoader 泄漏（动态代理、热部署未释放）。
