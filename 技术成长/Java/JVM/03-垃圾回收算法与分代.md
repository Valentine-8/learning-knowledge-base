# 03 · 垃圾回收算法与分代

> **目标读者**：7 年 Java 后端，需能解释可达性分析、三种 GC 算法、分代模型与 Minor/Full GC 触发条件。
> **预计阅读**：60 min · **难度**：★★★★

---

## 1. 如何判断对象可回收

### 1.1 引用计数（Java 未采用）

- 对象被引用 +1，失效 -1，为 0 回收。
- **循环引用**无法解决：`a.ref=b; b.ref=a`。

### 1.2 可达性分析（HotSpot 采用）

从 **GC Roots** 出发，不可达对象可被回收。

```
GC Roots
├── 虚拟机栈中引用的对象（局部变量）
├── 方法区静态属性引用的对象
├── 方法区常量引用的对象
├── 本地方法栈 JNI 引用的对象
├── 同步锁 hold 的对象
├── JMX Bean / Thread 等
└── 分代 GC 中跨代引用（Remembered Set / Card Table）
```

### 1.3 引用类型（JDK 机制）

| 类型 | 回收时机 |
|------|----------|
| 强引用 | 不回收，OOM 前不抛 |
| 软引用 SoftReference | 内存不足前回收（缓存） |
| 弱引用 WeakReference | 下次 GC 即回收（WeakHashMap） |
| 虚引用 PhantomReference | 无法通过引用取对象，用于堆外回收跟踪 |

## 2. 三种基本算法

### 2.1 标记-清除（Mark-Sweep）

```
标记存活对象 → 清除未标记区域
```

| 优点 | 缺点 |
|------|------|
| 实现简单 | **内存碎片** |
| 不需移动对象 | 分配大对象可能失败 |

### 2.2 复制（Copying）

```
内存分两块，只用一半；GC 时存活对象复制到另一半，清空当前
```

| 优点 | 缺点 |
|------|------|
| 无碎片 | **浪费 50% 空间** |
| 分配快（ bump pointer） | 存活率高时复制成本大 |

**新生代** Eden + 2 Survivor 即复制算法：Eden+S0 → S1，互换角色。

### 2.3 标记-整理（Mark-Compact）

```
标记存活 → 向一端移动压缩 → 更新引用
```

| 优点 | 缺点 |
|------|------|
| 无碎片 | **移动对象 + 更新引用** 成本高 |

**老年代**常用标记-整理或标记-清除的变种。

## 3. 分代收集理论

| 假设 | 策略 |
|------|------|
| 多数对象朝生夕死 | 新生代频繁 Minor GC |
| 越老越难死 | 老年代较少 Full GC |
| 跨代引用少 | **Card Table** 记录老→新引用，减少全堆扫描 |

```
┌─────────────────────────────────────────────┐
│ 新生代 Young (1/3 堆典型)                    │
│  Eden (8)  │ S0 (1) │ S1 (1)   SurvivorRatio=8 │
└─────────────────────────────────────────────┘
                    │ 年龄 ≥ MaxTenuringThreshold
                    ▼
┌─────────────────────────────────────────────┐
│ 老年代 Old (2/3)                             │
└─────────────────────────────────────────────┘
```

---

## 4. Minor GC 过程

```
1. Eden 满 → 触发 Minor GC（Stop-The-World）
2. 标记 Eden + 在用 Survivor 中存活对象
3. 复制到另一 Survivor；年龄 +1
4. 年龄达阈值 → 晋升老年代
5. 清空 Eden 和原 Survivor
```

| 参数 | 含义 |
|------|------|
| `-XX:MaxTenuringThreshold=15` | 晋升老年代最大年龄 |
| `-XX:TargetSurvivorRatio=50` | Survivor 目标使用率 |

**动态年龄判定**：Survivor 中相同年龄对象大小超 Survivor 一半 → 该年龄及以上晋升。

## 5. Full GC 触发条件

| 触发场景 | 说明 |
|----------|------|
| System.gc() | 建议 GC，可能 Full GC |
| 老年代空间不足 | 晋升失败、大对象 |
| Metaspace 不足 | 类元数据 |
| CMS Concurrent Mode Failure | 并发阶段来不及回收 |
| Promotion Failed | Survivor 放不下晋升对象 |

**Full GC** 通常 STW 更长，生产要 **监控频率与耗时**。

---

## 6. 安全点与安全区域

- **安全点**：方法调用、循环跳转等可停顿位置，GC 需在安全点暂停线程。
- **安全区域**：线程处于 Sleep/Blocked 时，视为安全区域，进入时标记，离开时补 GC。

---

## 7. 写屏障与 Remembered Set

跨代引用：老年代对象引用新生代 → Minor GC 需扫描老年代？

**Card Table**：老年代划卡片，写引用时 **写屏障** 标记脏卡，Minor GC 只扫脏卡区域。

G1 用 **Remembered Set** 记录 Region 间引用，更精细。

## 8. GC 日志阅读（JDK9+）

```bash
-Xlog:gc*:file=gc.log:time,uptime,level,tags
```

```
[2.5s][info][gc] GC(12) Pause Young (Normal) 24M->8M(256M) 12ms
```

| 字段 | 含义 |
|------|------|
| Pause Young | Minor / Young GC |
| 24M->8M | 回收前后新生代使用 |
| (256M) | 堆当前容量 |
| 12ms | STW 停顿 |
