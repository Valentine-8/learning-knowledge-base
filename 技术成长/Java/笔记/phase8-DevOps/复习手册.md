## 二、Docker

### 核心概念

| 概念 | 说明 |
|------|------|
| 镜像 Image | 只读层，Union FS |
| 容器 Container | 镜像的运行实例 |
| Dockerfile | 构建镜像脚本 |

### Dockerfile 优化

```dockerfile
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY target/*.jar app.jar
# 多阶段构建：构建阶段 maven，运行阶段只留 jre+jar
EXPOSE 8080
ENTRYPOINT ["java","-jar","app.jar"]
```

- **多阶段构建**减小镜像
- 合理 `.dockerignore`
- 层缓存：变动少的 COPY 放前面
- 非 root 用户运行

### 网络与存储

- bridge / host / overlay
- volume 持久化数据，bind mount 开发用

## 三、Kubernetes 核心

```
Cluster
├── Node（工作节点）
│   └── Pod（最小调度单位，1+ 容器）
├── Deployment（无状态，ReplicaSet 管理 Pod 副本）
├── Service（ClusterIP/NodePort/LoadBalancer，稳定访问）
├── Ingress（HTTP 路由到 Service）
├── ConfigMap / Secret（配置与密钥）
└── HPA（水平自动扩缩容）
```

### Pod 生命周期

```
Pending → Running → Succeeded/Failed
探针：
  liveness  存活，失败重启
  readiness 就绪，失败从 Service 摘除
  startup   启动慢时用
```

### 常用命令

```bash
kubectl get pods -n prod
kubectl describe pod xxx
kubectl logs -f pod/xxx -c container
kubectl apply -f deployment.yaml
kubectl scale deployment app --replicas=3
```

### Java 应用在 K8s

- 合理设置 **JVM 堆**（容器 limit 的 70~75%，留 native）
- `-XX:+UseContainerSupport`（JDK10+ 默认识别 cgroup）
- 优雅停机：`preStop` + Spring `server.shutdown=graceful`

## 四、CI/CD

```
代码 push → 触发 Pipeline
→ 编译单元测试 → 构建镜像 → 推送仓库
→ 部署测试环境 → 自动化测试
→ 审批 → 滚动发布生产
```

| 工具 | 说明 |
|------|------|
| Jenkins | 插件生态，Pipeline as Code |
| GitLab CI | `.gitlab-ci.yml` |
| GitHub Actions | yaml workflow |

**质量门禁**：单测覆盖率、Sonar 扫描、依赖漏洞扫描。

## 五、监控与日志

| 层 | 工具 |
|----|------|
| 指标 | Prometheus + Grafana（QPS、延迟、错误率、JVM） |
| 链路 | SkyWalking、Jaeger、Zipkin |
| 日志 | ELK（Elasticsearch+Logstash+Kibana）、Loki |
| 告警 | Alertmanager、钉钉/企微 webhook |

**黄金指标**：延迟、流量、错误、饱和度（Google SRE）。

**日志规范**：结构化 JSON、traceId 贯穿、不打敏感信息。

## 六、Git 工作流

- **Git Flow**：master/develop/feature/release/hotfix
- **Trunk Based**：主干开发，短分支（互联网常见）
- `rebase` vs `merge`：rebase 历史线性；merge 保留分支图
- 冲突解决：理解两边改动再合

## 七、面试速答

| 问 | 答 |
|----|-----|
| Docker 和虚拟机？ | 容器共享内核，轻量；VM 完整 OS 隔离 |
| Pod 是什么？ | K8s 最小调度单元，共享网络命名空间 |
| Deployment 和 StatefulSet？ | 无状态 vs 有状态（固定网络标识、有序部署） |
| 滚动更新？ | 逐步替换 Pod，maxSurge/maxUnavailable 控制 |
| 如何排查 Pod CrashLoop？ | kubectl logs/describe，看 OOM、启动失败、探针 |

## 八、易错点

- [ ] 容器没设 memory limit，JVM 按宿主机算堆 → OOM Kill
- [ ] 镜像用 latest 标签，无法追溯版本
- [ ] Secret 明文提交 Git
- [ ] 生产直接 kubectl edit，要 GitOps
