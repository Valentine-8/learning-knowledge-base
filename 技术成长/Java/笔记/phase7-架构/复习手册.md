## 一、高并发三板斧

```
缓存 → 异步 → 池化
  + 无状态（水平扩展）
  + 限流熔断降级
```

| 手段 | 例子 |
|------|------|
| 缓存 | 多级缓存（本地 Caffeine + Redis） |
| 异步 | MQ 削峰、CompletableFuture |
| 池化 | 连接池、线程池 |
| 读写分离 | 主写从读，注意延迟 |
| CDN | 静态资源边缘节点 |

## 二、高可用

- **多活 / 异地容灾**：RPO/RTO 指标
- **故障转移**：健康检查、自动摘除
- **混沌工程**：故意注入故障验证韧性
- **预案**：降级开关、熔断、限流阈值

## 三、DDD 限界上下文（面试够用版）

| 概念 | 说明 |
|------|------|
| 限界上下文 | 业务边界，一个上下文一套模型 |
| 实体 Entity | 有 ID，生命周期内可变 |
| 值对象 Value Object | 无 ID，不可变（金额、地址） |
| 聚合 Aggregate | 一致性边界，通过根实体访问 |
| 领域事件 | 领域内发生的事，解耦上下文 |
| 防腐层 ACL | 对接外部系统时转换模型 |

**微服务拆分**：按**业务能力/限界上下文**拆，不是按表拆。

## 四、设计模式（场景速记）

| 模式 | 场景 |
|------|------|
| 单例 | 配置、连接池（注意线程安全） |
| 工厂 / 抽象工厂 | 多实现创建 |
| 策略 | 多种算法/规则可替换（支付渠道） |
| 模板方法 | 固定流程，子类扩展步骤 |
| 观察者 | 事件监听（Spring Event） |
| 责任链 | Filter、Interceptor、审批流 |
| 装饰器 | IO 流、增强功能不改原类 |
| 代理 | AOP、RPC stub |
| 适配器 | 老接口适配新接口 |

**原则**：能简单就别模式；Review 时警惕过度抽象。

---

## 五、API 设计

- RESTful：资源名词、HTTP 动词、状态码语义
- **幂等**：PUT/DELETE 天然；POST 用幂等键
- 版本：`/v1/` 或 Header
- 错误码：业务码 + 可读 message，不泄露堆栈
- 分页：cursor 优于深 offset

## 六、系统设计答题框架（45 min 题）

```
1. 需求澄清（QPS、数据量、一致性、延迟）
2. 估算（存储、带宽、机器数）
3. 高层架构图（客户端→网关→服务→存储）
4. 核心流程（时序图）
5. 数据模型 / 存储选型
6. 瓶颈与扩展（缓存、分片、MQ）
7. 可靠性（冗余、备份、监控）
8. 权衡与演进
```

### 经典题要点

| 题 | 关键 |
|----|------|
| 短链 | 哈希/发号器、缓存、301/302 |
| 秒杀 | 静态化、Redis 预减、MQ 异步下单、限流 |
| _feed 流 | 推/拉/推拉结合、热点、分页 |
| 即时通讯 | 长连接 WebSocket、消息序、已读、离线存储 |
| 分布式定时任务 | 时间轮、ZK 选主、分片执行 |

## 七、技术方案文档（ADR）

```
背景 → 目标/非目标 → 方案对比 → 选定方案 → 风险与回滚 → 监控指标
```

7 年工程师要能**写方案、评风险、给数据**，不是堆名词。

---

## 八、面试速答

| 问 | 答 |
|----|-----|
| 如何设计高并发系统？ | 澄清指标→缓存异步池化→无状态扩展→限流熔断→数据层读写分离分片 |
| DDD 和微服务？ | 限界上下文映射服务边界；聚合保证事务一致性边界 |
| 缓存一致性？ | 先更 DB 删缓存；延迟双删；Canal 订阅 |
| 如何拆微服务？ | 按业务域，避免分布式单体；数据归属清晰 |

## 九、易错点

- [ ] 过早微服务，团队小维护不起
- [ ] 跨服务分布式事务滥用
- [ ] 设计不考虑运维和监控
- [ ] 只谈技术不谈成本和排期
