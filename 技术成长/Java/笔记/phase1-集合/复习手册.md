## 一、集合框架全景

```
Collection                    Map
├── List                      ├── HashMap（无序，O(1)）
│   ├── ArrayList             ├── LinkedHashMap（插入序/LRU）
│   ├── LinkedList            ├── TreeMap（红黑树，有序）
│   └── CopyOnWriteArrayList  └── ConcurrentHashMap（线程安全）
├── Set
│   ├── HashSet（底层 HashMap）
│   ├── LinkedHashSet
│   └── TreeSet
└── Queue / Deque
    ├── ArrayDeque（栈/队列首选）
    ├── PriorityQueue（堆）
    └── BlockingQueue 家族（并发）
```

| 接口 | 典型实现 | 线程安全版 | 选型口诀 |
|------|----------|------------|----------|
| List | ArrayList | CopyOnWriteArrayList / Vector(淘汰) | 随机读多→ArrayList |
| Map | HashMap | ConcurrentHashMap | 要顺序→LinkedHashMap；要排序→TreeMap |
| Set | HashSet | ConcurrentHashMap.newKeySet() | 去重用 Set |
| Queue | ArrayDeque | LinkedBlockingQueue 等 | 队列用 Deque 别用 LinkedList |

## 二、ArrayList

| 项 | 内容 |
|----|------|
| 底层 | 动态数组 `Object[]`，**非线程安全** |
| 默认容量 | 10（**首次 add** 时才分配，不是 new 时） |
| 扩容 | **1.5 倍**：`newCap = old + (old >> 1)`，再与 `minCapacity` 取大 |
| 复杂度 | get O(1)；中间 insert/remove O(n)（arraycopy） |
| fail-fast | 迭代中结构修改 → `ConcurrentModificationException`（`modCount`） |

**与 LinkedList**：头插删多 LinkedList 略优，但多数场景 **ArrayDeque** 更好（数组实现、缓存友好）。

## 三、HashMap（JDK 8）

### 核心参数

| 项 | 值/说明 |
|----|---------|
| 结构 | 数组 + 链表 + **红黑树** |
| 默认容量 | 16；负载因子 **0.75** |
| 树化 | 链表长度 **≥ 8** 且数组长度 **≥ 64** |
| 退化 | 树节点 **≤ 6** 退链表 |
| 扩容 | **2 倍**；`(n-1) & hash` 定位桶 |
| null | **允许** 一个 null key、多个 null value |

### put 流程

1. `hash(key)` 扰动（高 16 位参与，减少碰撞）
2. 桶下标 `(n-1) & hash`
3. 桶空 → 直接放 Node
4. 否则：比 key（先 hash 再 equals）；相同则覆盖；不同则尾插链表/树插入
5. `++size`，若 `size > threshold` → **resize**

### resize

- 新容量 = 旧容量 × 2
- 每个节点：要么留原桶，要么去 `原下标 + oldCap`（利用 `(n-1)&hash` 特性，不需重新算 hash）
- JDK7：**头插**扩容可能死循环（多线程）；JDK8 改**尾插**但仍**非线程安全**

### 面试速答

| 问 | 答 |
|----|-----|
| 为什么容量是 2 的幂？ | `(n-1)&hash` 等价取模且分布均匀；扩容翻倍可快速判断节点去留 |
| 为什么重写 equals 必须重写 hashCode？ | equals 相等对象 hash 必须相等，否则 HashMap 找不到 |
| HashMap 线程不安全？ | 多线程 put 丢数据/覆盖；JDK7 resize 死循环；用 CHM 或 `Collections.synchronizedMap` |

## 四、ConcurrentHashMap（JDK 8）

| 对比 | HashMap | ConcurrentHashMap |
|------|---------|-------------------|
| 线程安全 | 否 | 是 |
| null | key/value 可 null | **都不允许**（歧义） |
| JDK7 | — | Segment 分段锁 |
| JDK8 | — | **synchronized 锁桶头** + CAS 放首节点 |
| size | — | baseCount + CounterCell 类似 LongAdder |

**put 要点**：桶空 CAS 放；否则 synchronized 锁头节点再操作链表/树。

**size 统计**：多线程下用分散计数再求和，避免全局锁。

## 五、泛型与类型擦除

```java
List<String> a = new ArrayList<>();
// 编译后擦除为 List，运行时无 String 类型信息
```

| 概念 | 说明 |
|------|------|
| 类型擦除 | 编译期检查，运行期泛型信息丢失（反射/字节码可看签名） |
| PECS | **Producer extends, Consumer super** |
| `<? extends T>` | 只能读（生产者），不能 add（除 null） |
| `<? super T>` | 只能写 T 及子类（消费者），读只能当 Object |

**典型题**：`List<? extends Number>` 不能 `add(1)`；`List<? super Integer>` 可 add Integer，读出来是 Object。

## 六、Stream API

| 类型 | 操作 | 特点 |
|------|------|------|
| 中间操作 | filter/map/flatMap/sorted/distinct | **惰性**，不触发计算 |
| 终止操作 | collect/count/forEach/reduce | 触发流水线 |

**Parallel Stream**：共用 `ForkJoinPool.commonPool()`；**有状态/IO/小数据**别用；要保证无共享可变状态。

**常用**：`Collectors.groupingBy`、`toMap`（注意 key 冲突）、`partitioningBy`。

## 七、Java 8 → 21 新特性（复习要点）

| 版本 | 特性 | 要点 |
|------|------|------|
| 8 | Lambda、Stream、Optional、java.time | 别用 `Date/Calendar` |
| 11 | `var`、HTTP Client | LTS |
| 17 | Record、Sealed Class、Pattern Matching | Record 不可变 DTO |
| 21 | **Virtual Thread**（虚拟线程） | IO 密集高并发；别在虚拟线程里 synchronized 长时间占载体线程 |

**Optional**：表达可能为空；别滥用 `get()`；链式 `map/orElseThrow`。

**java.time**：`Instant`（UTC 时间戳）、`ZonedDateTime`（带时区）、`Duration/Period`。

## 八、fail-fast vs fail-safe

| | fail-fast | fail-safe |
|--|-----------|-----------|
| 代表 | ArrayList、HashMap 迭代器 | CopyOnWriteArrayList、ConcurrentHashMap 迭代器 |
| 行为 | 检测到 modCount 变化抛异常 | 遍历**副本/弱一致**快照 |
| 场景 | 单线程别边遍历边改 | 并发读多写少 |

## 九、易错点 checklist

- [ ] 用 `Integer` 作 HashMap key 时注意缓存 -128~127 与 equals
- [ ] `Arrays.asList` 返回固定大小 List，不能 add/remove
- [ ] `subList` 是原列表视图，原列表修改可能导致子列表异常
- [ ] HashMap **初始容量**要预估，避免频繁 resize
- [ ] `ConcurrentHashMap` 的 `size()` 是估计值
- [ ] Stream 里不要改外部可变变量（应用 collect）
