# 01 面向对象与泛型

> **目标**：7 年工程师应能讲清 OOP 设计取舍、多态底层机制、泛型擦除与 PECS，并在 Code Review 中识别常见反模式。

---

## 一、面向对象四大特性

### 1.1 封装（Encapsulation）

**定义**：隐藏内部状态，通过受控接口暴露行为。

**后端意义**：
- Domain 对象不暴露可变集合引用（返回 `Collections.unmodifiableList` 或拷贝）
- DTO/Entity 分层，避免持久化细节泄漏到 API
- 配置类通过 getter 暴露，setter 仅在构建期可用（Builder 模式）

```java
public class Order {
    private final List<OrderItem> items = new ArrayList<>();

    public List<OrderItem> getItems() {
        return Collections.unmodifiableList(items);
    }

    public void addItem(OrderItem item) {
        Objects.requireNonNull(item);
        items.add(item);
    }
}
```

**面试点**：「封装」不仅是 private 字段 + getter/setter，而是 **不变量（invariant）** 由类自身维护。

### 1.2 继承（Inheritance）

**is-a 关系**：子类是父类的一种特殊形式。

**限制**：
- Java 单继承（类），多实现（接口）
- `final` 类不可继承（如 `String`、`Integer`）
- 继承破坏封装：子类依赖父类实现细节，父类变更可能破坏子类

**Liskov 替换原则（LSP）**：
- 子类对象应能替换父类对象而不改变程序正确性
- 反例：正方形继承矩形，修改宽时高也变，违反调用方对「矩形」的假设

### 1.3 多态（Polymorphism）

**编译期类型 vs 运行期类型**：

```java
Animal a = new Dog();
a.speak();  // 编译期看 Animal.speak() 是否存在；运行期调用 Dog.speak()
```

**绑定方式**：

| 调用类型 | 绑定时机 | 示例 |
|----------|----------|------|
| 静态方法 | 编译期 | `Parent.staticMethod()` |
| private/final 实例方法 | 编译期 | 不可重写 |
| 实例方法 | 运行期（虚方法表） | 普通 override |
| 字段访问 | 编译期 | 看引用类型，不看实际对象 |

**虚方法表（vtable）**：每个类有方法表，对象头指向类元数据，invokevirtual 通过 vtable 偏移查找实际实现。这是 JVM 层多态的实现基础，与 C++ 虚表类似。

### 1.4 抽象（Abstraction）

**抽象类**：可有构造器、成员变量、具体方法；抽象方法无实现。

**接口（Java 8+）**：默认方法、静态方法、私有方法；Java 9+ 私有静态方法。

**选型建议**：

| 场景 | 选择 |
|------|------|
| 共享状态或模板方法 | 抽象类 |
| 多种 unrelated 类型实现同一能力 | 接口 |
| 需要多重「类型标签」 | 接口（如 `Serializable` + `Cloneable`） |
| API 演进、向后兼容 | 接口 default 方法 |

## 二、重载与重写

### 2.1 重载（Overload）

- 同一类中，方法名相同，**参数列表不同**（类型、个数、顺序）
- 返回值 alone 不构成重载
- 编译期根据静态类型解析 → **静态分派**

```java
void print(List<String> list) { }
void print(List<Integer> list) { }  // 擦除后签名相同，编译错误！
```

泛型擦除后若签名冲突，需不同方法名或桥方法由编译器处理 override 场景。

### 2.2 重写（Override）

- 子类方法与父类 **签名相同**（名称、参数、返回类型协变）
- 访问权限不能更严格；异常不能 broader checked exception
- `@Override` 注解强制编译器校验

**返回类型协变**：父类返回 `Animal`，子类可返回 `Dog`。

## 三、组合优于继承

### 3.1 何时用继承

- 真正的 is-a，且 LSP 成立
- 框架扩展点（如 `HttpServlet`、Spring `OncePerRequestFilter`）
- 需要利用 protected 模板方法（谨慎）

### 3.2 何时用组合/委托

- 仅为复用代码 → 组合
- 需要运行时切换行为 → 策略模式 + 接口
- 避免 fragile base class

```java
// 委托而非继承
public class LoggingExecutor implements Executor {
    private final Executor delegate;

    public LoggingExecutor(Executor delegate) {
        this.delegate = delegate;
    }

    @Override
    public void execute(Runnable command) {
        log.info("task submitted");
        delegate.execute(command);
    }
}
```

### 3.3 SOLID 与后端映射

| 原则 | 含义 | 后端示例 |
|------|------|----------|
| S 单一职责 | 一类一变化原因 | Controller 不直接写 SQL |
| O 开闭 | 对扩展开放，对修改关闭 | 支付渠道 Strategy + 注册表 |
| L 里氏替换 | 子类可替换父类 | 缓存实现可互换 |
| I 接口隔离 | 接口小而专 | 不强迫实现无用方法 |
| D 依赖倒置 | 依赖抽象 | Service 依赖 Repository 接口 |

## 四、equals、hashCode 与对象契约

### 4.1 契约

`equals` 必须满足：自反、对称、传递、一致；`x.equals(null)` 为 false。

**与 hashCode**：若 `a.equals(b)`，则 `a.hashCode() == b.hashCode()`。反之不成立。

### 4.2 实现要点

- 使用 `Objects.equals(a, b)` 防 NPE
- 不可变字段优先作为 equals 依据
- 重写 equals 必须重写 hashCode
- 继承体系中使用 `getClass()` 比较，不用 `instanceof`（除非明确需要）

### 4.3 HashMap 键对象

作为 HashMap key 的类必须正确实现 equals/hashCode；否则「相等」对象可能落在不同桶，导致 get 失败。

**反模式**：仅用部分字段做 hashCode，equals 却比较全部字段。

## 五、不可变对象

### 5.1 好处

- 线程安全，无需同步
- 可安全共享、缓存
- 简化推理，减少防御性拷贝

### 5.2 构建要点

```java
public final class Money {
    private final BigDecimal amount;
    private final Currency currency;

    public Money(BigDecimal amount, Currency currency) {
        this.amount = Objects.requireNonNull(amount);
        this.currency = Objects.requireNonNull(currency);
    }

    public Money add(Money other) {
        if (!currency.equals(other.currency)) throw new IllegalArgumentException();
        return new Money(amount.add(other.amount), currency);
    }
}
```

- `final` 类防止子类破坏不变性
- 不暴露可变内部状态
- String、Integer、LocalDate 均为不可变典型

## 六、泛型基础

### 6.1 为什么需要泛型

编译期类型检查，消除强制转换，提高可读性；运行时通过擦除保持向后兼容。

```java
List<String> list = new ArrayList<>();
list.add("hello");
// list.add(1);  // 编译错误
String s = list.get(0);  // 无需 cast
```

### 6.2 类型参数与边界

```java
// 上界：T 必须是 Number 子类
public <T extends Number> double sum(List<T> list) { ... }

// 多个边界
public <T extends Number & Comparable<T>> T max(T a, T b) { ... }
```

### 6.3 通配符

| 写法 | 读作 | 能读 | 能写 |
|------|------|------|------|
| `List<?>` | 未知类型的 List | 读为 Object | 几乎不能 add |
| `List<? extends T>` | T 的某个子类型 | 读为 T | 不能 add（除 null） |
| `List<? super T>` | T 的某个父类型 | 读为 Object | 可 add T 及子类 |

---

## 七、PECS 原则

**Producer Extends, Consumer Super**

- **生产者**（只读出来用）→ `? extends T`
- **消费者**（只往里写）→ `? super T`

```java
// 从 src 读元素，写入 dest
public static <T> void copy(List<? extends T> src, List<? super T> dest) {
    for (T item : src) {
        dest.add(item);
    }
}
```

**API 设计**：`Collections.sort(List<T> list)` 需要读写同一类型，故用 `<T>` 而非通配符。

**7 年工程师考点**：能解释 `Collections.addAll(List<? super T> list, T... elements)` 为何用 super。

## 八、类型擦除

### 8.1 编译后是什么

```java
// 源码
List<String> list = new ArrayList<>();

// 擦除后近似等价
List list = new ArrayList();  // 原始类型 raw type
```

泛型信息在 **字节码签名（Signature attribute）** 中保留，供反射读取；运行时默认不可获取 `List<String>` 的 `String`。

### 8.2 桥方法（Bridge Method）

子类泛型重写父类泛型方法时，编译器生成桥方法保持多态：

```java
class Node<T> {
    public T data() { return null; }
}
class StringNode extends Node<String> {
    @Override
    public String data() { return "x"; }
    // 编译器生成：public Object data() { return data(); }
}
```

### 8.3 擦除带来的限制

- 不能 `new T()`、`new T[]`（数组协变与擦除冲突）
- 不能 `instanceof List<String>`（可写 `list instanceof List`）
- 不能 catch `T` 类型异常（除非具体类）
- 静态字段不能引用类型参数

### 8.4 获取泛型类型的方式

- 子类 **显式指定** 类型参数：`new TypeToken<List<String>>() {}`
- 方法/字段 **ParameterizedType** 反射（需保留 Signature）
- Guava `TypeToken`、Jackson `JavaType` 均基于此

## 九、泛型与数组

**数组是协变、可 reified 的**；**泛型是 invariant、擦除的**。

```java
// 合法但危险
Number[] nums = new Integer[10];
nums[0] = 1.0;  // ArrayStoreException 运行时

// 非法
// List<String>[] array = new List<String>[10];
```

**最佳实践**：集合用 `List<T>`，需要数组时用 `toArray(T[]::new)`。

## 十、实战：通用 Repository 接口设计

```java
public interface Repository<ID, E extends Entity<ID>> {
    Optional<E> findById(ID id);
    E save(E entity);
    void deleteById(ID id);
    Page<E> findAll(Specification<E> spec, Pageable pageable);
}
```

- `E extends Entity<ID>` 保证 ID 类型与实体一致
- 查询侧 `Specification<E>` 只读 → 可用 extends
- 批量写入 API 考虑 `? super E`

## 十一、常见反模式（Code Review）

| 反模式 | 问题 | 改进 |
|--------|------|------|
| 贫血模型 | 只有 getter/setter，逻辑散落 Service | 富领域模型或明确 DDD 分层 |
| 继承仅为复用 | fragile base class | 组合 |
| raw type | 失去类型安全 | ParameterizedType |
| `(List) list`  unchecked cast | ClassCastException | 正确泛型或 TypeToken |
| equals 无 hashCode | HashMap/HashSet 异常 | 同时重写 |
| 可变 Date | 线程不安全 | `Instant` / `LocalDateTime` |

## 十三、设计模式与 OOP 映射

### 13.1 策略模式（Strategy）

```java
public interface PricingStrategy {
    Money price(Order order);
}

public class OrderService {
    private final Map<CustomerLevel, PricingStrategy> strategies;

    public Money calculate(Order order) {
        return strategies.get(order.getCustomerLevel()).price(order);
    }
}
```

替代 if-else 链，符合开闭原则；Spring 注入 `List<PricingStrategy>` + `@Qualifier` 或注册表模式。

### 13.2 模板方法（Template Method）

```java
public abstract class AbstractExportJob {
    public final void run() {
        List<Row> data = fetchData();
        validate(data);
        write(format(data));
    }
    protected abstract List<Row> fetchData();
    protected void validate(List<Row> data) { /* 默认空 */ }
}
```

继承定义骨架，子类填步骤；注意 fragile base class，钩子方法文档化。

### 13.3 工厂 vs 抽象工厂

- **工厂方法**：一个产品等级，子类决定实例化哪种
- **抽象工厂**：产品族（WinButton + WinCheckbox）

后端常见：BeanFactory、ConnectionFactory，本质是工厂 + DI 容器。

## 十四、里氏替换与契约式编程

### 14.1 前置条件、后置条件、不变量

子类 override 时：
- **前置条件**不能更强（不能要求更多）
- **后置条件**不能更弱（保证不能少）
- **类不变量**必须维护

```java
// 反例：父类 account.withdraw 允许任意正数，子类 OverdraftAccount 只允许 ≤ 1000
// 若调用方按父类契约 withdraw(5000)，子类行为违反 LSP
```

### 14.2 防御性拷贝

```java
public class Period {
    private final Date start;
    private final Date end;

    public Period(Date start, Date end) {
        this.start = new Date(start.getTime());  // 防御外部修改
        this.end = new Date(end.getTime());
    }

    public Date getStart() {
        return new Date(start.getTime());
    }
}
```

Date 可变导致的问题；现代代码用 `Instant`/`LocalDate` 替代。

## 十五、泛型高级场景

### 15.1 递归类型边界（F-bounded）

```java
public interface Comparable<T extends Comparable<T>> {
    int compareTo(T other);
}
```

`Enum<E extends Enum<E>>` 同理，保证 compareTo 参数类型与自身一致。

### 15.2 通配符捕获（capture）

```java
public static void swap(List<?> list, int i, int j) {
    swapHelper(list, i, j);  // 编译错误：不能写 list
}

private static <T> void swapHelper(List<T> list, int i, int j) {
    T tmp = list.get(i);
    list.set(i, list.get(j));
    list.set(j, tmp);
}
```

`?` 无法作为类型参数写入，需辅助泛型方法捕获。

### 15.3 泛型 Singleton

```java
private static final AtomicReference<Object[]> EMPTY_ARRAY = new AtomicReference<>();

@SuppressWarnings("unchecked")
public static <T> T[] emptyArray(Class<T> type) {
    Object[] array = EMPTY_ARRAY.get();
    if (array == null || array.getClass().getComponentType() != type) {
        array = Array.newInstance(type, 0);
        EMPTY_ARRAY.set(array);
    }
    return (T[]) array;
}
```

`Collections.emptyList()` 返回 `List<T>` 靠类似擦除 + unchecked cast，调用方指定类型。

## 十八、手写题：实现类型安全的 Pair

```java
public final class Pair<L, R> {
    private final L left;
    private final R right;

    private Pair(L left, R right) {
        this.left = left;
        this.right = right;
    }

    public static <L, R> Pair<L, R> of(L left, R right) {
        return new Pair<>(left, right);
    }

    public L left() { return left; }
    public R right() { return right; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Pair<?, ?> pair)) return false;
        return Objects.equals(left, pair.left) && Objects.equals(right, pair.right);
    }

    @Override
    public int hashCode() {
        return Objects.hash(left, right);
    }
}
```

面试扩展：如何实现 `Pair<L, R> mapLeft(Function<L, L2> f)` 并正确推断 L2。
