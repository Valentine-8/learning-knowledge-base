# 02 注解、反射与异常

> **目标**：理解 Spring/MyBatis 等框架的「注解驱动」底层机制，掌握反射的性能边界，建立可观测、可维护的异常体系。

---

## 一、注解本质

### 1.1 注解是什么

注解（Annotation）是 **带元数据的接口**，编译后由 `Annotation` 接口的实现类（动态代理或生成类）表示。

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface RateLimit {
    int permitsPerSecond() default 100;
    String key() default "";
}
```

使用处：

```java
@RateLimit(permitsPerSecond = 50, key = "order:create")
public Order createOrder(CreateOrderCmd cmd) { ... }
```

### 1.2 注解 vs 注释 vs 配置

| 维度 | 注释 | 注解 | 外部配置 |
|------|------|------|----------|
| 编译器处理 | 丢弃 | 可保留到 class | N/A |
| 与代码耦合 | 无 | 高 | 低 |
| 运行时读取 | 否 | 可以 | 可以 |
| 典型用途 | 说明 | 框架元编程 | 环境差异 |

**7 年工程师视角**：注解适合 **稳定的结构性元数据**（路由、权限、ORM 映射）；频繁变更的业务规则更适合配置中心或数据库。

## 二、元注解

### 2.1 @Target

限定注解可标注的元素：

```java
public enum ElementType {
    TYPE, FIELD, METHOD, PARAMETER, CONSTRUCTOR,
    LOCAL_VARIABLE, ANNOTATION_TYPE, PACKAGE,
    TYPE_PARAMETER, TYPE_USE, MODULE, RECORD_COMPONENT
}
```

`TYPE_USE` 支持泛型：`List<@NonNull String>`。

### 2.2 @Retention

| 策略 | 生命周期 | 典型 |
|------|----------|------|
| SOURCE | 源码，编译丢弃 | `@Override`、`@SuppressWarnings` |
| CLASS | 进入 class，反射不可见 | 部分编译期注解 |
| RUNTIME | 反射可读 | Spring `@Component` |

### 2.3 @Inherited

仅对 **类** 注解有效：子类继承父类类级别注解（接口不继承）。

### 2.4 @Repeatable（Java 8）

同一位置多次使用同一注解：

```java
@Repeatable(Schedules.class)
public @interface Schedule { ... }

@Schedule(cron = "0 0 * * * ?")
@Schedule(cron = "0 30 * * * ?")
public void syncJob() { }
```

### 2.5 @Documented / @Native

- `@Documented`：出现在 Javadoc
- `@Native`：JNI 相关字段提示

## 三、注解处理器

### 3.1 编译期 APT（Annotation Processing Tool）

在编译阶段生成代码或校验：

- Lombok：生成 getter/setter、builder
- MapStruct：生成映射实现类
- AutoService：生成 SPI 配置文件

**流程**：`javac` → 注解处理器轮次 → 可能产生新源文件 → 再次编译。

**优势**：零运行时反射开销；错误编译期暴露。

### 3.2 运行期反射读取

Spring 启动时扫描 `@Component`、`@Autowired` 等，构建 BeanDefinition。

```java
RateLimit rl = method.getAnnotation(RateLimit.class);
if (rl != null) {
    int qps = rl.permitsPerSecond();
}
```

**注意**：注解属性必须是编译期常量（基本类型、String、Class、enum、注解、上述数组）。

## 四、反射 API 体系

### 4.1 获取 Class 对象

```java
Class<?> c1 = String.class;
Class<?> c2 = "hello".getClass();
Class<?> c3 = Class.forName("java.lang.String");
```

**类加载**：`forName` 触发初始化（执行 static 块）；`.class` 不触发。

### 4.2 核心 API

| API | 用途 |
|-----|------|
| `getDeclaredFields()` | 所有字段（不含父类 public） |
| `getFields()` | public 字段含继承 |
| `getDeclaredMethods()` | 声明的方法 |
| `setAccessible(true)` | 突破 private（JDK 9+ 模块限制） |
| `Constructor.newInstance()` | 创建实例 |
| `Method.invoke(obj, args)` | 调用方法 |

```java
Method m = clazz.getDeclaredMethod("privateMethod", String.class);
m.setAccessible(true);
Object result = m.invoke(instance, "arg");
```

### 4.3 泛型反射

```java
Field field = clazz.getDeclaredField("items");
Type genericType = field.getGenericType();
if (genericType instanceof ParameterizedType pt) {
    Type raw = pt.getRawType();           // List
    Type[] args = pt.getActualTypeArguments(); // String
}
```

## 五、反射性能与优化

### 5.1 为什么慢

- 方法访问校验、装箱拆箱
- `invoke` 无法被 JIT 内联（早期）
- 安全 manager / 模块检查

**数量级**：单次 invoke 比直接调用慢 **1～2 个数量级**；框架启动时大量反射可接受，**热路径**不可接受。

### 5.2 优化手段

| 手段 | 说明 |
|------|------|
| 缓存 Method/Field | 启动时解析一次 |
| `setAccessible(true)` | 关闭访问检查（JDK 11+ `--add-opens`） |
| MethodHandle | JSR 292，更接近直接调用 |
| 字节码生成 | CGLIB、ByteBuddy、ASM 生成子类/代理 |
| 编译期 APT | 彻底消除运行时反射 |

**Spring 实践**：
- 启动：ClassPathScanning 反射扫描
- 运行时：CGLIB 子类代理替代部分反射调用
- Spring 6 / Native：AOT 预生成 Bean 定义，减少反射

### 5.3 MethodHandle 示例

```java
MethodHandles.Lookup lookup = MethodHandles.lookup();
MethodHandle mh = lookup.findVirtual(String.class, "length", MethodType.methodType(int.class));
int len = (int) mh.invoke("hello");
```

## 六、框架中的注解链路（Spring 简化）

```
@ComponentScan 指定包路径
    ↓
ClassPathBeanDefinitionScanner 扫描 .class
    ↓
读取 @Component / @Service / @Configuration
    ↓
解析 @Bean 方法 → BeanDefinition
    ↓
AutowiredAnnotationBeanPostProcessor 处理 @Autowired / @Value
    ↓
CommonAnnotationBeanPostProcessor 处理 @PostConstruct / @PreDestroy
    ↓
容器实例化 + 依赖注入
```

**MyBatis**：`@Mapper` 接口 → `MapperFactoryBean` → JDK 动态代理 → `MapperProxy` 解析 `@Select` 等 → `SqlSession`。

**7 年考点**：能画从 `@RestController` 到 HandlerMethod 的注册过程（Spring MVC）。

## 七、自定义注解 + AOP 实战

```java
@Aspect
@Component
public class RateLimitAspect {
    private final LoadingCache<String, RateLimiter> limiters = Caffeine.newBuilder()
            .build(key -> RateLimiter.create(100));

    @Around("@annotation(rl)")
    public Object around(ProceedingJoinPoint pjp, RateLimit rl) throws Throwable {
        String key = rl.key().isEmpty() ? pjp.getSignature().toShortString() : rl.key();
        RateLimiter limiter = limiters.get(key, k -> RateLimiter.create(rl.permitsPerSecond()));
        if (!limiter.tryAcquire()) {
            throw new BusinessException(ErrorCode.RATE_LIMIT);
        }
        return pjp.proceed();
    }
}
```

要点：注解仅声明策略；切面统一织入；限流器缓存避免重复创建。

## 八、Java 异常体系

```
Throwable
├── Error（不应捕获）
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── ...
└── Exception
    ├── RuntimeException（Unchecked）
    │   ├── NullPointerException
    │   ├── IllegalArgumentException
    │   └── ...
    └── Checked Exception（必须处理或声明）
        ├── IOException
        ├── SQLException
        └── ...
```

### 8.1 Checked vs Unchecked 争议

**传统 Java**：Checked 强制调用方处理 IO、SQL 异常。

**现代后端倾向**：
- 业务层用 **Unchecked 业务异常**（Spring `@Transactional` 默认只 rollback RuntimeException）
- 边界层（Controller）统一捕获转 HTTP 响应
- 避免「异常污染」方法签名（层层 throws IOException）

## 九、业务异常设计

### 9.1 分层

```java
public abstract class BaseException extends RuntimeException {
    private final String errorCode;
    private final HttpStatus httpStatus;

    protected BaseException(String errorCode, String message, HttpStatus status) {
        super(message);
        this.errorCode = errorCode;
        this.httpStatus = status;
    }
}

public class BusinessException extends BaseException {
    public BusinessException(ErrorCode code) {
        super(code.getCode(), code.getMessage(), code.getHttpStatus());
    }
}
```

### 9.2 错误码规范

- 机器可读：`ORDER_NOT_FOUND`、`INSUFFICIENT_STOCK`
- 携带 traceId 便于日志关联
- 区分 **用户可见消息** vs **内部诊断信息**（不向前端泄漏 SQL）

### 9.3 与 HTTP 状态码

| 场景 | HTTP | 异常类型 |
|------|------|----------|
| 参数校验失败 | 400 | ValidationException |
| 未认证 | 401 | AuthException |
| 无权限 | 403 | ForbiddenException |
| 资源不存在 | 404 | NotFoundException |
| 业务规则冲突 | 409 / 422 | BusinessException |
| 系统故障 | 500 | SystemException |

## 十、异常最佳实践

### 10.1 不吞异常

```java
// 反模式
try {
    doWork();
} catch (Exception e) {
    log.error("failed");  // 丢失 stack trace
}

// 正确
try {
    doWork();
} catch (Exception e) {
    log.error("doWork failed, orderId={}", orderId, e);
    throw new SystemException("WORK_FAILED", e);
}
```

### 10.2 异常链

```java
throw new ServiceException("save order failed", cause);
```

保留 root cause，MAT/日志分析时可追溯。

### 10.3 控制流反模式

不要用异常做正常分支（如 `parseInt` 循环内 catch NumberFormatException）。

## 十一、try-with-resources

Java 7+ 自动关闭 `AutoCloseable`：

```java
try (InputStream in = Files.newInputStream(path);
     OutputStream out = Files.newOutputStream(outPath)) {
    in.transferTo(out);
}
```

**Suppressed Exception**：close 时若主 try 和 close 都抛异常，close 的异常附加为 suppressed。

**实现 AutoCloseable** 时注意 close 幂等。

## 十二、全局异常处理（Spring）

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ApiError> handleBusiness(BusinessException ex, WebRequest req) {
        return ResponseEntity.status(ex.getHttpStatus())
                .body(ApiError.of(ex.getErrorCode(), ex.getMessage()));
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiError> handleValidation(MethodArgumentNotValidException ex) {
        String msg = ex.getBindingResult().getFieldErrors().stream()
                .map(e -> e.getField() + ": " + e.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return ResponseEntity.badRequest().body(ApiError.of("VALIDATION_ERROR", msg));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiError> handleUnknown(Exception ex) {
        log.error("unhandled", ex);
        return ResponseEntity.internalServerError()
                .body(ApiError.of("INTERNAL_ERROR", "系统繁忙，请稍后重试"));
    }
}
```

**注意**：`@ExceptionHandler` 匹配最近父类；顺序从具体到通用。

## 十三、序列化与反序列化安全

### 13.1 Java 原生序列化

```java
ObjectInputStream ois = new ObjectInputStream(input);
Object obj = ois.readObject();  // 危险：任意类构造链
```

**风险**：gadget chain 远程代码执行（Apache Commons Collections 等历史漏洞）。

**建议**：
- 新系统禁用 Java 序列化，用 JSON/Protobuf
- 必须用时：`ObjectInputFilter`（JEP 290）白名单
- 不反序列化不可信数据

### 13.2 JSON 反序列化

- Jackson 默认类型：`enableDefaultTyping` 曾导致 RCE
- 使用 `@JsonTypeInfo` 显式控制多态
- 只绑定 DTO，不直接绑定 Domain Entity
