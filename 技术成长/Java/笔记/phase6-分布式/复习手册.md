# Phase 6 复习手册：分布式 · 消息队列 · ES

> **用法**：通读 45 min。CAP、分布式事务、MQ 幂等、限流熔断是核心。

---

## 一、理论基础

### CAP

| | 说明 |
|--|------|
| C 一致性 | 所有节点同一时刻看到相同数据 |
| A 可用性 | 请求总能得到响应 |
| P 分区容错 | 网络分区时系统仍能工作 |

**定理**：最多同时满足两个。**分布式系统必须接受 P**，在 C 和 A 间权衡。

- **CP**：ZooKeeper、etcd（选举期间不可用）
- **AP**：Eureka、Cassandra（可能短暂不一致）

### BASE

- **Basically Available** 基本可用
- **Soft state** 软状态
- **Eventually consistent** 最终一致

## 二、分布式事务

| 方案 | 一致性 | 说明 |
|------|--------|------|
| 2PC | 强 | 协调者两阶段，阻塞、单点 |
| TCC | 最终 | Try-Confirm-Cancel，业务侵入大 |
| Saga | 最终 | 长事务拆本地事务+补偿 |
| 本地消息表 | 最终 | 同库事务写业务+消息，定时投递 |
| 事务消息（RocketMQ） | 最终 | 半消息 |
| **Seata AT** | 最终 | 自动 undo_log，对业务透明 |

**选型**：强一致场景少，多数用**最终一致 + 补偿**。

## 三、分布式锁

| 实现 | 优点 | 缺点 |
|------|------|------|
| Redis SET NX | 快 | 主从切换可能丢锁 |
| Redisson | 看门狗、可重入 | 同上 |
| ZooKeeper 临时顺序节点 | 强一致 | 性能、运维成本 |
| DB 唯一索引 | 简单 | 性能差 |

## 四、限流 · 熔断 · 降级

| 概念 | 说明 |
|------|------|
| 限流 | 控制 QPS，令牌桶/漏桶/滑动窗口 |
| 熔断 | 下游故障率超阈值 → 快速失败，半开探测 |
| 降级 | 关非核心功能，返回兜底 |

**Sentinel**：滑动窗口统计、规则热更新、与 Spring Cloud 集成。

**Hystrix**（维护模式）：线程池/信号量隔离、已逐渐被 Sentinel/Resilience4j 替代。

## 五、消息队列（Kafka / RocketMQ）

### 为什么用 MQ

削峰填谷、异步解耦、最终一致、广播。

### 通用问题

| 问题 | 解法 |
|------|------|
| **丢失** | 生产者 ack、Broker 持久化、消费者手动 ack |
| **重复** | **幂等**：业务唯一键、Redis 去重、DB 唯一约束 |
| **顺序** | 单分区单消费者；或业务层按 key 路由同队列 |
| **积压** | 扩容消费者、批量消费、降级、跳过非核心 |

### Kafka vs RocketMQ

| | Kafka | RocketMQ |
|--|-------|----------|
| 吞吐 | 极高 | 高 |
| 延迟 | 毫秒级 | 毫秒级，事务消息 |
| 顺序 | 分区内 | 队列内 |
| 场景 | 日志、大数据管道 | 业务消息、电商 |

### 消费语义

- **at most once**：可能丢
- **at least once**：可能重复（常见）
- **exactly once**：Kafka 事务 + 幂等 sink

## 六、Elasticsearch（简述）

| 概念 | 说明 |
|------|------|
| 倒排索引 | 词 → 文档列表 |
| 分片 Shard | 水平拆分 |
| 副本 Replica | 高可用、读扩展 |
| 写入 | 近实时，先写内存再 refresh |

**同步方案**：Canal 监听 binlog → MQ → ES；或双写（不推荐）。

**和 MySQL 分工**：MySQL 事务写；ES 搜索、聚合、日志分析。

## 八、面试速答

| 问 | 答 |
|----|-----|
| CAP 怎么选？ | 分布式必 P；CP 强一致；AP 高可用最终一致 |
| 如何保证 MQ 不丢？ | 生产 ack、Broker 同步刷盘、消费手动 commit |
| 幂等怎么做？ | 唯一业务 ID + DB 唯一索引 / Redis setnx |
| 分布式 ID？ | 雪花、号段、UUID（无序不利索引） |
| 接口幂等？ | Token、唯一键、状态机防重 |

## 九、易错点

- [ ] 消费者自动 ack 失败消息会丢
- [ ] 大消息打爆 Broker，要压缩或对象存储+传链接
- [ ] 分布式事务不是银弹，能避免就避免
- [ ] ES 不适合做主库，不做强一致写
