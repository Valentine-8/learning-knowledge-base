# 03 · 设计模式实战

> **预计阅读**：80 min

---

## 1. 模式不是银弹

```
适用：变化点隔离、扩展开放、代码可读
滥用：简单 if-else 硬套工厂+策略+装饰器
```

**7 年 Review 能力**：识别过度设计，也识别该用模式却硬写分支的地方。

---

## 2. 创建型模式

| 模式 | 场景 | Java/Spring 例子 |
|------|------|------------------|
| 单例 | 全局唯一实例 | Spring Bean 默认单例 |
| 工厂方法 | 子类决定创建哪种产品 | `BeanFactory` |
| 抽象工厂 | 一族相关产品 | UI 主题套件 |
| 建造者 | 多步骤复杂对象 | `Lombok @Builder`、`HttpRequest.Builder` |
| 原型 | 克隆对象 | `Object.clone`（少用） |

**单例注意**：枚举单例、双重检查锁、Spring 管理优于手写。

---

## 3. 结构型模式

| 模式 | 场景 | 例子 |
|------|------|------|
| 适配器 | 老接口适配新接口 | `InputStreamReader` |
| 装饰器 | 动态增强功能 | Java IO 流、`@Cacheable` 思想 |
| 代理 | 控制访问、延迟加载 | Spring AOP、RPC Stub |
| 外观 | 简化子系统调用 | Facade Service |
| 桥接 | 抽象与实现分离 | JDBC Driver |
| 组合 | 树形结构统一处理 | 菜单树 |
| 享元 | 共享细粒度对象 | 字符串常量池、连接池 |

---

## 4. 行为型模式（面试高频）

| 模式 | 场景 | 例子 |
|------|------|------|
| 策略 | 算法/规则可替换 | 支付渠道、促销计算 |
| 模板方法 | 固定骨架，子类填步骤 | `JdbcTemplate`、抽象类 |
| 观察者 | 一对多通知 | Spring `ApplicationEvent` |
| 责任链 | 请求沿链传递 | Filter、Interceptor、审批 |
| 命令 | 请求封装为对象 | 撤销/重做、MQ 消息 |
| 状态 | 状态驱动行为 | 订单状态机 |
| 迭代器 | 遍历集合 | `Iterator` |
| 中介者 | 对象间解耦 | MQ、事件总线 |
| 备忘录 | 保存/恢复状态 | 草稿箱 |
| 访问者 | 数据结构与操作分离 | 编译器 AST（少用） |
| 解释器 | 语法解析 | SpEL（了解） |

## 5. 实战：策略 + 工厂

```java
public interface PaymentStrategy {
    PayResult pay(PayRequest req);
}

@Service
public class PaymentService {
    private final Map<PayChannel, PaymentStrategy> strategies;

    public PayResult pay(PayRequest req) {
        return strategies.get(req.channel()).pay(req);
    }
}
```

Spring 注入 `List<PaymentStrategy>` 自动注册 Map，比手写工厂更惯用。

## 6. 实战：责任链

```
Servlet Filter → Spring Interceptor → AOP → Controller
```

审批流、风控规则链同理：每个节点处理或传递。

## 7. 架构模式（系统设计常提）

| 模式 | 说明 |
|------|------|
| 分层 | Controller-Service-DAO |
| MVC | 视图与逻辑分离 |
| 微内核 | 插件化核心 |
| 事件驱动 | MQ、领域事件 |
| CQRS | 读写分离模型 |

---

## 8. SOLID 与模式关系

| 原则 | 模式体现 |
|------|----------|
| 开闭 | 策略、装饰器 |
| 单一职责 | 每个类一个变化理由 |
| 依赖倒置 | 面向接口，Spring DI |
| 里氏替换 | 子类可替换父类 |
| 接口隔离 | 细粒度接口 |

## 9. Code Review 反模式清单

- [ ] 单例手写双重锁而不交给容器
- [ ] 三层继承只为复用两个方法（用组合）
- [ ] 策略模式只有两种实现且不会扩展
- [ ] 过度使用反射+注解实现「灵活框架」
- [ ] 状态模式用字符串 status + 巨型 switch 更清晰时仍硬套
