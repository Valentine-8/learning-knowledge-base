# 01 · 响应式编程基础

> **预计阅读**：90 min

## 1. 为什么响应式

传统阻塞模型：

```
1 请求 = 1 线程（Tomcat 200 线程 → 最多 ~200 并发连接处理）
```

线程阻塞在 IO 时浪费资源。响应式用**少量线程 + 事件循环**处理大量连接。

---

## 2. Reactive Streams 规范

四个核心接口：

| 接口 | 角色 |
|------|------|
| Publisher | 发布数据 |
| Subscriber | 订阅消费 |
| Subscription | 订阅关系 |
| Processor | 处理器 |

**背压（Backpressure）**：Subscriber 通过 `request(n)` 告诉 Publisher 发多少，防止生产者压垮消费者。

## 4. 操作符（常考）

| 操作符 | 作用 |
|--------|------|
| `map` | 同步转换 1:1 |
| `flatMap` | 异步转换 1:N，无序 |
| `concatMap` | 异步有序 |
| `flatMapSequential` | 有限并发有序 |
| `zip` | 组合多个 Publisher |
| `merge` | 合并流 |
| `onErrorResume` | 错误降级 |
| `timeout` | 超时 |
| `retry` | 重试 |

```java
webClient.get().retrieve().bodyToMono(User.class)
    .timeout(Duration.ofSeconds(3))
    .onErrorResume(e -> Mono.empty());
```

## 5. Scheduler 线程模型

| Scheduler | 用途 |
|-----------|------|
| `Schedulers.immediate()` | 当前线程 |
| `Schedulers.boundedElastic()` | 阻塞 IO 包装 |
| `Schedulers.parallel()` | CPU 密集 |

```java
Mono.fromCallable(() -> blockingJdbcQuery())
    .subscribeOn(Schedulers.boundedElastic());
```

**规则**：阻塞操作必须离开 event loop，用 `subscribeOn(boundedElastic)`。

## 6. 热流 vs 冷流

| | Cold | Hot |
|---|------|-----|
| 特点 | 有订阅才生产 | 生产与订阅无关 |
| 例子 | `Mono.just` | `Sinks`, `share()` |

## 7. block() 与 subscribe()

```java
// 测试
User u = mono.block();

// 生产（WebFlux 自动 subscribe）
return mono.map(this::toDto);
```

**Never block on event loop thread** — 会导致 Netty 假死。

## 8. 与 Java 虚拟线程

Java 21 **虚拟线程**让阻塞代码低成本：

```
阻塞 MVC + 虚拟线程  vs  WebFlux + Reactor
```

许多团队选后者更简单；WebFlux 仍在 Gateway、全 reactive 栈有优势。
