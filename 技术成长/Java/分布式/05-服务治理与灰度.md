# 05 · 服务治理与灰度

> **目标读者**：7 年 Java 后端，能讲清注册发现、负载均衡、配置中心与灰度发布策略。
> **预计阅读**：50 min · **难度**：★★★★

## 1. 微服务治理全景

```
                    ┌──────────────┐
                    │  配置中心     │  动态配置、开关
                    └──────┬───────┘
                           │
    客户端 ──► Gateway ──► 注册中心 ◄── 服务实例(健康心跳)
                  │              │
                  └─ 负载均衡 ────┘
                  └─ 灰度路由
                  └─ 限流熔断(Sentinel)
```

---

## 2. 服务注册与发现

### 2.1 流程

```
1. 服务启动 → 向注册中心注册(IP、端口、元数据)
2. 定时心跳 → 保活
3. 消费者拉取/订阅实例列表
4. 本地缓存 + 推送变更
5. 下线/超时 → 剔除实例
```

### 2.2 主流注册中心

| 组件 | 特点 |
|------|------|
| **Nacos** | AP/CP 可切换；注册+配置一体；国内主流 |
| **Eureka** | AP；自我保护；Spring Cloud 老项目 |
| **Consul** | 多 DC、健康检查、KV |
| **ZooKeeper** | CP；老 Dubbo 注册；见 [06 章](./06-ZooKeeper与注册中心.md) |

Nacos 实战 → [SpringCloud/02-Nacos注册发现](../SpringCloud/02-Nacos注册发现.md)。

## 3. 健康检查

| 类型 | 说明 |
|------|------|
| 心跳 | 客户端周期 ping（Nacos/Eureka） |
| TCP/HTTP 探活 | Consul、K8s probe |
| 被动剔除 | 调用失败累计踢出（Ribbon 配合） |

**注意**：服务 **启动完成** 再注册（Readiness），避免半启动接流量。

## 4. 负载均衡

### 4.1 客户端 LB（Spring Cloud）

`Spring Cloud LoadBalancer` 替代 Ribbon：

| 策略 | 说明 |
|------|------|
| RoundRobin | 轮询（默认） |
| Random | 随机 |
| Weighted | 权重（Nacos 元数据） |
| 同 zone 优先 | 减少跨机房延迟 |

```java
@LoadBalanced
@Bean
RestTemplate restTemplate() { return new RestTemplate(); }

// 或 OpenFeign 内置 LB
@FeignClient(name = "order-service")
```

Feign 详见 [SpringCloud/05](../SpringCloud/05-OpenFeign与负载均衡.md)。

### 4.2 服务端 LB

Nginx、Gateway、云 SLB — **入口统一调度**，后端实例透明。

## 6. 灰度发布

### 6.1 目标

新版本 **小流量验证** → 逐步放大 → 全量；异常快速回滚。

### 6.2 路由维度

| 维度 | 示例 |
|------|------|
| 流量比例 | 5% 到新版本 |
| 请求头 | `X-Version: v2` |
| 用户 ID | 白名单用户走新版本 |
| 地域/机房 | 单 AZ 先试 |
| 标签 metadata | Nacos `tag=gray` |

### 6.3 实现方式

```
Gateway 路由规则：
  - Path=/api/order/** AND Header version=v2 → order-service-v2
  - 默认 → order-service-v1

或 Istio VirtualService / K8s Argo Rollouts
```

### 6.4 与发布策略

| 策略 | 说明 |
|------|------|
| 蓝绿 | 两套环境，切换流量 |
| 金丝雀 | 逐步加新版本比例 |
| 滚动 | K8s 默认，逐 Pod 替换 |

**数据库兼容**：灰度期 **向后兼容** API 与 schema（expand-contract）。

## 7. 服务元数据与多环境

```yaml
spring:
  cloud:
    nacos:
      discovery:
        metadata:
          version: v2
          zone: hangzhou-a
```

消费者按 metadata 路由；Feign + 自定义 `LoadBalancer` 实现灰度。

## 8. 治理常见问题

| 问题 | 处理 |
|------|------|
| 注册风暴 | 分批启动；延长心跳 |
| 缓存脏实例 | 短 TTL + 推送；调用失败剔除 |
| 配置泄露 | 权限 RBAC、加密、审计 |
| 全链路灰度 | Gateway + 透传 header + 下游 Feign 拦截器 |

## 9. 面试题精选

**Q：Eureka 自我保护是什么？**  
A：心跳大面积失败时不立即剔除，防止网络抖动误杀；AP 体现。

**Q：Nacos AP 和 CP 模式？**  
A：临时实例 Distro AP；持久实例 Raft CP。

**Q：灰度和 AB 测试区别？**  
A：灰度重 **发布风险**；AB 重 **业务指标对比**，常长期并行。

---

## 10. 本章小结

- **注册发现**是微服务导航；**配置中心**是动态开关。
- **负载均衡**客户端（Feign）+ 服务端（Gateway）分层。
- **灰度**靠 metadata + 路由规则；schema 须兼容。
