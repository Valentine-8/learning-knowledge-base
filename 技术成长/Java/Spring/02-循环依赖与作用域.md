# 02 · 循环依赖与作用域

> **目标读者**：能讲清三级缓存、提前曝光、哪些场景无法解决，并结合源码回答面试追问。
> **预计阅读**：50 min · **难度**：★★★★★

---

## 1. 什么是循环依赖

```java
@Service
public class A {
    @Autowired
    private B b;
}

@Service
public class B {
    @Autowired
    private A a;
}
```

创建 A 需要 B，创建 B 需要 A → **循环**。

Spring **默认单例 + 属性注入** 可解决；其他场景不行。

---

## 2. 三级缓存

```java
// DefaultSingletonBeanRegistry（简化）
Map<String, Object> singletonObjects = new ConcurrentHashMap<>();           // 一级：成品
Map<String, Object> earlySingletonObjects = new HashMap<>();                // 二级：早期
Map<String, ObjectFactory<?>> singletonFactories = new HashMap<>();         // 三级：工厂
```

| 级别 | 键值 | 说明 |
|------|------|------|
| 一级 | beanName → 完整 Bean | getBean 最终返回 |
| 二级 | beanName → 早期引用 | 可能是未完全初始化的对象 |
| 三级 | beanName → ObjectFactory | 调用 `getEarlyBeanReference` 可能生成代理 |

---

## 3. 解决流程（A↔B 属性注入）

```
1. getBean(A)
2. 创建 A 实例（空壳），将 A 的 ObjectFactory 放入三级缓存
3. 填充 A 的属性 → 需要 B → getBean(B)
4. 创建 B 实例，B 的工厂入三级
5. 填充 B 的属性 → 需要 A
6. 从三级拿 A 的工厂 → getEarlyBeanReference(A) → 放入二级 → 返回 A 的早期引用给 B
7. B 完成初始化 → 一级缓存 B
8. A 继续填充，得到完整 B → A 完成 → 一级缓存 A
9. 清除二三级 A 相关条目
```

**关键**：提前暴露的是 **ObjectFactory**，若需要 AOP，在 `getEarlyBeanReference` 里可创建 **代理对象**，保证 B 注入的 A 与最终 A 一致。

---

## 4. 不能解决的场景

| 场景 | 原因 |
|------|------|
| **构造器注入循环** | 实例化阶段就要 B，B 也要 A，无早期引用 |
| **prototype 循环** | 每次 new，不缓存 |
| **多例 + 单例混合** | prototype 不进入三级缓存 |
| **@Async 等需完整 Bean** | 特殊初始化顺序 |

**构造器循环报错**：

```
BeanCurrentlyInCreationException: Error creating bean with name 'a':
Requested bean is currently in creation: Is there an unresolvable circular reference?
```

**解决构造器循环**：

- 改 **setter/字段** 注入
- `@Lazy` 延迟一方
- 重构设计（事件、Provider）

```java
public A(@Lazy B b) { this.b = b; }
```

---

## 5. `@Lazy` 原理

```java
@Autowired
@Lazy
private B b;  // 注入 B 的代理，首次调用才初始化真实 B
```

打破「创建时必须存在」的环。

---

## 6. ObjectProvider / Provider

```java
@Service
public class A {
    private final ObjectProvider<B> bProvider;
    public A(ObjectProvider<B> bProvider) { this.bProvider = bProvider; }
    void work() {
        B b = bProvider.getObject();  // 延迟获取
    }
}
```

---

## 7. 设计层面避免

| 手段 | 说明 |
|------|------|
| 分层 | Controller → Service → Repository，单向依赖 |
| 事件 | `ApplicationEvent` 解耦 |
| 接口下沉 | 共同依赖接口模块 |
| Facade | 合并过紧的两个 Service |

**7 年工程师**：能讲三级缓存，也要能说 **不应依赖循环依赖写业务**。

---

## 8. 源码入口

```
AbstractBeanFactory.doGetBean
  → DefaultSingletonBeanRegistry.getSingleton
  → beforeSingletonCreation / afterSingletonCreation
  → addSingletonFactory / getEarlyBeanReference
```

**面试追问**：「二级缓存能否去掉？」—— 讨论 AOP 代理一致性；Spring 2.6+ 对无 AOP 场景有优化讨论，答「保证早期引用与最终 Bean 一致，尤其代理场景」。

---

## 9. 面试题

| 问 | 答 |
|----|-----|
| 三级缓存分别是什么？ | 成品、早期引用、ObjectFactory |
| 为什么需要三级不是二级？ | 延迟决定是否 AOP 代理；工厂可多次决策 |
| 构造器循环怎么办？ | @Lazy、改注入方式、重构 |
| prototype 为何不行？ | 不.singleton 缓存，无法提前暴露 |

---

## 10. 图解：有 AOP 时的 early reference

```
创建 A（需被 B 注入）
  → 实例化 A 原始对象
  → addSingletonFactory(A, () -> getEarlyBeanReference(A))
       → 若需 AOP，此处可能返回 A 的代理
  → 填充 B...
  → B 注入的是 early 中的引用（可能是代理）
  → A 初始化完成，最终 singletonObjects 中也是同一代理
```

若二级缓存直接放原始对象，B 注入原始 A，而最终对外是代理 A → **不一致**。

---

## 11. Spring Boot 2.6+ 变化（了解）

- `spring.main.allow-circular-references=false` 默认 **禁止** 循环依赖（Boot 2.6+ 倾向显式打破）
- 面试可答：「能讲三级缓存，但新项目应 **设计避免** 循环依赖；Boot 可配置允许。」
