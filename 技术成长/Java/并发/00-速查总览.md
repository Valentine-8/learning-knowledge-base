## 1. 并发三要素

| 要素 | 含义 | 手段 |
|------|------|------|
| **原子性** | 操作不可分割 | synchronized、Lock、CAS |
| **可见性** | 一线程写，他线程能立刻看到 | volatile、synchronized、final |
| **有序性** | 禁止有害指令重排 | volatile、happens-before |

## 2. 锁与同步一图

```
                    ┌─────────────────┐
                    │   synchronized   │  JVM 内置，自动释放
                    │  偏向→轻量→重量   │
                    └────────┬────────┘
                             │
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
    volatile            ReentrantLock          CAS 原子类
   可见+有序            AQS · 可中断公平         乐观无锁
   不保证原子            多 Condition
```

## 3. AQS 骨架

```
state（int）+ CLH 双向队列
├─ CAS 抢 state
├─ 失败 → 入队 park
└─ release → 唤醒后继
```

JUC 锁、Semaphore、CountDownLatch、线程池 Worker 均基于 AQS。

---

## 4. 线程池 7 参数

```java
new ThreadPoolExecutor(
    corePoolSize, maximumPoolSize, keepAliveTime, unit,
    workQueue, threadFactory, handler
);
```

**执行顺序**：核心未满 → 新建核心线程 → 否则入队 → 队满且未达 max → 新建非核心 → 否则拒绝。

| 队列 | 生产建议 |
|------|----------|
| ArrayBlockingQueue | **有界**，防 OOM |
| LinkedBlockingQueue | 注意默认容量极大 |
| SynchronousQueue | Cached 风格，线程数≈max |

**拒绝策略**：`CallerRunsPolicy` 做背压；默认 `AbortPolicy` 抛异常。

**不要用 `Executors` 工厂**：无界队列/无限线程 → OOM 或线程爆炸。

---

## 5. 线程数估算

| 类型 | 经验 |
|------|------|
| CPU 密集 | N 或 N+1 |
| IO 密集 | 2N 或 `N × (1 + 等待/计算)` |

**隔离**：订单 / 通知 / 查询 **不同线程池**，互不影响。

## 6. 高频面试 5 题

| 问 | 答 |
|----|-----|
| synchronized vs ReentrantLock？ | JVM 自动 vs API 灵活（中断、超时、公平、多 Condition） |
| volatile 保证原子吗？ | **不能**，仅可见+有序 |
| ThreadLocal 为何泄漏？ | 线程池复用线程，Entry 强引用 value，用完须 `remove()` |
| AQS 是什么？ | state + CLH 队列，JUC 同步器基石 |
| 虚拟线程适合什么？ | IO 密集；不适合 CPU 密集、大量 synchronized（pin） |

## 7. 生产易错 checklist

- [ ] `@Async` 默认池不适合生产，须自定义
- [ ] 异步线程里 **Spring 事务失效**
- [ ] `parallelStream` 与业务池争用 common pool
- [ ] ThreadLocal 在线程池场景忘记 `remove()`
- [ ] 锁粒度：能读写锁就别互斥锁，能无锁就 CAS
