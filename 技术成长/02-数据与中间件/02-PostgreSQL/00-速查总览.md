## 1. 是什么

**PostgreSQL（PG）** 开源对象关系型数据库，标准 SQL 支持好，扩展强（JSONB、GIS、全文），MVCC 无读锁并发读。

**Java 连接**：

```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/mydb
    username: app
    password: ***
    driver-class-name: org.postgresql.Driver
```

依赖：`org.postgresql:postgresql`

## 2. 架构一图

```
Client (JDBC)
    │
    ▼
Postmaster（主进程）
    ├── Backend 进程 × N（每个连接一个）
    ├── WAL Writer / Checkpointer / Autovacuum ...
    └── Shared Buffers（共享缓冲）
            │
            ▼
        数据文件 + WAL 段
```

## 3. 与 MySQL InnoDB 速对比

| 维度 | PostgreSQL | MySQL InnoDB |
|------|------------|--------------|
| 默认隔离级别 | **Read Committed** | **Repeatable Read** |
| 聚簇 | 堆表，无聚簇 PK | 聚簇索引 |
| 空字符串 | `''` 与 NULL 不同 | 常混用 |
| JSON | **JSONB** 二进制+索引 | JSON 类型 |
| 分页 | `LIMIT/OFFSET` 深分页慢 | 类似 |
| 复制 | 物理/逻辑流复制 | Binlog 主从 |
| 国内生态 | 增长中 | 更普遍 |

## 4. 常用 SQL 差异

```sql
-- 自增
id BIGSERIAL PRIMARY KEY;
-- 或
CREATE SEQUENCE user_id_seq;
INSERT INTO user(id, name) VALUES (nextval('user_id_seq'), 'a');

-- 分页
SELECT * FROM orders ORDER BY id LIMIT 20 OFFSET 40;

-- UPSERT
INSERT INTO t (id, v) VALUES (1, 'x')
ON CONFLICT (id) DO UPDATE SET v = EXCLUDED.v;

-- 当前时间
NOW(), CURRENT_TIMESTAMP

-- 字符串拼接
'hello' || ' world'
```

## 5. EXPLAIN 速查

```sql
EXPLAIN (ANALYZE, BUFFERS, FORMAT TEXT)
SELECT * FROM orders WHERE user_id = 100 AND status = 1;
```

| 节点 | 含义 |
|------|------|
| Seq Scan | 全表扫 |
| Index Scan | 索引定位再回表 |
| Index Only Scan | 覆盖索引 |
| Bitmap Index Scan | 多条件组合 |
| Nested Loop / Hash Join / Merge Join | 连接方式 |

## 6. JSONB 一行

```sql
CREATE TABLE product (
  id BIGSERIAL PRIMARY KEY,
  attrs JSONB NOT NULL DEFAULT '{}'
);
CREATE INDEX idx_attrs ON product USING GIN (attrs);

SELECT * FROM product WHERE attrs @> '{"color":"red"}';
SELECT attrs->>'name' FROM product WHERE id = 1;
```

## 7. VACUUM（PG 特有必知）

UPDATE/DELETE 产生 dead tuple，需 **VACUUM** 回收空间；**Autovacuum** 自动跑。

| 现象 | 可能原因 |
|------|----------|
| 表膨胀 | autovacuum 跟不上 |
| 事务 ID 回卷 | 长事务阻塞 vacuum |
| 慢查询 | 未建索引、统计信息过期 `ANALYZE` |

## 8. 面试 5 分钟

| 问 | 答 |
|----|-----|
| PG 和 MySQL 选型？ | PG：复杂查询、JSON、GIS、标准 SQL；MySQL：国内运维熟、电商 OLTP 多 |
| MVCC 如何实现？ | 每行多版本 xmin/xmax，快照可见性，无读锁 |
| JSON 和 JSONB？ | JSON 存文本；JSONB 二进制、去重键、可 GIN 索引 |
| 为什么需要 VACUUM？ | 回收 dead row，更新 visibility map，防膨胀 |
| ON CONFLICT？ | PG 的 UPSERT，需唯一约束 |
