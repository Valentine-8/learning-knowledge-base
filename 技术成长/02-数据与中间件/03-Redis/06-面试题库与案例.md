## 2. 面试题库（55 题）

### 2.1 基础与架构（1～10）

**Q1. Redis 是什么？适用场景？**

A：内存 KV 存储，单线程命令执行；场景：缓存、计数、Session、分布式锁、排行榜、轻量 MQ（Stream）。不适合：大 value 持久化主库、强一致账务。

**Q2. Redis 为什么快？**

A：内存；高效数据结构；单线程无锁竞争；IO 多路复用（epoll）；多数操作 O(1)/O(log N)。

**Q3. 单线程如何处理高并发？**

A：命令串行无竞态；多连接由事件循环非阻塞处理；瓶颈常在内存/网络非 CPU。6.0+ IO 线程可并行读写字节，命令仍单线程。

**Q4. Redis 与 Memcached 区别？**

A：Redis 多数据结构、持久化、主从/Cluster、单线程；Memcached 多线程、纯 KV、无原生持久化。Redis 功能更丰富，Memcached 极简缓存。

**Q5. 五种基本类型？**

A：String、Hash、List、Set、ZSet；外加 Bitmap、HyperLogLog、GEO、Stream。

**Q6. 线程模型演变？**

A：6.0 前单线程处理网络+命令；6.0+ 可选 IO 线程处理 read/write，命令执行仍主线程。

**Q7. Redis 6.0 新特性了解？**

A：多 IO 线程、ACL 权限、RESP3、Client Side Cache 等。

**Q8. 如何选择 Redis 版本？**

A：生产用稳定版 7.x；关注 TLS、ACL、混合持久化、listpack 替代 ziplist。

**Q9. db 0～15 是什么？**

A：逻辑库编号，Cluster 仅 db0。生产一般单库 + key 前缀区分业务。

**Q10. Redis 事务（MULTI/EXEC）？**

A：命令排队批量执行，非关系库事务：无回滚，某条失败其余仍执行。Watch 实现 CAS 乐观。

### 2.2 数据结构底层（11～22）

**Q11. String 底层 SDS 优势？**

A：O(1) 长度、二进制安全、预分配减少扩容、兼容 C 字符串部分 API。

**Q12. embstr 和 raw 区别？**

A：短串 redisObject 与 SDS 同分配只读；长串分开分配可修改。

**Q13. Hash 底层编码？**

A：小对象 listpack 紧凑；超阈值 hashtable（dict）。

**Q14. 渐进式 rehash？**

A：dict 扩容时双表，日常操作顺带迁移 bucket，避免一次性阻塞。

**Q15. ZSet 为何用跳表不用红黑树？**

A：实现简单、范围查询友好、与 dict 组合 O(1) 查 score。

**Q16. ZSet 底层结构？**

A：skiplist 排序 + dict member→score 指针共享。

**Q17. List 底层？**

A：quicklist = 双向链表 + listpack 节点（Redis 7）。

**Q18. ziplist 为何被 listpack 替代？**

A：ziplist 连锁更新；listpack 反向 backlen 避免级联。

**Q19. intset 何时用？**

A：Set 全整数且元素 ≤ 512（可配）用 intset，否则 hashtable。

**Q20. Stream 底层？**

A：radix tree 组织 listpack 链；支持 Consumer Group、ACK、Pending。

**Q21. HyperLogLog 误差？**

A：标准误差约 0.81%，适合 UV 近似统计，极省内存。

**Q22. GEO 原理？**

A：基于 ZSet，member 为 id，score 为 geohash 编码；GEORADIUS 算距离。

### 2.3 持久化与高可用（23～35）

**Q23. RDB 和 AOF 区别？**

A：RDB 快照紧凑恢复快可能丢区间；AOF 日志耐久文件大恢复慢。

**Q24. AOF 刷盘策略？**

A：always 每条 fsync；everysec 每秒（默认丢 1s）；no 靠 OS。

**Q25. AOF 重写作用？**

A：根据内存现状生成最小命令集压缩体积；子进程 + rewrite buffer。

**Q26. 混合持久化？**

A：4.0+ AOF 重写文件 RDB 头 + AOF 增量，恢复快且耐久。

**Q27. fork 为何导致卡顿？**

A：大内存 copy 页表；写密集 COW 内存涨；THP 加剧。

**Q28. 主从复制流程？**

A：全量 RDB + 缓冲命令；增量 replication buffer；backlog 断线重连。

**Q29. 主从延迟原因？**

A：异步复制、从库单线程、网络、大 key 全量同步。

**Q30. Sentinel 作用？**

A：监控、通知、自动故障转移、配置提供者；Raft 类投票选 Leader Sentinel。

**Q31. Sentinel 如何选新主？**

A：过滤主观/客观下线；replica-priority；复制 offset 最大；runid 最小。

**Q32. Cluster 槽位数量？**

A：16384；CRC16(key) & 16383；便于心跳与迁移粒度平衡。

**Q33. MOVED 和 ASK 区别？**

A：MOVED 槽永久迁移；ASK 迁移中临时重定向。

**Q34. Hash Tag？**

A：`{tag}` 部分参与 hash，同 tag 同槽，支持 multi-key。

**Q35. Cluster 能跨槽事务吗？**

A：不能，需同槽；Lua 脚本同理。

### 2.4 缓存设计（36～44）

**Q36. 缓存穿透/击穿/雪崩？**

A：穿透不存在打 DB；击穿热点过期；雪崩集体失效或 Redis 宕机。

**Q37. Cache Aside 读写？**

A：读 miss 查 DB 回填；写 DB 后删缓存。

**Q38. 为何先写 DB 再删缓存？**

A：先删缓存易旧值回填；仍可能极短不一致，可延迟双删/Canal。

**Q39. 布隆过滤器缺点？**

A：误判存在、难删元素、需预热重建。

**Q40. 互斥锁重建缓存？**

A：SET NX 仅一线程查 DB，其他等待或重试，防击穿。

**Q41. 逻辑过期？**

A：value 内 expireTime，不设 TTL；过期仍返旧值，单线程异步刷新。

**Q42. 多级缓存一致性？**

A：写删 Redis + Pub/Sub 广播删本地 Caffeine。

**Q43. Canal 方案？**

A：Binlog → MQ → 删/更新缓存，最终一致，需幂等。

**Q44. 缓存命中率低排查？**

A：TTL 过短、key 设计、预热不足、穿透、实例内存淘汰。

---

### 2.5 分布式锁（45～50）

**Q45. Redis 分布式锁实现？**

A：SET key uuid NX EX；Lua 校验 uuid 再 DEL。

**Q46. 为何要 unique value？**

A：防线程 A 删线程 B 的锁。

**Q47. Redisson 看门狗？**

A：默认 30s 锁，每 10s 续期；业务未完成自动延长。

**Q48. RedLock 争议？**

A：非 CP；主从/时钟/GC 可能导致不安全；强一致用 ZK/etcd。

**Q49. Redis 锁 vs ZK 锁？**

A：Redis 高性能 AP 极端丢锁；ZK 临时顺序节点 CP 强一致性能较低。

**Q50. 锁过期业务未完成？**

A：看门狗续期、合理 TTL、业务幂等兜底。

### 2.6 生产调优（51～55）

**Q51. 大 key 危害与治理？**

A：阻塞删、迁移慢、fork 涨内存；UNLINK、拆分、压缩、归档。

**Q52. 热 key 治理？**

A：本地缓存、多副本 key、读写分离、限流。

**Q53. 内存淘汰策略？**

A：allkeys-lfu/lru 纯缓存；volatile-lru 部分 TTL；noeviction 写拒绝。

**Q54. 慢查询排查？**

A：SLOWLOG、latency doctor；KEYS 改 SCAN；避免大 key 全量读。

**Q55. Redis 单线程如何利用多核？**

A：Cluster 多分片多实例；6.0 IO 线程；业务侧多连接池多实例。

## 3. 生产案例（8 个）

### 案例 1：秒杀库存超卖

| 项 | 内容 |
|----|------|
| 背景 | 大促秒杀，Redis 预扣库存 + MySQL 异步落库 |
| 现象 | 库存 100 售出 107，客诉 |
| 根因 | 主从切换锁丢失 + 未用 Lua 原子 DECR 判断 + 无 DB 约束 |
| 动作 | Redisson 锁 + Lua `if get>=n then decr` + DB `WHERE stock>=n` + 对账回补 |
| 结果 | 超卖归零；P99 延迟 +3ms 可接受 |

**口述要点**：锁不是银弹，DB 乐观锁/唯一约束最后一道防线。

---

### 案例 2：缓存穿透打垮 MySQL

| 项 | 内容 |
|----|------|
| 背景 | 用户详情 API，id 可枚举 |
| 现象 | DB CPU 95%，Redis 命中率 40% |
| 根因 | 恶意随机 id + 无空值缓存 + 无布隆 |
| 动作 | 布隆预热全量 id + 空值 TTL 120s + 网关 id 格式校验 + 单 IP 限流 |
| 结果 | DB QPS 从 8000 降至 200 |

---

### 案例 3：热点 key 单节点 CPU 100%

| 项 | 内容 |
|----|------|
| 背景 | 明星直播点赞，单 key 计数 |
| 现象 | Cluster 某节点 CPU 100%，其他 20% |
| 根因 | 单 key 单 slot 热读热写 |
| 动作 | 应用层本地聚合 500ms 批量刷 Redis；`like:{roomId}:{0..15}` 分片；CDN 静态计数展示 |
| 结果 | 该节点 CPU 35%，点赞延迟体感无变化 |

---

### 案例 4：大 key 删除导致 P99 3s

| 项 | 内容 |
|----|------|
| 背景 | 用户粉丝 List 800 万元素 |
| 现象 | 删用户时 `DEL fans:user:xxx` P99 3s |
| 根因 | 同步 DEL 大 List 阻塞主线程 |
| 动作 | 改 UNLINK；粉丝改 ZSet 分页 + DB 存全量；定时 `--bigkeys` 治理 |
| 结果 | 删用户 P99 < 5ms |

---

### 案例 5：AOF 80GB 重启 6 小时

| 项 | 内容 |
|----|------|
| 背景 | 3 年未 rewrite 的日志型 Redis |
| 现象 | 故障重启 6 小时未就绪 |
| 根因 | 纯 AOF 巨大 + 未开混合 |
| 动作 | 从库 BGREWRITEAOF；开 `aof-use-rdb-preamble`；低峰自动 rewrite；冷 key 归档 |
| 结果 | AOF 12GB，重启 8 分钟 |

---

### 案例 6：主从延迟读脏数据

| 项 | 内容 |
|----|------|
| 背景 | 读写分离，写主读从 |
| 现象 | 改密码后 2s 内旧密码仍能登录 |
| 根因 | 异步复制延迟 + 缓存未删 |
| 动作 | 写后删缓存；敏感读走主库 2s；Canal 删缓存 |
| 结果 | 客诉消失；主库读 QPS +5% |

---

### 案例 7：Sentinel 误切换双写

| 项 | 内容 |
|----|------|
| 背景 | 网络抖动 |
| 现象 | 短暂双主，部分数据冲突 |
| 根因 | 分区 + `min-replicas-to-write` 未配 |
| 动作 | 配置 min-replicas；应用写前 GET 集群 epoch；切换期间熔断写 |
| 结果 | 再未出现双主写 |

---

### 案例 8：内存碎片 OOM

| 项 | 内容 |
|----|------|
| 背景 | 8GB 数据 16GB RSS |
| 现象 | 凌晨批量过期后进程被 kill |
| 根因 | 碎片率 2.5 + noeviction |
| 动作 | activedefrag；改 allkeys-lfu；新实例双写迁移 |
| 结果 | RSS 降至 9GB，稳定运行 |

## 4. 连环追问示例

**题：设计一个商品详情缓存**

```
1. Key 设计？ → product:detail:{id}，TTL 随机 30min
2. 更新策略？ → 写 DB 删缓存；Canal 兜底
3. 击穿？     → 互斥锁 or 逻辑过期 + 预热热品
4. 穿透？     → 布隆 + 空值
5. 大 value？ → Hash 字段拆分；大图 CDN
6. 热 key？   → Caffeine L1
7. 监控？     → 命中率、miss 突增告警
```

**题：Redis 挂了怎么办？**

```
1. 限流降级 → 静态/default
2. 多级缓存 L1 撑部分读
3. Sentinel/Cluster 自动故障转移
4. 持久化恢复 RTO
5. 预热脚本重建热 key
```

## 6. 高频手写题

### 6.1 手写 Lua 解锁

```lua
-- KEYS[1] = lockKey, ARGV[1] = token
if redis.call("GET", KEYS[1]) == ARGV[1] then
    return redis.call("DEL", KEYS[1])
else
    return 0
end
```

### 6.2 手写限流（滑动窗口 ZSet）

```bash
# 每分钟最多 100 次
MULTI
ZREMRANGEBYSCORE rate:{userId} 0 (now-60000)
ZADD rate:{userId} now requestId
ZCARD rate:{userId}
EXPIRE rate:{userId} 120
EXEC
# ZCARD 结果 > 100 则拒绝
```

### 6.3 手写延迟队列

```bash
# 生产: ZADD delay:queue executeTimestamp taskJson
# 消费: ZRANGEBYSCORE delay:queue 0 now LIMIT 0 10
#       处理成功后 ZREM
```

## 7. 对比题速答

| 对比 | 答案要点 |
|------|----------|
| Redis vs MongoDB | Redis 内存 KV 低延迟；Mongo 文档磁盘 灵活查询 |
| Redis vs Kafka | Redis Stream 轻量 MQ；Kafka 高吞吐持久日志 |
| 哨兵 vs Cluster | 哨兵不分片；Cluster 16384 槽水平扩展 |
| LRU vs LFU | 时间 vs 频率；LFU 防刷掉热 key |
| 互斥锁 vs 逻辑过期 | 等待 vs 旧值；热点用逻辑过期 |
| SET NX vs Redisson | 简单 vs 可重入看门狗 |
