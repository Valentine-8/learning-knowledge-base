# 专题复习：消息队列（Kafka · RocketMQ · 可靠性与幂等）

> 对应技能清单 §5.2 MQ 精通。分布式理论见 [Phase6](../phase6-分布式/00-复习手册.md)。

---

## 一、为什么用 MQ

| 价值 | 说明 |
|------|------|
| 异步解耦 | 下单后发消息，库存/积分异步处理 |
| 削峰填谷 | 秒杀流量先写入 MQ，消费者按能力拉 |
| 最终一致 | 本地消息表、事务消息 |
| 广播 | 一条消息多消费者 |

---

## 二、Kafka 核心

| 概念 | 说明 |
|------|------|
| Topic / Partition | 分区并行；**分区内有序** |
| Offset | 消费者位移 |
| Consumer Group | 组内分区负载均衡 |
| ISR | 同步副本集合，leader 选举 |
| 零拷贝 | sendfile 提升吞吐 |

**适用**：日志采集、大数据管道、超高吞吐。

**投递语义**：at-most-once / at-least-once（常见）/ exactly-once（事务）。

---

## 三、RocketMQ 核心

| 概念 | 说明 |
|------|------|
| Topic / Queue | 类似 Kafka 分区 |
| Tag / Key | 消息过滤、顺序消息路由 |
| **事务消息** | 半消息 → 本地事务 → commit/rollback |
| 延迟消息 | 18 个延迟级别 |
| 顺序消息 | 同 MessageQueue 单消费者 |

**适用**：业务消息、电商、事务消息。

---

## 四、通用可靠性（必背）

### 消息丢失

| 环节 | 防护 |
|------|------|
| 生产者 | ack=all / 同步发送 / 重试 |
| Broker | 持久化、多副本同步 |
| 消费者 | **手动 ack**，处理完再提交 offset |

### 重复消费 → 幂等

- 业务唯一键 + DB 唯一索引
- Redis `SETNX` 记录已处理 messageId
- 状态机：只允许合法状态迁移

### 顺序消息

- 同 key 路由到同一分区/Queue
- 单线程消费该分区

### 积压

- 扩容消费者（≤ 分区数）
- 批量消费、降级、临时跳过非核心

---

## 五、Kafka vs RocketMQ

| | Kafka | RocketMQ |
|--|-------|----------|
| 吞吐 | 极高 | 高 |
| 延迟 | 低 | 低 |
| 事务消息 | 事务 API | 原生半消息 |
| 延迟消息 | 较弱 | 内置级别 |
| 生态 | 大数据 | 国内业务 |

**7 年工程师**：至少精通一种，另一种能说清差异。

## 六、与分布式事务

| 方案 | 说明 |
|------|------|
| 本地消息表 | 业务+消息同库事务，定时投递 |
| RocketMQ 事务消息 | 半消息 + 回查 |
| Saga | 长事务 + 补偿 |

---

## 七、面试速答

| 问 | 答 |
|----|-----|
| 如何保证不丢？ | 生产 ack、Broker 持久化多副本、消费手动 commit |
| 如何保证幂等？ | 唯一业务 ID + 去重表/Redis |
| 顺序消息？ | 同 key 同分区 + 单消费者 |
| Kafka 高吞吐原因？ | 顺序写盘、零拷贝、分区并行、批量 |
