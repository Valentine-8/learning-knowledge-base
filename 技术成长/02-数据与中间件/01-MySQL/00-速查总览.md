## 一、InnoDB 核心架构

```
内存：Buffer Pool（数据页/索引页缓存）
磁盘：Redo Log（崩溃恢复）· Undo Log（回滚+MVCC）· Binlog（复制/归档）
```

**更新一行**：改 Buffer Pool → 写 Undo → 写 Redo → 事务提交时 Binlog（两阶段提交）。

## 二、索引（B+ 树）

| 类型 | 说明 |
|------|------|
| 聚簇索引 | 叶子 = 整行，表数据即索引（主键） |
| 二级索引 | 叶子 = 主键值 → **回表** |
| 覆盖索引 | 查询列全在索引，Extra: Using index |
| 联合索引 | **最左前缀**；(a,b,c) 可用 a / ab / abc |
| 索引下推 ICP | 5.6+ 索引层过滤，减回表 |

**失效常见原因**：对列函数/运算、隐式类型转换、like '%x'、or 一侧无索引、违反最左前缀。

## 三、explain 解读

| 列 | 关注 |
|----|------|
| type | system > const > eq_ref > ref > range > index > **ALL** |
| key | 是否走索引 |
| rows | 扫描行数 |
| Extra | Using index 好；Using filesort/temporary 需优化 |

## 四、事务与 MVCC

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|----------|------|------------|------|
| RC | 否 | 可能 | 可能 |
| RR（默认） | 否 | 否 | 快照读无；当前读靠间隙锁 |

- **快照读**：普通 SELECT + Read View
- **当前读**：`FOR UPDATE`、UPDATE、DELETE → 加锁
- **锁**：记录锁、间隙锁 Gap、Next-Key Lock

---

## 五、主从复制与读写分离

```
主库 Binlog → 从库 IO 线程拉取 → Relay Log → SQL 线程重放
```

- **延迟**：从库落后 → 读己之写问题 → 关键读走主库 / 同步复制
- **半同步复制**：至少一个从库 ack 再返回客户端

---

## 六、分库分表

| 方式 | 场景 |
|------|------|
| 垂直拆库 | 业务域分离 |
| 水平分片 | 单表数据量过大，ShardingSphere |
| 分布式 ID | **雪花**（时间+机器+序列）、号段（批量取号） |

**雪花注意**：时钟回拨、workerId 分配。

**跨库难题**：Join → 应用层；分页 → 各库取再归并。

## 七、慢 SQL 治理流程

```
1. 慢查询日志 / APM 发现
2. explain 看 type、rows、Extra
3. 加/改索引、改写 SQL、拆大 SQL
4. 验证执行计划
5. 上线观察
```

**深分页**：`WHERE id > last_id LIMIT n` 优于大 offset。

## 八、面试速答

| 问 | 答 |
|----|-----|
| 为什么用 B+ 树不用 B 树？ | 叶子链表便于范围扫；非叶只存 key，扇出大，树矮 IO 少 |
| RR 如何解决幻读？ | 快照读 MVCC；当前读 Next-Key Lock |
| redo 和 binlog？ | redo InnoDB 物理崩溃恢复；binlog Server 逻辑归档与主从 |
| 如何优化慢查询？ | explain、索引、避免 select *、控制扫描行数 |
