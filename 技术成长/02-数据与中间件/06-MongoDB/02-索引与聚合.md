# 02 · 索引与聚合

> **预计阅读**：60 min · **难度**：★★★★

---

## 1. 索引基础

MongoDB 默认对 `_id` 建唯一索引。其他索引基于 **B-tree**（WiredTiger 引擎）。

```javascript
// 单字段升序
db.users.createIndex({ email: 1 })

// 复合索引
db.orders.createIndex({ userId: 1, createdAt: -1 })

// 唯一索引
db.users.createIndex({ email: 1 }, { unique: true })

// 部分索引（条件索引）
db.orders.createIndex(
  { status: 1 },
  { partialFilterExpression: { status: { $eq: "pending" } } }
)

// TTL 索引：到期自动删除
db.sessions.createIndex({ expireAt: 1 }, { expireAfterSeconds: 0 })
```

---

## 2. 复合索引 ESR 规则

**E**quality（等值）→ **S**ort（排序）→ **R**ange（范围）

```javascript
// 查询：userId=100, status="paid", createdAt 范围 + 按 createdAt 降序
db.orders.createIndex({ userId: 1, status: 1, createdAt: -1 })
```

| 查询条件 | 能否用上索引 |
|----------|-------------|
| `{ userId: 1, status: "paid" }` | ✅ 前缀匹配 |
| `{ userId: 1 }` + sort createdAt | ✅ |
| `{ status: "paid" }`  alone | ❌ 跳过 userId 前缀 |
| `{ userId: 1, amount: { $gt: 100 } }` | ⚠️ amount 范围后无法用于 sort |

**最左前缀原则**与 MySQL 复合索引类似。

## 3. 特殊索引类型

| 类型 | 场景 | 示例 |
|------|------|------|
| 多键索引 | 数组字段 | `{ tags: 1 }` |
| 文本索引 | 全文搜索 | `{ title: "text", body: "text" }` |
| 地理空间 | LBS | `{ location: "2dsphere" }` |
| 哈希索引 | 分片键 | `{ _id: "hashed" }` |
| 稀疏索引 | 字段可选 | `{ sparse: true }` |

```javascript
// 文本搜索
db.articles.createIndex({ title: "text", content: "text" })
db.articles.find({ $text: { $search: "MongoDB 索引" } })

// 2dsphere
db.stores.createIndex({ location: "2dsphere" })
db.stores.find({
  location: {
    $near: {
      $geometry: { type: "Point", coordinates: [116.4, 39.9] },
      $maxDistance: 1000
    }
  }
})
```

## 4. explain 与性能分析

```javascript
db.orders.find({ userId: 100, status: "paid" })
  .sort({ createdAt: -1 })
  .explain("executionStats")
```

| 指标 | 含义 |
|------|------|
| `totalDocsExamined` | 扫描文档数，应接近 nReturned |
| `totalKeysExamined` | 扫描索引键数 |
| `executionTimeMillis` | 执行耗时 |
| `stage: COLLSCAN` | 全表扫描，需加索引 |
| `stage: IXSCAN` | 索引扫描 |
| `stage: FETCH` | 索引定位后回表 |

**优化 checklist**：

1. 避免 COLLSCAN（除小集合）
2. 投影减少 FETCH 字段
3. 覆盖查询：`{ name: 1, _id: 0 }` 且索引含 name
4. 索引过多拖慢写入，定期 `$indexStats` 审查

## 5. 聚合管道（Aggregation Pipeline）

聚合是 MongoDB 分析查询的核心，数据像流水线一样经过各 **Stage** 处理。

```javascript
db.orders.aggregate([
  // 1. 过滤
  { $match: { status: "paid", createdAt: { $gte: ISODate("2026-01-01") } } },

  // 2. 关联（类似 LEFT JOIN）
  { $lookup: {
      from: "users",
      localField: "userId",
      foreignField: "_id",
      as: "user"
  }},
  { $unwind: "$user" },

  // 3. 分组统计
  { $group: {
      _id: "$user.city",
      orderCount: { $sum: 1 },
      totalAmount: { $sum: "$amount" },
      avgAmount: { $avg: "$amount" }
  }},

  // 4. 排序与分页
  { $sort: { totalAmount: -1 } },
  { $limit: 10 },

  // 5. 投影
  { $project: { city: "$_id", orderCount: 1, totalAmount: 1, _id: 0 } }
])
```

---

## 6. 常用 Stage 速查

| Stage | 作用 |
|-------|------|
| `$match` | 过滤，尽量放最前（利用索引） |
| `$project` | 字段投影、计算新字段 |
| `$group` | 分组聚合 |
| `$sort` | 排序 |
| `$limit` / `$skip` | 分页 |
| `$lookup` | 跨集合关联 |
| `$unwind` | 数组展开 |
| `$addFields` | 添加/覆盖字段 |
| `$bucket` | 分桶统计 |
| `$facet` | 多路并行聚合 |
| `$count` | 计数 |

**$group 累加器**：

```javascript
{ $sum: 1 }           // 计数
{ $sum: "$amount" }   // 求和
{ $avg: "$score" }    // 平均
{ $max: "$date" }     // 最大
{ $push: "$item" }    // 收集为数组
{ $addToSet: "$tag" } // 去重收集
```

## 7. $lookup 性能注意

`$lookup` 本质是嵌套循环，大数据量性能差。

| 策略 | 说明 |
|------|------|
| 嵌入设计 | 避免 lookup |
| 冗余字段 | 存常用关联字段 |
| `$lookup` + pipeline | 4.4+ 支持子管道过滤 |
| 应用层组装 | 两次查询 + 内存 join |

```javascript
// 4.4+ 带条件的 lookup
{ $lookup: {
    from: "inventory",
    let: { sku: "$sku" },
    pipeline: [
      { $match: { $expr: { $eq: ["$sku", "$$sku"] } } },
      { $project: { stock: 1 } }
    ],
    as: "inv"
}}
```

---

## 8. 索引与聚合优化

1. **`$match` 前置**：在 `$lookup` 之前过滤，减少数据量。
2. **允许磁盘溢出**：`{ allowDiskUse: true }` 大数据聚合防内存超限。
3. **复合索引覆盖 $match + $sort**：避免内存排序。
4. **物化视图**：`$merge` / `$out` 写结果集，定时预聚合报表。

---

## 9. 小结

| 要点 | 一句话 |
|------|--------|
| 复合索引 | ESR 规则 + 最左前缀 |
| explain | 看 COLLSCAN 和 docsExamined |
| 聚合 | $match 放最前，慎用 $lookup |
| TTL | 会话/日志自动过期的好选择 |
