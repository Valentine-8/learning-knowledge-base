# 05 · 治理、超时、重试与网关

---

## 1. Deadline / 超时

```java
OrderResponse resp = stub
    .withDeadlineAfter(3, TimeUnit.SECONDS)
    .getOrder(request);
```

**规则**：超时从 client 传到 server（剩余时间），server 应检查 `Context.current().isCancelled()`。

与 Spring：

```yaml
grpc:
  client:
    order-service:
      deadline: 5s
```

**链路超时**：Gateway HTTP 10s > Feign 8s > gRPC 5s > DB，逐层递减。

---

## 2. 重试

gRPC 内置有限重试（幂等 RPC）：

```java
Map<String, Object> retryPolicy = new HashMap<>();
retryPolicy.put("maxAttempts", 3.0);
// service config JSON
```

**注意**：

- 仅 **UNAVAILABLE** 等可安全重试
- 非幂等 Unary（CreateOrder）**不要盲重**
- 用 **幂等键** 或改用 MQ

## 4. TLS / mTLS

```yaml
grpc:
  server:
    security:
      enabled: true
      certificate-chain: classpath:certs/server.pem
      private-key: classpath:certs/server.key
  client:
    order-service:
      negotiationType: tls
      trustCertCollection: classpath:certs/ca.pem
```

**mTLS**：双向证书，零信任服务间。

---

## 5. grpc-gateway（REST 转 gRPC）

```
Browser/HTTP → grpc-gateway → gRPC Server
```

`.proto` 加 HTTP 注解（google.api.http）：

```protobuf
import "google/api/annotations.proto";

rpc GetOrder(GetOrderRequest) returns (OrderResponse) {
  option (google.api.http) = {
    get: "/v1/orders/{order_id}"
  };
}
```

**Spring 替代**：Gateway 仍走 HTTP，BFF 调 gRPC；或单独部署 grpc-gateway 容器。
