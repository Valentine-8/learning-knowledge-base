# 专题复习：Elasticsearch（倒排索引 · 写入查询 · 同步）

> 对应技能清单 §5.2 ES 熟练项。搜索场景与 MySQL 分工明确。

---

## 一、核心概念

| 概念 | 说明 |
|------|------|
| Index | 逻辑库（类似 DB） |
| Document | JSON 文档（类似行） |
| Field / Mapping | 字段类型与分析器 |
| Shard | 主分片，水平扩展 |
| Replica | 副本，高可用与读扩展 |

---

## 二、倒排索引

```
正向：文档 ID → 词列表
倒排：词 → 文档 ID 列表（+ 位置、频率）
```

**分词器**：standard、ik（中文）、自定义。

**为什么快**：倒排 + FST 词典 + 缓存；**不适合**复杂事务写。

---

## 三、写入与近实时

```
写入 → 内存 buffer → refresh（默认 1s）→ 可搜
→ flush → 持久化段 segment
```

- **refresh interval** 影响可见延迟
- 段合并影响写入性能

---

## 四、查询类型

| 类型 | 说明 |
|------|------|
| match | 分词后匹配 |
| term | 精确匹配（不分词） |
| bool | must/should/must_not/filter |
| 聚合 aggregation | 桶、指标、类似 GROUP BY |

**评分**：TF-IDF / BM25（默认）。

---

## 五、与 MySQL 分工

| MySQL | ES |
|-------|-----|
| 事务、强一致写 | 搜索、日志、聚合 |
| 精确 CRUD | 全文、模糊、复杂筛选 |

**同步方案**：
- **Canal** 监听 binlog → MQ → ES 消费者
- 双写（不推荐，一致性难）
- 定时全量/增量

---

## 六、生产注意

- 映射 Mapping 上线后改字段类型难 → 提前设计
- 深分页：`search_after` 优于大 `from/size`
- 集群脑裂、分片数规划（扩容后难改）
- 别当主库存业务数据

---

## 七、面试速答

| 问 | 答 |
|----|-----|
| 倒排索引是什么？ | 词到文档 ID 的映射，支持全文检索 |
| ES 和 MySQL？ | MySQL 事务写；ES 搜索分析，最终一致同步 |
| 如何保证数据同步？ | Canal binlog → MQ → 写 ES |
| 为什么近实时？ | refresh 周期默认 1s 才可见 |
