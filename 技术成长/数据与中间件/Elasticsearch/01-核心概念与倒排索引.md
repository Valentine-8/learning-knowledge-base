# 01 · 核心概念与倒排索引

> **目标**：理解 Elasticsearch 核心概念、Mapping 与分析器、倒排索引底层原理，建立搜索场景的技术直觉。

---

## 一、Elasticsearch 是什么

Elasticsearch（ES）是基于 **Apache Lucene** 的分布式搜索与分析引擎，特点：

| 特点 | 说明 |
|------|------|
| 全文检索 | 倒排索引，毫秒级关键词搜索 |
| 分布式 | 分片水平扩展，副本高可用 |
| 近实时 | 写入后约 1s 可搜（可配置） |
| Schema-on-read | 动态 Mapping，灵活但需规划 |
| RESTful API | JSON 请求，生态丰富 |

**定位**：搜索、日志分析、指标聚合的 **读模型**；**不是**关系型数据库替代品。

## 二、核心概念映射

### 2.1 与关系型数据库对比

| 关系型 DB | Elasticsearch | 说明 |
|-----------|---------------|------|
| Database | Index（7.x+）/ 多 Index | 逻辑命名空间 |
| Table | **Document Type 已废弃**，单 Index 多字段 | 7.x 起 _type 移除 |
| Row | Document | JSON 文档 |
| Column | Field | 字段 |
| Schema | Mapping | 字段类型与分析器 |
| Index（索引） | 倒排索引 Inverted Index | 概念同名不同义 |
| Partition | **Shard 主分片** | 水平切分 |
| Replica | Replica Shard | 副本 |

### 2.2 集群层级结构

```
Cluster（集群，唯一名字）
  └── Node（节点：Master / Data / Coordinating / Ingest）
        └── Index（索引，如 products）
              └── Shard（分片）
                    ├── Primary Shard（主分片，写入口）
                    └── Replica Shard（副本，读扩展 + HA）
```

### 2.3 Document 与 _id

```json
PUT /products/_doc/1001
{
  "title": "无线蓝牙耳机",
  "price": 299,
  "category": "electronics",
  "tags": ["蓝牙", "降噪"],
  "created_at": "2025-06-01T10:00:00"
}
```

| 元字段 | 含义 |
|--------|------|
| `_index` | 所属 Index |
| `_id` | 文档唯一标识（可指定或自动生成） |
| `_source` | 原始 JSON |
| `_score` | 查询相关性得分（仅 search） |

### 2.4 Index、Shard、Replica

| 概念 | 说明 |
|------|------|
| **Primary Shard** | 创建 Index 时指定数量（默认 5/1），**创建后不可改** |
| **Replica Shard** | 主分片副本，默认 1，可动态调整 |
| **Routing** | 默认 `hash(_id) % num_primary_shards` 决定文档所在分片 |

**分片数规划**：
- 单分片建议 10GB~50GB
- 过多分片 → 集群元数据压力、查询 fan-out
- 过少 → 无法水平扩展

## 三、Mapping 映射

### 3.1 什么是 Mapping

Mapping 定义字段 **类型**、**是否索引**、**分词器**、**格式** 等，类似表结构。

```json
PUT /products
{
  "mappings": {
    "properties": {
      "title": {
        "type": "text",
        "analyzer": "ik_max_word",
        "search_analyzer": "ik_smart"
      },
      "price": { "type": "double" },
      "sku": { "type": "keyword" },
      "created_at": { "type": "date", "format": "yyyy-MM-dd HH:mm:ss||epoch_millis" }
    }
  }
}
```

### 3.2 核心字段类型

| 类型 | 用途 | 是否分词 |
|------|------|----------|
| **text** | 全文检索 | 是 |
| **keyword** | 精确匹配、聚合、排序 | 否 |
| **long/integer/double** | 数值 | - |
| **date** | 日期 | - |
| **boolean** | 布尔 | - |
| **object** | 嵌套 JSON | - |
| **nested** | 数组对象独立索引 | 特殊 |
| **geo_point** | 地理坐标 | - |

**text vs keyword**：
- 同一字段常需两种用途 → `fields` 多字段：

```json
"title": {
  "type": "text",
  "fields": {
    "keyword": { "type": "keyword", "ignore_above": 256 }
  }
}
```

### 3.3 dynamic mapping

- **true**（默认）：新字段自动添加
- **false**：忽略新字段，仍存储 _source
- **strict**：拒绝未知字段

**生产建议**：核心 Index 用 **显式 Mapping + strict 或 false**，避免类型漂移。

### 3.4 Mapping 变更限制

| 操作 | 可否 |
|------|------|
| 新增字段 | ✅ |
| 改 analyzer | ❌ 需 reindex |
| text ↔ keyword | ❌ 需 reindex |
| 增删字段 sub-field | 部分可以 |

**Reindex 流程**：新建 Index → _reindex API → 别名切换。

## 四、分析器（Analyzer）

### 4.1 三组件

```
文本 → Character Filter → Tokenizer → Token Filter → Terms
         (字符过滤)        (分词)        (词项过滤)
```

| 组件 | 示例 |
|------|------|
| Character Filter | HTML strip、映射字符 |
| Tokenizer | standard、ik_max_word |
| Token Filter | lowercase、stop、synonym |

### 4.2 内置分析器

| 分析器 | 说明 |
|--------|------|
| **standard** | 按 Unicode 文本算法分词，小写 |
| **simple** | 非字母分割 |
| **whitespace** | 空格分割 |
| **keyword** | 不分词，整体一个 term |
| **language** | english、french 等，含词干提取 |

### 4.3 中文分词：IK

| 分析器 | 说明 |
|--------|------|
| **ik_max_word** | 最细粒度（索引时用） |
| **ik_smart** | 最粗粒度（搜索时用） |

```
"中华人民共和国" 
  ik_max_word: 中华人民共和国, 中华, 华人, 人民, 共和国, ...
  ik_smart: 中华人民共和国
```

### 4.4 自定义分析器

```json
"settings": {
  "analysis": {
    "analyzer": {
      "my_analyzer": {
        "type": "custom",
        "tokenizer": "standard",
        "filter": ["lowercase", "stop"]
      }
    }
  }
}
```

### 4.5 search_analyzer vs analyzer

- **analyzer**：索引时使用（写入）
- **search_analyzer**：查询时使用（可不同，如索引 ik_max_word，搜索 ik_smart）

## 五、倒排索引原理

### 5.1 正排 vs 倒排

**正排索引（Forward Index）**：
```
Doc1 → [无线, 蓝牙, 耳机]
Doc2 → [有线, 耳机]
```

**倒排索引（Inverted Index）**：
```
无线  → [Doc1]
蓝牙  → [Doc1]
耳机  → [Doc1, Doc2]
有线  → [Doc2]
```

搜索「耳机」→ 查倒排表得 Doc1、Doc2 → 取文档。**关键词 → 文档 ID**，O(1) 定位。

### 5.2 倒排索引结构

每个 Term 对应一个 **Posting List**：

```
Term "耳机":
  DocId: 1, Freq: 1, Positions: [2]
  DocId: 2, Freq: 1, Positions: [1]
```

| 信息 | 用途 |
|------|------|
| DocId | 文档标识 |
| Term Freq (TF) | 词在文档中出现次数 → 相关性 |
| Positions | 词在文档中的位置 → 短语查询 |
| Offsets | 字符偏移 → 高亮 |

### 5.3 Term Dictionary 与 Posting List

Lucene 索引文件：

| 结构 | 说明 |
|------|------|
| **Term Dictionary** | 所有 Term 的有序词典 |
| **Posting List** | 每个 Term 的倒排列表 |
| **FST (Finite State Transducer)** | 内存中 Term 词典前缀树，快速 lookup |
| **Skip List** | Posting List 跳表，加速 AND 合并 |

**FST 优势**：前缀查询、模糊查询高效；内存占用小。

### 5.4 段（Segment）

- 写入先内存 buffer → refresh 生成新 **Segment**（只读）
- 多个 Segment 共存 → 后台 **Merge** 合并大 Segment
- Segment 内文档不可变（update = delete + insert）

```
Index
  Segment_1  [term → postings]
  Segment_2
  Segment_3
  → 查询时合并各 Segment 结果
```

## 六、Doc Values 与列存

### 6.1 为什么需要 Doc Values

倒排索引适合 **按词找文档**；**排序、聚合、脚本** 需要 **按文档找字段值**。

**Doc Values**：列式存储，磁盘上按字段、按 DocId 顺序存储，用于：
- sort
- aggregation
- script 访问字段

### 6.2 fielddata（已过时）

text 字段默认无 doc values；旧版用 fielddata 加载到堆内存 → **OOM 风险**。
**现代做法**：聚合/排序用 **keyword** 子字段。

## 七、写入路径概览（为第二章铺垫）

```
Client → Coordinating Node
           → Primary Shard（写）
           → Replica Shard（复制）
           → refresh（默认 1s）→ 可搜索
           → flush → 持久化 translog + commit segment
```

详见 [02-写入查询与聚合](./02-写入查询与聚合.md)。

## 八、节点角色

| 角色 | 职责 |
|------|------|
| **Master-eligible** | 集群状态、Index 创建、分片分配 |
| **Data** | 存储分片、CRUD |
| **Coordinating** | 路由请求、合并结果（默认所有节点都可协调） |
| **Ingest** | 预处理 Pipeline |

**生产建议**：
- 专用 Master 节点（3 个，不存数据）
- Data 节点按磁盘/内存扩展
- 大集群分离 Coordinating（可选）

## 九、别名（Alias）

```json
POST /_aliases
{
  "actions": [
    { "add": { "index": "products_v2", "alias": "products" } },
    { "remove": { "index": "products_v1", "alias": "products" } }
  ]
}
```

**用途**：
- 零停机 Reindex 切换
- 一个别名指向多个 Index（写别名需唯一 Index）

## 十、ES 与 Lucene 关系

| ES | Lucene |
|----|--------|
| 分布式、REST、集群管理 | 单机搜索引擎库 |
| Shard = Lucene Index 实例 | 底层索引引擎 |
| 一个 ES Shard 对应一个 Lucene Index | - |

---

## 十一、不适用场景

| 场景 | 原因 |
|------|------|
| 主业务事务库 | 无 ACID 跨文档事务 |
| 频繁更新 | 删+写，段合并开销 |
| 精确金融记账 | 最终一致，非强一致 |
| 小数据量简单 CRUD | MySQL 更简单 |

**正确分工**：MySQL 写 + ES 搜，通过 MQ/CDC 同步。

---

## 十二、生产 Mapping 设计原则

1. **提前设计**：字段类型、analyzer、是否需要 keyword 子字段
2. **禁用不需要搜索的字段**：`"index": false` 或 `"enabled": false`
3. **避免动态 text 泛滥**：控制 dynamic
4. **nested 代替 object**：数组对象需独立查询时用 nested
5. **ignore_above**：keyword 过长截断
6. **版本升级**：关注 breaking changes（7→8 等）

---

## 十三、常见问题

| 问题 | 原因 | 处理 |
|------|------|------|
| 搜不到刚写入的数据 | 未 refresh | 等待或 `refresh=wait_for` |
| 聚合内存 OOM | text 字段 fielddata | 改 keyword 子字段 |
| 中文分词不准 | 未用 IK | 安装 IK 插件 |
| Mapping 冲突 | 动态映射类型不一致 | strict + 显式 Mapping |

## 十五、Lucene 底层文件结构

### 15.1 核心文件类型

| 文件 | 说明 |
|------|------|
| **segments_N** | 段信息清单 |
| **_0.si** | Segment Info |
| **_0.cfs/cfe** | 复合文件（可选） |
| **_0.tim / .tip** | Term Dictionary + Index |
| **_0.doc** | Posting List（倒排） |
| **_0.dvd / .dvm** | Doc Values |
| **_0.fnm / .fdt / .fdx** | 存储字段（Stored Fields） |
| **_0.nvd / .nvm** | Norms（评分归一化因子） |

### 15.2 查询执行路径

```
1. Term Dictionary（FST）定位 Term
2. 读取 Posting List 得 DocId 集合
3. 多 Term 求交集/并集（Skip List 加速）
4. 按 Norms + TF 算 BM25 分
5. 从 Stored Fields / _source 取文档
6. 合并多 Segment 结果，Top N 堆排序
```

---

## 十六、评分因子 Norms

- **Norms**：文档长度归一化因子，编码为单字节，与 DocId 一起存储
- BM25 的 `b` 参数控制长度惩罚强度
- 禁用 Norms：`"norms": false` 节省空间，但评分不准

## 十七、同义词与停用词

### 17.1 Synonym Filter

```json
"filter": {
  "synonym_filter": {
    "type": "synonym",
    "synonyms": [
      "手机, 移动电话, 智能手机",
      "cpu, 中央处理器"
    ]
  }
}
```

**注意**：索引与搜索需一致；expand 模式影响索引大小。

### 17.2 Stop Words

```json
"filter": {
  "stop_filter": {
    "type": "stop",
    "stopwords": "_chinese_" 
  }
}
```

中文停用词需谨慎，「的」去掉可能改变语义。

## 十八、字段类型进阶

### 18.1 dense_vector

```json
"embedding": {
  "type": "dense_vector",
  "dims": 768,
  "index": true,
  "similarity": "cosine"
}
```

**用途**：语义搜索、KNN（k 近邻），8.x 原生向量检索。

### 18.2 flattened

```json
"metadata": { "type": "flattened" }
```

整个 JSON 对象作为一组 searchable terms，适合动态 schema。

### 18.3 join 类型（了解）

`join` 类型实现 parent-child，查询用 `has_child`/`has_parent`，性能低于 nested 或宽表。
