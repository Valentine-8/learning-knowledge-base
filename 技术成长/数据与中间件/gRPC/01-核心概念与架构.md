# 01 · 核心概念与架构

> **预计阅读**：50 min · **难度**：★★★★

---

## 1. RPC 是什么

**RPC（Remote Procedure Call）**：像调本地方法一样调远程服务。

```java
// 本地
Order order = orderService.getOrder(1L);

// RPC 抽象（底层走网络）
Order order = orderStub.getOrder(GetOrderRequest.newBuilder().setOrderId(1).build());
```

| 层次 | REST | gRPC |
|------|------|------|
| 调用方式 | HTTP + 路径 | 方法名 + Protobuf |
| 接口描述 | OpenAPI YAML | .proto |
| 代码生成 | 可选 | **标准流程** |

---

## 2. HTTP/2 为何重要

| 特性 | 收益 |
|------|------|
| 多路复用 | 单连接并发多 RPC，无 HOL 阻塞 |
| 头部压缩 HPACK | 减开销 |
| 二进制帧 | 解析高效 |
| 流控 | 背压基础 |

gRPC **强制 HTTP/2**（明文 h2c 或 TLS h2）。

---

## 3. 核心组件

```
┌──────────────────────────────────────┐
│ Channel（连接抽象，负载均衡、TLS）      │
│   └── Stub（客户端代理）               │
│         └── 调用 RPC 方法              │
└──────────────────────────────────────┘
              │
              ▼ HTTP/2
┌──────────────────────────────────────┐
│ Server（Netty 等）                    │
│   └── Service 实现（你的业务代码）      │
│   └── ServerInterceptor（鉴权、日志）  │
└──────────────────────────────────────┘
```

| 概念 | 说明 |
|------|------|
| **Channel** | 长连接池，可 LB |
| **Stub** | Blocking / Async / Future |
| **Metadata** | 类似 HTTP Header，传 token、traceId |
| **Status** | 标准错误码 + message + trailers |

---

## 4. Protobuf 在链路中的位置

```
.proto 文件
  → protoc 编译器 + grpc-java 插件
  → OrderServiceGrpc.OrderServiceImplBase（服务端）
  → OrderServiceGrpc.OrderServiceBlockingStub（客户端）
  → 二进制 on wire
```

---

## 5. 状态码（Status Code）

| Code | 含义 | 类比 HTTP |
|------|------|-----------|
| OK | 成功 | 200 |
| INVALID_ARGUMENT | 参数错 | 400 |
| NOT_FOUND | 不存在 | 404 |
| DEADLINE_EXCEEDED | 超时 | 504 |
| UNAVAILABLE | 服务不可用 | 503 |
| INTERNAL | 内部错误 | 500 |

```java
responseObserver.onError(
    Status.NOT_FOUND.withDescription("order not found").asRuntimeException());
```

---

## 6. 与 Dubbo 对比（面试）

| | gRPC | Dubbo |
|---|------|-------|
| 归属 | CNCF / Google | Apache / 阿里 |
| 协议 | HTTP/2 | 自有 TCP/HTTP |
| 多语言 | **强** | 以 Java 为主 |
| 注册中心 | 需外接（Nacos/etcd） | 内置丰富 |
| 国内 | 云原生、跨语言 | Java 微服务传统 |

---

## 7. 何时不用 gRPC

- 公开 HTTP API、移动端 H5
- 需要浏览器直连（用 REST 或 grpc-web + Envoy）
- 团队无 .proto 契约治理
- 简单 CRUD，REST 足够
