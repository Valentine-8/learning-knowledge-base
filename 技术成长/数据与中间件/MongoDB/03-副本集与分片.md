# 03 · 副本集与分片

> **预计阅读**：50 min · **难度**：★★★★

---

## 1. 副本集（Replica Set）

副本集是一组维护相同数据的 MongoDB 节点，提供 **高可用** 和 **读扩展**。

```
                ┌─────────────┐
                │   Primary   │ ◄── 默认读写
                └──────┬──────┘
           复制       │       复制
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
   Secondary     Secondary      Arbiter（可选）
   （可读）       （可读）        （仅投票）
```

| 角色 | 说明 |
|------|------|
| Primary | 接收所有写操作，写 oplog |
| Secondary | 异步拉取 oplog 重放 |
| Arbiter | 不存数据，仅参与选举投票 |
| Hidden | 对客户端不可见，备份/报表用 |
| Delayed | 延迟 N 秒复制，误删恢复 |

**最少配置**：1 Primary + 2 Secondary（或 1S + 1A）= 3 投票成员。

---

## 2. 选举机制

Primary 不可达时，Secondary 发起 **Raft 类选举**：

| 条件 | 说明 |
|------|------|
| 多数派 | 存活节点 ≥ (总数/2)+1 才能选主 |
| 优先级 | `priority` 高的优先成为 Primary |
| 版本号 | term 递增，防止脑裂 |
| 心跳 | 默认 2s 心跳，10s 超时 |

**常见无法选举**：

- 网络分区导致少数派
- 所有节点 priority=0（无法成为 Primary）
- 复制延迟过大节点被否决

## 3. 写关注与读关注

### writeConcern

```javascript
db.orders.insertOne(
  { ... },
  { writeConcern: { w: "majority", j: true, wtimeout: 5000 } }
)
```

| 参数 | 含义 |
|------|------|
| `w: 1` | 主节点确认（默认，可能丢） |
| `w: "majority"` | 多数副本确认，防故障丢写 |
| `j: true` | 写 journal 落盘 |
| `wtimeout` | 超时毫秒 |

### readConcern

| 级别 | 说明 |
|------|------|
| `local` | 读本地最新（默认） |
| `majority` | 读已多数确认的数据 |
| `snapshot` | 事务内一致性快照 |

### readPreference

```java
// Java 读偏好
ReadPreference.secondaryPreferred()  // 优先从节点，主节点兜底
```

| 模式 | 场景 |
|------|------|
| primary | 默认，强一致读 |
| secondary | 只读从节点 |
| secondaryPreferred | 读写分离 |
| nearest | 延迟最低节点 |

---

## 4. Oplog

**Oplog**（操作日志）是 capped collection，记录所有写操作，Secondary 通过 **tailable cursor** 拉取重放。

| 注意 | 说明 |
|------|------|
| 窗口大小 | oplog 太小 + 从节点长时间离线 → 需全量 resync |
| 写放大 | 大量写操作占满 oplog |
| 监控 | `rs.printReplicationInfo()` 查看窗口 |

## 5. 分片集群（Sharded Cluster）

数据量超过单机能力时，使用分片水平扩展。

```
Client
   │
   ▼
mongos × N（路由，无状态）
   │
   ├── Config Servers（元数据：chunk 分布、分片键）
   │
   ├── Shard 1（Replica Set）
   ├── Shard 2（Replica Set）
   └── Shard 3（Replica Set）
```

| 组件 | 作用 |
|------|------|
| mongos | 解析查询，路由到目标 shard |
| Config Server | 存储集群元数据 |
| Shard | 每个 shard 本身是副本集 |

---

## 6. 分片键选择

分片键 **创建后不可修改**，是架构最关键决策。

| 策略 | 特点 |
|------|------|
| 范围分片 | 相邻键在同一 chunk，范围查询高效 |
| 哈希分片 | `{ _id: "hashed" }` 打散写入，范围查需 scatter-gather |

**好分片键特征**：

1. **高基数**：值分布广（如 userId、orderId）
2. **低频率**：避免单调递增（如时间戳 alone → 热点写）
3. **查询覆盖**：常用查询带分片键

**复合分片键示例**：

```javascript
sh.shardCollection("shop.orders", { userId: 1, createdAt: 1 })
// userId 打散 + createdAt 支持范围
```

**坏例子**：`{ createdAt: 1 }` → 所有新写入打到一个 chunk → 热点。

---

## 7. Chunk 与平衡

| 概念 | 说明 |
|------|------|
| Chunk | 数据块，默认 64MB～128MB |
| Split | chunk 过大时自动拆分 |
| Migration | balancer 在 shard 间迁移 chunk |
| Jumbo Chunk | 无法拆分的大 chunk，阻塞平衡 |

**jumbo chunk 处理**：调整分片键设计、手动 split、或 `$mergeChunks`（运维操作）。

---

## 8. 部署建议

| 场景 | 配置 |
|------|------|
| 开发 | 单节点或 3 节点副本集 |
| 生产 | 3 节点副本集，跨 AZ 部署 |
| 大集群 | 3 Config + N mongos + M×3 Shard |
| 备份 | mongodump / 云快照 / Hidden Secondary |

**Java 连接串**：

```
mongodb://host1:27017,host2:27017,host3:27017/mydb?replicaSet=rs0&w=majority
```

---

## 9. 小结

| 要点 | 一句话 |
|------|--------|
| 副本集 | 3 节点 + writeConcern majority |
| 选举 | 多数派存活才能选主 |
| 分片键 | 高基数、防单调热点、不可改 |
| 读写分离 | readPreference + 接受最终一致 |
