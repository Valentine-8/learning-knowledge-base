# 02 · 索引与执行计划

> **预计阅读**：60 min · **难度**：★★★★

---

## 1. 索引类型

| 类型 | 场景 | 命令 |
|------|------|------|
| **B-tree** | 等值、范围、排序（默认） | `CREATE INDEX idx ON t(col)` |
| **Hash** | 仅等值（少用） | `USING hash` |
| **GIN** | JSONB、数组、全文 | `USING gin` |
| **GiST** | 几何、全文、范围 | `USING gist` |
| **BRIN** | 超大表、物理有序 | 时序数据 |

```sql
-- 联合索引
CREATE INDEX idx_user_status_created ON orders(user_id, status, created_at DESC);

-- 部分索引（条件索引）
CREATE INDEX idx_active ON users(email) WHERE deleted = false;

-- 表达式索引
CREATE INDEX idx_lower_email ON users(lower(email));
```

---

## 2. EXPLAIN ANALYZE

```sql
EXPLAIN (ANALYZE, BUFFERS, VERBOSE)
SELECT * FROM orders
WHERE user_id = 100 AND status = 1
ORDER BY created_at DESC
LIMIT 20;
```

| 字段 | 含义 |
|------|------|
| actual time | 实际耗时 ms |
| rows | 估计 vs 实际行数（偏差大要 ANALYZE） |
| Buffers: shared hit/read | 缓存命中 vs 磁盘读 |
| Planning Time | 规划时间 |

**Seq Scan 不一定坏**：小表或大部分行命中时优化器选全表。

---

## 3. 最左前缀与多列

B-tree 联合索引 `(a,b,c)`：

```sql
WHERE a = 1 AND b = 2           -- 好
WHERE a = 1 AND b > 2 AND c = 3 -- a,b 用索引，c 可能 filter
WHERE b = 2                     -- 不能用 a 前缀
```

---

## 4. 覆盖索引（Index Only Scan）

索引含查询全部列 + **Visibility Map** 确认可见性 → 不回表。

```sql
CREATE INDEX idx_cover ON orders(user_id, status) INCLUDE (amount, created_at);
```

---

## 5. JOIN 方式

| 节点 | 适用 |
|------|------|
| Nested Loop | 小表驱动大表，有索引 |
| Hash Join | 等值连接，一侧可放内存 work_mem |
| Merge Join | 两侧已排序 |

---

## 6. 慢 SQL 治理

1. `pg_stat_statements` 扩展统计 Top SQL
2. EXPLAIN ANALYZE
3. 缺索引 / 统计过期 → CREATE INDEX / ANALYZE
4. 深分页改 **keyset pagination**：

```sql
-- 差：OFFSET 100000
SELECT * FROM orders ORDER BY id LIMIT 20 OFFSET 100000;

-- 好：游标
SELECT * FROM orders WHERE id > 100000 ORDER BY id LIMIT 20;
```

---

## 7. 与 MySQL EXPLAIN 对照

| MySQL | PostgreSQL |
|-------|------------|
| type: ref/range | Index Scan |
| Extra: Using index | Index Only Scan |
| filesort | Sort 节点 |
| EXPLAIN | EXPLAIN (ANALYZE) 才有真实耗时 |
