# AI 时代程序员与代码的关系

> **定位**：回答「还要不要认真看代码、每一行都要 Review 吗」——以及日常怎么用 AI 而不踩坑。  
> **配套**：[AI时代开发者技能与概念手册.md](./AI时代开发者技能与概念手册.md) 讲能力地图；本文讲 **工作方式**。

---

## 一、关系变了什么、没变什么

### 1.1 变了的：代码的生产方式

| 以前 | AI 时代 |
|------|---------|
| 程序员 **主要时间** 在敲代码 | 大量 **样板代码** 由 AI 生成 |
| 会写 = 会实现 | 会写 ≠ 稀缺；**会判断对错** 更稀缺 |
| 读源码靠慢慢啃 | 读源码 = AI 解释 + **你抽样验证** |
| CRUD 是基本功展示 | CRUD 是 **交付手段**，不是核心价值 |

**代码从「纯手工工艺品」变成「可快速复制的中间产物」。**  
就像有了 CAD，建筑师仍要对结构安全负责，但不会手画每一根钢筋。

### 1.2 没变的：你对结果负责

| 不变项 | 说明 |
|--------|------|
| **上线签字** | 合并进主分支、发布生产的责任人是你，不是 Cursor |
| **业务正确性** | AI 不懂你们公司的 orgId、返佣规则、人社部调配政策 |
| **安全与合规** | 注入、越权、密钥泄露、PII 日志——AI 经常「看起来对」 |
| **线上排障** | 3 点告警时，要能 **定位** 和 **讲清楚**，不能只会重新 Generate |

### 1.3 新的关系模型（建议内化）

```
        ┌─────────────┐
        │  你（工程师）  │  ← 意图、边界、验收、担责
        └──────┬──────┘
               │ 设计 / Prompt / Review / 测试
               ▼
        ┌─────────────┐
        │  AI（执行层） │  ← 生成、改写、解释、搜模式
        └──────┬──────┘
               │ diff / 代码 / 文档
               ▼
        ┌─────────────┐
        │    代码      │  ← 可丢弃、可重写；不是身份象征
        └──────┬──────┘
               │ 编译 / 测试 / 运行
               ▼
        ┌─────────────┐
        │  可运行的系统  │  ← 真正交付物
        └─────────────┘
```

**程序员和代码的关系**：从「我写的每一行都是我的作品」→ **「我负责让系统在对的约束下正确运行；代码是达成目标的媒介，且越来越常由 AI 起草」。**

## 二、还要不要「认真看代码」？

### 要，但看的是「理解 + 风险」，不是「背诵」

| 深度 | 适用场景 |
|------|----------|
| **精读** | 鉴权、多租户、钱/库存、事务、并发、SQL、对外 API |
| **读懂 diff + 测通** | 普通业务分支、新接口、和现有风格是否一致 |
| **扫 diff + 编译/测试** | DTO、重复 CRUD、文档、简单配置 |

**错误做法**

- ❌ 整包 Accept，从不看 diff  
- ❌ 每一行 generated 代码都当面试题背  
- ❌ 完全不看，只靠「AI 说应该没问题」  

**正确做法**

- ✅ **每个 PR / 每次 Agent 结束：过一遍 diff**  
- ✅ **高风险路径：能用自己的话讲清楚逻辑和边界**  
- ✅ **关键模块：跑测试 + 手测主流程**  

一句话：**不是「看每一行」，是「对每一类风险做到足够深度的理解」。**

## 三、你的时间应该花在哪（7 年工程师）

AI 省下来的时间，建议 **挪到** 这些高杠杆活动，而不是刷更多 prompt：

| 优先级 | 活动 | 为什么 |
|:------:|------|--------|
| P0 | **需求与边界** | 问错问题，AI 写得越快错得越快 |
| P0 | **架构与数据模型** | 租户隔离、表设计、API 契约——AI 易幻觉 |
| P1 | **Review 高风险 diff** | 见下文检查清单 |
| P1 | **测试与验证** | 假绿比没测试更危险 |
| P2 | **读 legacy / 调用链** | CloudCC 这种 monolith，AI 需要你对上下文 |
| P2 | **让 AI 写样板** | CRUD、DTO、单测骨架、文档初稿 |
| P3 | **手敲重复代码** | 除非练手或面试，否则性价比低 |

对你当前经历的具体映射：

| 项目 | 你应「人脑持有」的部分 | 可交给 AI 起草的部分 |
|------|------------------------|----------------------|
| FollowUpAI | 租户 DB 隔离、鉴权、Widget CORS | CRUD、前端组件样板 |
| CloudCC 服务云 | 业务规则、多租户 org、移动端兼容 | 类似 Controller 的重复结构 |
| Setup 菜单树 | Profile/权限/递归树逻辑 | 日志、部分 boilerplate |
| mall（若依） | RAG 链路、库存扣减、客服状态机 | 若依已有模块的小改 |
| 人社部项目 | 调配政策对应的规则分支 | 报表、简单表单（当年） |

## 四、AI 代码 Review 工作流（标准动作）

每次 AI 改完代码，按 **5 步** 走（ habit 化后可 5～15 分钟）：

```
1. 看 diff 范围     → 有没有动到不该动的文件？
2. 过检查清单       → 见第五节（1 分钟版 / 5 分钟版）
3. 编译 + 测试      → 至少相关模块；关键路径手测
4. 口述一遍         → 「改了啥、边界 case、回滚方式」
5. 再 Accept / Commit
```

**Agent 跨多文件时**：先看 **删了啥**，再看 **新增依赖/配置**。

## 五、Review 检查清单

### 5.1 一分钟版（Accept 前扫一眼）

打印或 Pin 在 IDE 旁：

- [ ] 我 **看过 diff**，不是整包 Accept  
- [ ] 没有 **硬编码密钥、密码、Token**  
- [ ] 没有 **吞异常 / 空 catch**  
- [ ] SQL 用 **参数绑定**，不是字符串拼接  
- [ ] 鉴权 / 租户 / orgId **没被 AI 删掉或绕过**  
- [ ] 没 **编造** 不存在的类、方法、依赖版本（import 能解析）  
- [ ] **跑过** 编译或相关测试  

> 任一项不确定 → 升级到 **5 分钟版** 或 **精读**。

### 5.2 五分钟版（业务 / 接口改动）

**安全**

- [ ] 入参校验（长度、类型、权限）  
- [ ] 日志无手机号、身份证、Token 明文  
- [ ] 文件上传 / OpenCall 类接口无路径遍历  

**正确性**

- [ ] 事务边界对（多表写是否同一事务）  
- [ ] 并发：库存、计佣、订单是否幂等 / 乐观锁  
- [ ] 空指针：Optional、集合 empty、RPC 返回 null  
- [ ] i18n / 多租户：label、org 隔离是否仍成立  

**可维护性**

- [ ] 没有 **过度抽象**（AI 爱抽 3 层接口只用一个实现）  
- [ ] 没有 **重复代码** 复制粘贴一整块  
- [ ] 风格和 **周围文件** 一致（命名、ResponseInfo 等）  

**AI 特有问题**

- [ ] 是否用了 **已废弃** 的 API（Spring Boot 2/3、Java 版本）  
- [ ] 测试是否 **Mock 过度** 导致假绿  
- [ ] 注释/文档是否 **编造** 了不存在的配置项  

### 5.3 必须精读（建议自己写或逐行看）

出现以下任一情况，**不要** 只跑一键 Accept：

1. 登录、Session、JWT、站点 Token（getSiteToken）  
2. 多租户路由、DB 切换、Profile 权限  
3. 支付、退款、库存、返佣、对账  
4. 定时任务、MQ 消费、幂等键  
5. legacy 核心 Service 超过 50 行改动  
6. 安全相关：XSS/SQL 过滤、加密、CORS

## 六、AI 常犯的 8 类问题（对照 [AI 手册 1.3](./AI时代开发者技能与概念手册.md)）

| # | 问题 | 典型后果 |
|---|------|----------|
| 1 | 编造不存在的方法/类/依赖 | 编译不过或运行时 ClassNotFound |
| 2 | 错误的事务与并发 | 脏数据、重复计佣、超卖 |
| 3 | 吞异常 | 线上 silent failure |
| 4 | N+1、缺索引 | 慢 SQL、审批超时 |
| 5 | 硬编码配置与密钥 | 安全事件 |
| 6 | 测试 Mock 过度 | CI 绿、生产挂 |
| 7 | 忽略幂等与防重 | 重复提交、双扣款 |
| 8 | 日志打敏感字段 | 合规风险 |

## 七、和「还要不要学底层」的关系

AI 时代 **更需要** 有层次的底层理解，但 **不需要** 背每一行 JDK 源码：

| 需要理解到… | 不需要… |
|-------------|---------|
| HashMap / 并发容器 **选型与坑** | 背每个位运算细节 |
| JVM **OOM/GC 排查路径** | 手算 GC 公式 |
| Spring **事务失效、循环依赖** | 背 BeanFactory 全类图 |
| MySQL **索引、MVCC、慢 SQL** | 背 InnoDB 每页结构 |
| 分布式 **幂等、消息至少一次** | 手推 Raft 每一轮 |

**目的**：Review AI 代码时能 **识别胡说**，排障时能 **缩小范围**——不是和 AI 比谁背得多。

## 八、心态建议（避免两个极端）

| 极端 | 问题 | 调整 |
|------|------|------|
| **AI 依赖症** | 不思考就 Accept，出了事不会查 | 强制 diff + 清单 + 测试 |
| **AI 排斥症** | 一切手敲，交付慢 | 样板交给 AI，精力放在 P0/P1 |
| **代码崇拜** | 以「写了多少行」衡量成长 | 以 **系统结果、业务影响** 衡量 |
| **代码虚无** | 完全不看，当黑盒 | 高风险必须能 **画调用链** |

**健康目标**：你是 **Tech Lead of your own AI**，不是 AI 的打字员，也不是拒绝工具的 Luddite。

## 九、每周自检（3 个问题）

周日复盘时可加在 [周复盘模板.md](../00-通用/周复盘模板.md) 里：

1. 本周 Accept 的 AI 代码里，有没有 **没看 diff** 就合并的？  
2. 有没有 **能讲清楚** 的模块，和 **其实说不清** 的模块？（后者优先补理解）  
3. 省下的时间是否用在 **架构/测试/legacy 阅读**，还是只刷了更多 prompt？
