# 工程素养 · 速查

> 10 分钟复习。深入见 [01～05 章](./README.md)。

---

## 1. Code Review 四维度

```
正确性 → 可读性 → 性能安全 → 测试覆盖
```

| 级别 | 处理 |
|------|------|
| must-fix | 阻塞合并 |
| should-fix | 建议改 |
| nit | 可选，不阻塞 |

**AI 时代**：AI 代码更要审事务、并发、安全。

---

## 2. ADR 模板

```
背景 → 目标/非目标 → 方案对比 → 决策 → 风险/回滚 → 监控
```

---

## 3. 估时排期

- WBS 拆到 **0.5～2 天**
- Buffer **20～30%**
- 区分必须 vs 可砍
- 风险前置：依赖、环境、迁移

---

## 4. 技术选型 5 步

```
1. 澄清需求（QPS、一致性、团队熟悉度）
2. 列 2～3 方案
3. 维度打分（性能、成本、运维、生态）
4. 选「够用」不选「最新」
5. 写 ADR
```

---

## 5. 故障复盘（5 Whys）

```
现象 → Why × N → 根因 → 改进项（负责人+DDL）→ 不追责个人
```

---

## 6. 跨团队沟通

| 对象 | 要点 |
|------|------|
| 产品 | 业务规则、边界、优先级 |
| 测试 | 可测性、环境、核心用例 |
| 运维 | 部署、监控、回滚 |
| 上级 | 风险透明、早要资源 |

**书面留痕**：会议纪要、结论、待办。

---

## 7. Mentoring

- 任务拆解、结对、Review 反馈
- 教排查思路，不只给答案
- 内部分享（费曼学习）

---

## 8. 技术影响力

- 文档沉淀（本知识库即例子）
- 规范制定：日志、异常、API、DB 变更
- 内部分享 / 博客 / 开源

---

## 9. STAR 面试法

```
S 情境 → T 任务 → A 行动 → R 结果（量化）
```

例：雪崩 → 负责稳定性 → 限流+扩容+复盘 → 99.9→99.95

---

## 10. 7 年 vs 3 年差异

| 3 年 | 7 年 |
|------|------|
| 实现需求 | 评估风险、写方案 |
| 修 bug | 建机制防复发 |
| 写代码 | Review + 带人 |
| 口头沟通 | 书面 + 跨团队 |
