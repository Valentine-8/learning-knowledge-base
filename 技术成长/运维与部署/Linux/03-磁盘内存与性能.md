# 03 · 磁盘内存与性能

> **预计阅读**：60 min · **难度**：★★★★

---

## 1. 磁盘空间

```bash
df -h                     # 文件系统使用率
df -i                     # inode 使用率
du -sh /*                 # 根下各目录大小
du -h --max-depth=1 /var/log
ncdu /                    # 交互式（需安装）
```

| 告警阈值 | 建议 |
|----------|------|
| > 85% | 清理或扩容 |
| inode 100% | 小文件过多，删临时/cache |

**常见占满路径**：`/var/log`、`/tmp`、应用日志目录、Docker `/var/lib/docker`。

---

## 2. 磁盘 IO

```bash
iostat -x 1 5             # %util await r/s w/s
iotop -o                  # 按 IO 排序进程
lsblk                     # 块设备
fdisk -l                  # 分区
```

| iostat 字段 | 含义 |
|-------------|------|
| %util | 设备繁忙度，接近 100% 饱和 |
| await | 平均 IO 等待 ms |
| svctm | 服务时间 |
| r/s w/s | 读写 IOPS |

**Java 场景**：GC 日志狂写、慢 SQL 临时表、日志未轮转导致 IO 高。

---

## 3. 内存

```bash
free -h
cat /proc/meminfo
```

```
              total   used   free   shared  buff/cache  available
Mem:           16G    12G    500M   100M    3.5G        3G
```

| 概念 | 说明 |
|------|------|
| buff/cache | 文件缓存，可回收 |
| available | 估算可用，比 free 更准 |
| Swap | 内存不足时换出，**Java 生产建议 swap=0 或很小** |

### OOM Killer

```bash
dmesg | grep -i "out of memory"
grep -i kill /var/log/messages
```

内存不足时内核杀进程（常选 RSS 最大）。Java 容器需设 `-Xmx` 和 cgroup limit 留余量。

---

## 4. CPU 与负载

```bash
top
htop
mpstat -P ALL 1
uptime                    # load average: 1.2, 1.5, 1.8
```

**Load Average**：运行队列 + 不可中断 IO 等待的平均长度。

| 规则 | 说明 |
|------|------|
| 单核 | load > 1 表示过载 |
| N 核 | load > N 需关注 |
| load 高 CPU 低 | IO 瓶颈（D 状态多） |

```bash
top 中：
%us  用户态
%sy  内核态
%wa  IO wait ← 高则查磁盘
%id  空闲
```

---

## 5. vmstat 综合

```bash
vmstat 1
# procs r b | memory swpd free buff cache | swap si so | io bi bo | system cs in | cpu us sy id wa
```

| 字段 | 关注 |
|------|------|
| r | 运行队列长度 |
| b | 阻塞进程（IO） |
| si/so | swap 换入换出，非 0 说明内存紧张 |
| bi/bo | 块 IO |

## 6. Java 进程性能排查

```bash
# CPU 高
top -Hp PID               # 找热点线程
printf '%x\n' TID
jstack PID | grep -A 20 hex_tid

# 内存
jmap -heap PID
jmap -histo:live PID | head -30
jcmd PID GC.heap_info

# 综合
arthas dashboard
```

## 7. 内核参数调优（生产常见）

`/etc/sysctl.conf`：

```ini
# 网络
net.core.somaxconn = 65535
net.ipv4.tcp_max_syn_backlog = 65535
net.ipv4.tcp_tw_reuse = 1
net.ipv4.ip_local_port_range = 1024 65535

# 内存
vm.swappiness = 10
vm.overcommit_memory = 0

# 文件
fs.file-max = 1000000
```

```bash
sysctl -p
```

**注意**：调参需压测验证，盲目抄配置有风险。

---

## 8. cgroup 与容器资源

```bash
# cgroup v1
cat /sys/fs/cgroup/memory/docker/<id>/memory.limit_in_bytes

# 容器内
cat /sys/fs/cgroup/memory.max
```

Java 在容器内需用 `-XX:+UseContainerSupport` 和 `MaxRAMPercentage`。

---

## 9. 性能 baseline

| 指标 | 正常参考 |
|------|----------|
| CPU us+sy | < 70%  sustained |
| %wa | < 10% |
| load | < CPU 核数 |
| 磁盘 %util | < 80% |
| Swap si/so | 0 |
| GC pause | < 200ms（视 SLA） |

---

## 10. 小结

| 要点 | 一句话 |
|------|--------|
| df/du | 空间；df -i 查 inode |
| iostat | %util 和 await 看 IO 瓶颈 |
| free | 看 available 不是 free |
| load | 结合 CPU 核数和 %wa 解读 |
