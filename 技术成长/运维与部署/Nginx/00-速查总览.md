## 1. 架构一图

```
                    Client
                      │
                      ▼
              ┌───────────────┐
              │  Nginx Master │  读配置、管理 Worker
              └───────┬───────┘
                      │ fork
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
    Worker 1      Worker 2      Worker N   ← 实际处理请求（事件驱动 epoll）
        │             │             │
        └─────────────┴─────────────┘
                      │
          ┌───────────┼───────────┐
          ▼           ▼           ▼
      静态文件    upstream 后端    FastCGI/uWSGI
                 (Java :8080)
```

## 2. 配置层级（作用域）

```
main（全局）  →  events  →  http  →  server  →  location
                                              ↑ 最常用
```

| 层级 | 典型指令 |
|------|----------|
| main | `worker_processes`、`error_log` |
| events | `worker_connections` |
| http | `gzip`、`upstream`、`include` |
| server | `listen`、`server_name`、`ssl_certificate` |
| location | `proxy_pass`、`root`、`try_files` |

**原则**：子块可继承父块；同类型指令子块覆盖父块。

## 3. 反向代理最小配置

```nginx
upstream backend {
    server 127.0.0.1:8080;
    server 127.0.0.1:8081;
}

server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 4. 负载均衡算法

| 方式 | 指令 | 场景 |
|------|------|------|
| 轮询（默认） | — | 后端同质 |
| 加权轮询 | `weight=3` | 机器配置不同 |
| IP Hash | `ip_hash;` | 会话粘滞（慎用，节点变化会乱） |
| 最少连接 | `least_conn;` | 长连接、耗时不均 |
| 一致性 Hash | `hash $request_uri consistent;` | 缓存节点固定（需第三方或 stream） |

## 5. HTTPS 最小配置

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    location / {
        proxy_pass http://backend;
    }
}
```

## 6. 限流速查

```nginx
# http 块
limit_req_zone $binary_remote_addr zone=api:10m rate=10r/s;

# location
limit_req zone=api burst=20 nodelay;
limit_conn addr 10;
```

| 指令 | 作用 |
|------|------|
| `limit_req_zone` | 定义限流区（按 IP 等 key） |
| `limit_req` | 应用漏桶，`burst` 允许突发 |
| `limit_conn` | 限制并发连接数 |

## 8. 面试 5 分钟版

| 问 | 答要点 |
|----|--------|
| Nginx 为什么高并发？ | 多 Worker + 事件驱动（epoll/kqueue）+ 非阻塞 IO，少量线程处理大量连接 |
| 反向代理 vs 正向代理？ | 反向：客户端不知道后端，Nginx 代后端接请求；正向：客户端知道代理（VPN） |
| `proxy_pass` 末尾有无 `/`？ | 有 `/` 会替换 location 前缀；无 `/` 会拼接 URI，易踩坑 |
| 502 vs 504？ | 502 上游无效响应/连接被拒；504 上游超时 |
| 如何做灰度？ | 按 cookie/header/权重 split upstream，或 OpenResty/Kong |
