# 02 · 工作负载与发布策略

> **目标读者**：掌握 Deployment 滚动更新、StatefulSet 场景、Job/CronJob、蓝绿与金丝雀思路。
> **预计阅读**：60 min · **难度**：★★★★

---

## 1. 工作负载类型选型

| 类型 | 场景 | Java 示例 |
|------|------|-----------|
| **Deployment** | 无状态 HTTP 服务 | Spring Boot 微服务 |
| **StatefulSet** | 稳定网络标识、有序部署 | Kafka、ES、有状态中间件 |
| **DaemonSet** | 每节点一个 Pod | 日志 agent、node-exporter |
| **Job** | 跑完即停 | 批处理、迁移脚本 |
| **CronJob** | 定时 | 对账、清理任务 |

## 2. 滚动更新（RollingUpdate）

```yaml
spec:
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 25%        # 最多超出期望副本数
      maxUnavailable: 25%  # 最多不可用比例
```

```
 replicas=3, maxSurge=1, maxUnavailable=0

 旧: [P1][P2][P3]
 新: [P1][P2][P3][N1]     ← 先起新
 新: [P1][P2][N1][N2]
 ...
 最终全为 N*
```

**零宕机发布**：`maxUnavailable: 0` + readiness 探针通过才接流量。

```bash
kubectl set image deployment/order-app app=order-app:1.0.2
kubectl rollout status deployment/order-app
kubectl rollout history deployment/order-app
kubectl rollout undo deployment/order-app
kubectl rollout undo deployment/order-app --to-revision=2
```

## 3. 蓝绿发布

两套 Deployment，`app=blue` / `app=green`，Service selector 一次切换：

```yaml
# 切换流量到 green
kubectl patch service order-app -p '{"spec":{"selector":{"version":"green"}}}'
```

| 优点 | 缺点 |
|------|------|
| 回滚快 | 双倍资源 |
| 流量切换清晰 | 数据库迁移需兼容双版本 |

---

## 4. 金丝雀（Canary）

**简易版**：两 Deployment，副本比 9:1

```yaml
# stable replicas: 9
# canary replicas: 1
# 同一 Service selector 只 match app=order（两版都带）
```

**进阶**：Argo Rollouts、Istio VirtualService 权重、Nginx Ingress canary annotation：

```yaml
metadata:
  annotations:
    nginx.ingress.kubernetes.io/canary: "true"
    nginx.ingress.kubernetes.io/canary-weight: "10"
```

## 5. StatefulSet 要点

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql-headless
  replicas: 3
  selector:
    matchLabels:
      app: mysql
  template:
    ...
  volumeClaimTemplates:
    - metadata:
        name: data
      spec:
        accessModes: ["ReadWriteOnce"]
        resources:
          requests:
            storage: 20Gi
```

| 特性 | 说明 |
|------|------|
| 稳定 hostname | `mysql-0`, `mysql-1` |
| 有序扩缩 | 0→1→2 顺序 |
| PVC 绑定 | 删 Pod 不删 PVC |

**Java 业务服务** 多数用 Deployment；中间件运维需懂 StatefulSet。

## 6. Job 与 CronJob

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: daily-report
spec:
  schedule: "0 2 * * *"
  jobTemplate:
    spec:
      template:
        spec:
          containers:
            - name: job
              image: report-job:1.0
          restartPolicy: OnFailure
```

Spring Batch 可打包镜像，CronJob 触发；或集群外调度 + 调 API。

## 7. 探针（与发布强相关）

| 探针 | 作用 | 失败后果 |
|------|------|----------|
| **startup** | 启动慢的应用 | 杀容器前给长 grace |
| **readiness** | 是否接 Service 流量 | 从 Endpoints 摘除 |
| **liveness** | 是否存活 | 重启容器 |

```yaml
startupProbe:
  httpGet:
    path: /actuator/health/liveness
    port: 8080
  failureThreshold: 30
  periodSeconds: 10
readinessProbe:
  httpGet:
    path: /actuator/health/readiness
    port: 8080
  periodSeconds: 5
livenessProbe:
  httpGet:
    path: /actuator/health/liveness
    port: 8080
  periodSeconds: 10
```

**滚动更新时**：新 Pod readiness 通过才继续，避免流量打到半启动实例。

**易错**：liveness 检依赖外部服务（MySQL）→ 连锁重启；liveness 应检 **进程本身**。

## 8. PodDisruptionBudget（PDB）

```yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: order-app-pdb
spec:
  minAvailable: 2
  selector:
    matchLabels:
      app: order-app
```

节点维护/驱逐时保证至少 2 个 Pod 可用。

## 9. HPA 预览

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: order-app-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: order-app
  minReplicas: 3
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
```

需 **metrics-server**；Java 建议结合自定义指标（QPS、线程池）。
