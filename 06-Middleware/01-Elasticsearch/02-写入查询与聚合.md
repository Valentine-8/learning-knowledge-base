# 02 · 写入查询与聚合

> **目标**：掌握 ES 写入流程与近实时机制、Query DSL 查询、聚合分析、BM25 评分，能编写生产级搜索请求。

---

## 一、写入流程

### 1.1 整体路径

```
1. Client 发送 Index 请求
2. Coordinating Node 路由：hash(_id) % shards → Primary Shard
3. Primary 写入：
   - 写入 Memory Buffer（内存）
   - 写入 Translog（预写日志，防丢）
4. Primary 复制到 Replica Shard
5. 返回客户端成功（默认只等 Primary + 部分 Replica）
6. refresh（默认 1s）→ segment 可读
7. flush（translog 大小/时间触发）→ commit segment 到磁盘
```

### 1.2 近实时（NRT）

| 阶段 | 可见性 |
|------|--------|
| 写入 Memory Buffer | 不可搜 |
| refresh 后 | **可搜**（默认 1s 内） |
| flush 后 | 持久化到磁盘 |

**refresh**：将 buffer 写入新 Segment，打开读取器，**不清空 translog**。

```json
PUT /products/_doc/1?refresh=wait_for
```

| refresh 参数 | 行为 |
|--------------|------|
| 默认 | 等 Index 级 refresh 周期 |
| `true` | 立即 refresh（慎用，影响性能） |
| `wait_for` | 等本次写入 refresh 后返回 |
| `false` | 不等待 |

### 1.3 Translog

- 每次写入先写 **translog**（事务日志）
- flush 时 translog 内容 commit 到 Lucene segment，然后清空
- 节点崩溃 → 未 flush 的数据从 translog 恢复

### 1.4 更新与删除

| 操作 | 底层 |
|------|------|
| **Update** | 标记旧文档 deleted + 插入新文档 |
| **Delete** | 标记 deleted（.tombstone） |
| **物理删除** | Segment merge 时 purge |

**结论**：频繁 update 产生大量 deleted docs，影响性能 → 批量导入用 bulk，少 update。

### 1.5 Bulk API

```json
POST /_bulk
{ "index": { "_index": "products", "_id": "1" } }
{ "title": "耳机", "price": 99 }
{ "index": { "_index": "products", "_id": "2" } }
{ "title": "键盘", "price": 199 }
```

**最佳实践**：
- 每批 5~15MB 或 1000~5000 条
- 同 Index 批量
- 失败重试需幂等（_id 固定）
- 关闭 refresh_interval（-1）大批量导入，完成后恢复

### 1.6 写入一致性

| 参数 | 说明 |
|------|------|
| `consistency=quorum` | 过半分片可用才写（默认 one） |
| `wait_for_active_shards` | 等待 N 个 active shard |

**生产**：副本 ≥ 1，`wait_for_active_shards=1` 或 all（高可靠场景）。

## 二、查询基础

### 2.1 搜索类型

| API | 说明 |
|-----|------|
| **URI Search** | `GET /index/_search?q=title:耳机` 简单但不灵活 |
| **Query DSL** | JSON body，**生产标准** |
| **_msearch** | 批量搜索 |

### 2.2 请求结构

```json
GET /products/_search
{
  "query": { ... },
  "from": 0,
  "size": 10,
  "sort": [ ... ],
  "_source": ["title", "price"],
  "highlight": { ... },
  "aggs": { ... }
}
```

| 参数 | 说明 |
|------|------|
| `from/size` | 分页（深分页有问题，见第三章） |
| `_source` | 返回字段过滤 |
| `track_total_hits` | 精确命中总数（默认 10000 上限） |

### 2.3 Query vs Filter Context

| Context | 评分 | 缓存 | 用途 |
|---------|------|------|------|
| **Query** | 算 _score | 否 | 全文、相关性 |
| **Filter** | 不算分 | 是 | 精确过滤、范围 |

**推荐**：可过滤的条件放 **filter**（bool.filter），性能更好。

## 三、Query DSL 详解

### 3.1 match 全文查询

```json
{
  "query": {
    "match": {
      "title": "无线 耳机"
    }
  }
}
```

- 对查询词 **分词** 后 OR 匹配（默认 operator=or）
- `operator: "and"` 全词匹配
- `minimum_should_match`: "75%"

**match_phrase**：短语匹配，词序一致。

```json
{ "match_phrase": { "title": { "query": "无线 耳机", "slop": 1 } } }
```

### 3.2 term 精确查询

```json
{
  "query": {
    "term": { "sku.keyword": "SKU-001" }
  }
}
```

- **不分词**，精确匹配 inverted index 中的 term
- text 字段需用 `.keyword` 子字段

### 3.3 terms 多值

```json
{ "terms": { "category.keyword": ["electronics", "books"] } }
```

### 3.4 range 范围

```json
{
  "query": {
    "range": {
      "price": { "gte": 100, "lte": 500 },
      "created_at": { "gte": "now-7d" }
    }
  }
}
```

### 3.5 bool 组合查询

```json
{
  "query": {
    "bool": {
      "must": [
        { "match": { "title": "耳机" } }
      ],
      "filter": [
        { "term": { "category.keyword": "electronics" } },
        { "range": { "price": { "lte": 500 } } }
      ],
      "should": [
        { "term": { "tags.keyword": "降噪" } }
      ],
      "must_not": [
        { "term": { "status.keyword": "deleted" } }
      ],
      "minimum_should_match": 1
    }
  }
}
```

| 子句 | 逻辑 | 评分 |
|------|------|------|
| must | AND | 参与 |
| filter | AND | 不参与 |
| should | OR | 参与（must 为空时至少匹配 min） |
| must_not | NOT | 不参与 |

### 3.6 其他常用 Query

| Query | 用途 |
|-------|------|
| **exists** | 字段存在 |
| **prefix** | 前缀 |
| **wildcard** | 通配符（慢，慎用） |
| **fuzzy** | 模糊拼写 |
| **nested** | 嵌套对象 |
| **geo_distance** | 地理距离 |
| **function_score** | 自定义打分 |

### 3.7 multi_match

```json
{
  "multi_match": {
    "query": "蓝牙耳机",
    "fields": ["title^3", "description"],
    "type": "best_fields"
  }
}
```

`^3` 字段权重 boost。

## 四、排序与分页

### 4.1 排序

```json
"sort": [
  { "price": "asc" },
  { "_score": "desc" }
]
```

- 排序字段需 **keyword/numeric + doc values**
- text 字段默认不可排序

### 4.2 深分页问题

`from=10000, size=10` → 每个分片取 10010 条，协调节点合并排序 → **内存爆炸**。

**解决**：
- **search_after**：游标分页，上一页 sort values
- **scroll**：快照导出（非实时）
- **PIT + search_after**（7.10+）：Point in Time 一致性读

```json
"search_after": [299, "doc_id_xxx"],
"sort": [{ "price": "asc" }, { "_id": "asc" }]
```

## 六、相关性评分

### 6.1 TF-IDF（旧版，5.x 前默认）

```
score = TF(词在文档频率) × IDF(词在全库稀有度) × field boost
```

### 6.2 BM25（5.x+ 默认）

```
BM25(q,d) = Σ IDF(qi) × (f(qi,d) × (k1+1)) / (f(qi,d) + k1×(1-b+b×|d|/avgdl))
```

| 参数 | 含义 |
|------|------|
| k1 | 词频饱和（默认 1.2） |
| b | 文档长度归一化（默认 0.75） |
| f(qi,d) | 词 qi 在文档 d 中频率 |
| \|d\| | 文档长度 |

**特点**：词频边际递减，长文档惩罚，比 TF-IDF 更稳健。

### 6.3 调优相关性

| 手段 | 说明 |
|------|------|
| field boost | 标题权重高于正文 |
| function_score | 销量、距离、时间衰减 |
| synonyms | 同义词扩展 |
| rescore | 两阶段打分，粗排+精排 |

```json
{
  "function_score": {
    "query": { "match": { "title": "耳机" } },
    "functions": [
      { "field_value_factor": { "field": "sales", "modifier": "log1p" } },
      { "gauss": { "created_at": { "origin": "now", "scale": "30d" } } }
    ],
    "score_mode": "sum",
    "boost_mode": "multiply"
  }
}
```

## 七、聚合（Aggregation）

### 7.1 聚合类型

| 类型 | 说明 | 类比 SQL |
|------|------|----------|
| **Metric** | 指标 | AVG/COUNT/SUM |
| **Bucket** | 分桶 | GROUP BY |
| **Pipeline** | 桶上再计算 | HAVING 子查询 |

### 7.2 Metric 聚合

```json
"aggs": {
  "avg_price": { "avg": { "field": "price" } },
  "max_price": { "max": { "field": "price" } },
  "total_sales": { "sum": { "field": "sales" } },
  "unique_users": { "cardinality": { "field": "user_id.keyword" } }
}
```

**cardinality**：HyperLogLog++ 基数估算，非精确。

### 7.3 Bucket 聚合

```json
"aggs": {
  "by_category": {
    "terms": { "field": "category.keyword", "size": 10 },
    "aggs": {
      "avg_price": { "avg": { "field": "price" } }
    }
  },
  "price_ranges": {
    "range": {
      "field": "price",
      "ranges": [
        { "to": 100 },
        { "from": 100, "to": 500 },
        { "from": 500 }
      ]
    }
  },
  "sales_over_time": {
    "date_histogram": {
      "field": "created_at",
      "calendar_interval": "day"
    }
  }
}
```

### 7.4 聚合注意事项

| 问题 | 处理 |
|------|------|
| text 字段聚合 | 用 keyword 子字段 |
| 高 cardinality terms | size 限制、composite 分页 |
| 内存 | `search.max_buckets` 默认 65535 |
| 精确去重 | cardinality 有误差；要精确用 scripted 或 transform |

### 7.5 Composite 聚合

深分页分桶：

```json
"aggs": {
  "my_buckets": {
    "composite": {
      "size": 100,
      "sources": [
        { "category": { "terms": { "field": "category.keyword" } } },
        { "brand": { "terms": { "field": "brand.keyword" } } }
      ]
    }
  }
}
```

## 八、Nested 与 Join

### 8.1 Nested

object 数组内部对象交叉匹配问题：

```json
{
  "comments": [
    { "user": "张三", "text": "好用" },
    { "user": "李四", "text": "差" }
  ]
}
```

普通 object 查询 `comments.user:张三 AND comments.text:差` 会误匹配。

**nested** 使每个数组元素独立索引：

```json
{
  "query": {
    "nested": {
      "path": "comments",
      "query": {
        "bool": {
          "must": [
            { "match": { "comments.user": "张三" } },
            { "match": { "comments.text": "好用" } }
          ]
        }
      }
    }
  }
}
```

### 8.2 Parent-Child（少用）

独立 Join 类型，子文档独立索引，更新灵活但查询慢。**推荐 nested 或 宽表冗余**。

## 十、查询性能优化

| 手段 | 说明 |
|------|------|
| filter 代替 query | 可缓存、不算分 |
| `_source` 过滤 | 减少网络 |
| routing | 指定 shard，减少 fan-out |
| preference=_local | 优先本地分片 |
| 避免 wildcard 前缀通配 | 极慢 |
| 控制 aggs size | 防止 OOM |
| 冷热分离 | 热 Index SSD，冷 Index 机械盘 |

## 十一、读写分离

- 默认：写 Primary，读可路由 Primary 或 Replica
- `preference=_replica_first`：优先副本读，减轻 Primary

## 十二、案例：商品搜索 DSL

```json
GET /products/_search
{
  "query": {
    "bool": {
      "must": [
        {
          "multi_match": {
            "query": "蓝牙 降噪",
            "fields": ["title^3", "description"],
            "type": "best_fields",
            "operator": "and"
          }
        }
      ],
      "filter": [
        { "term": { "status.keyword": "on_sale" } },
        { "range": { "price": { "gte": 50, "lte": 1000 } } }
      ]
    }
  },
  "sort": [
    { "_score": "desc" },
    { "sales": "desc" }
  ],
  "from": 0,
  "size": 20,
  "_source": ["title", "price", "image"],
  "highlight": {
    "fields": { "title": {} }
  },
  "aggs": {
    "price_stats": { "stats": { "field": "price" } },
    "brands": {
      "terms": { "field": "brand.keyword", "size": 10 }
    }
  }
}
```

|------|------|
| 写入 | buffer → translog → refresh → flush |

| 聚合 | terms/date_histogram + metric |
