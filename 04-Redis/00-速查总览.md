## 一、数据结构与应用

| 类型 | 底层 | 典型场景 |
|------|------|----------|
| String | SDS | 缓存、计数、分布式锁、Session |
| Hash | 哈希表/ziplist | 对象字段（用户信息） |
| List | quicklist | 简单队列（生产更常用 Stream） |
| Set | intset/hashtable | 去重、共同好友 |
| ZSet | 跳表+dict | 排行榜、延迟队列 |
| Stream | 链表 | 消息队列、消费者组 |
| Bitmap | String | 签到、布隆替代 |
| HyperLogLog | — | UV 统计（近似） |
| GEO | ZSet | 附近的人 |

## 二、持久化

| 方式 | 特点 |
|------|------|
| RDB | 快照，恢复快，可能丢最后一次数据 |
| AOF | 追加写，everysec 丢 1s；**重写**压缩 |
| 混合持久化 | RDB 头 + AOF 增量（4.0+） |

**选型**：要耐久 AOF；可接受分钟级丢失 RDB；都要可混合。

## 三、高可用架构

| 架构 | 说明 |
|------|------|
| 主从复制 | 异步复制，读扩展 |
| 哨兵 Sentinel | 自动故障转移，选新主 |
| Cluster | 16384 **槽**，CRC16 路由，无中心 |

**主从延迟**：读从库可能旧数据。

---

## 四、缓存三大问题

| 问题 | 现象 | 解法 |
|------|------|------|
| **穿透** | 查不存在的数据，打到 DB | 布隆过滤器；缓存空值短 TTL |
| **击穿** | 热点 key 过期瞬间打穿 DB | 互斥锁重建；逻辑过期（不设 TTL，异步更新） |
| **雪崩** | 大量 key 同时过期 / Redis 宕机 | 过期时间加随机；集群高可用；限流降级 |

---

## 五、缓存与 DB 一致性

| 策略 | 说明 |
|------|------|
| Cache Aside | 读：缓存→DB→回填；写：**先更 DB 再删缓存**（常用） |
| 延迟双删 | 删缓存→写 DB→sleep→再删 |
| 订阅 Binlog | Canal 异步删/更新缓存，最终一致 |

**没有银弹**：接受短暂不一致或强一致走 DB。

## 六、分布式锁

```redis
SET lock_key unique_value NX EX 30
-- 释放用 Lua：if get==unique then del
```

| 方案 | 说明 |
|------|------|
| 手写 SET NX | 要设过期防死锁；释放要校验 value |
| **Redisson** | 看门狗续期、可重入锁 |
| RedLock | 多主争议大，金融用 ZK/etcd |

**注意**：主从切换极端情况锁丢失。

---

## 七、其他生产问题

- **大 key**：阻塞、网络慢 → 拆分、压缩、异步删
- **热 key**：本地缓存、多副本、读写分离
- **内存淘汰**：volatile-lru、allkeys-lru 等 maxmemory-policy
- **单线程**：命令原子；别用 KEYS、慢命令

## 八、面试速答

| 问 | 答 |
|----|-----|
| Redis 为什么快？ | 内存、单线程无锁竞争、IO 多路复用、高效数据结构 |
| 单线程如何处理并发？ | 命令串行执行；多连接由 epoll 管理 |
| 持久化怎么选？ | 耐久 AOF/混合；可丢用 RDB |
| 分布式锁注意？ | NX+过期+唯一 value+Lua 释放；Redisson 看门狗 |
