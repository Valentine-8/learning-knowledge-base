# Phase 5 复习手册：MySQL · Redis · 分库分表

> **用法**：通读 50 min。索引、MVCC、Redis 数据结构、缓存三大问题是重中之重。

---

## 一、MySQL InnoDB 架构

```
SQL → 解析器 → 优化器 → 执行器
              ↓
Buffer Pool（数据页缓存）
Redo Log（崩溃恢复，WAL）
Undo Log（回滚 + MVCC 版本链）
Binlog（Server 层，主从复制）
```

| 日志 | 作用 |
|------|------|
| Redo | 物理日志，保证持久性 |
| Undo | 逻辑日志，多版本、事务回滚 |
| Binlog | 归档、主从、Canal 同步 |

**两阶段提交**：redo prepare → binlog → redo commit，保证 redo 与 binlog 一致。

## 二、索引（B+ 树）

| 概念 | 说明 |
|------|------|
| 聚簇索引 | 叶子存**整行**，InnoDB 主键即聚簇 |
| 二级索引 | 叶子存**主键值**，回表查聚簇 |
| 覆盖索引 | 查询列全在索引中，**不需回表** |
| 最左前缀 | 联合索引 (a,b,c) 可用 a / a,b / a,b,c |
| 索引下推 ICP | 5.6+ 在索引层过滤，减少回表 |

### explain 重点列

| 列 | 好 | 差 |
|----|-----|-----|
| type | const/ref/range | index/all |
| key | 用了索引 | NULL |
| rows | 少 | 大 |
| Extra | Using index | Using filesort/temporary |

### 优化口诀

- 最左前缀、避免函数/隐式转换导致索引失效
- 小表驱动大表、join 关联字段建索引
- 深分页：`WHERE id > last_id LIMIT n` 优于 `OFFSET` 大偏移

## 三、事务与锁

### 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|------------|------|
| RC | 否 | 可能 | 可能 |
| **RR（InnoDB 默认）** | 否 | 否 | **快照读无；当前读靠间隙锁** |

### MVCC

- 每行有隐藏列 `trx_id`、`roll_pointer`
- **Read View** 判断版本可见性 → **快照读**（普通 SELECT）
- **当前读**：`SELECT ... FOR UPDATE`、`UPDATE`、`DELETE` → 加锁

### 锁类型

| 锁 | 说明 |
|----|------|
| 记录锁 | 锁一行 |
| 间隙锁 Gap | 锁区间，防幻读 |
| Next-Key Lock | 记录锁 + 间隙锁 |

**死锁**：InnoDB 自动检测，回滚代价小的事务。

## 四、分库分表

| 类型 | 说明 |
|------|------|
| 垂直拆分 | 按业务/列拆表，冷数据分离 |

## 五、Redis

### 数据结构与应用

| 类型 | 底层 | 场景 |
|------|------|------|
| String | SDS | 缓存、计数、分布式锁 |
| Hash | 哈希表/压缩列表 | 对象字段 |
| List | 双向链表/quicklist | 消息队列（简单） |
| Set | 哈希/intset | 去重、共同好友 |
| ZSet | 跳表+哈希 | 排行榜、延迟队列 |
| Bitmap / HyperLogLog / GEO | — | 签到、UV、地理位置 |

### 持久化

| 方式 | 特点 |
|------|------|
| RDB | 快照，恢复快，可能丢最后一次 |
| AOF | 追加日志，可 everysec；重写压缩 |
| 混合 | 4.0+ RDB+AOF |

### 缓存三大问题

| 问题 | 解法 |
|------|------|
| **穿透** | 布隆过滤器；空值缓存 |
| **击穿** | 热点 key 互斥锁重建；逻辑过期 |
| **雪崩** | 过期时间加随机；集群高可用；限流降级 |

### 分布式锁

```
SET key uuid NX EX 30
释放：Lua 脚本比较 uuid 再 DEL（防删别人锁）
```

**Redisson**：看门狗自动续期；可重入。

**注意**：主从异步复制，极端情况锁丢失 → RedLock 有争议，金融场景用 ZooKeeper/etcd 更稳。

### 集群

- **主从**：读扩展，故障手动切换
- **哨兵**：自动故障转移
- **Cluster**：16384 槽位分片，去中心化

## 六、面试速答

| 问 | 答 |
|----|-----|
| 聚簇和非聚簇？ | InnoDB 主键聚簇存行；二级索引叶子存主键要回表 |
| RR 如何解决幻读？ | 快照读 MVCC；当前读 Next-Key Lock |
| Redis 单线程为什么快？ | 内存、IO 多路复用、无上下文切换 |
| 缓存和 DB 一致性？ | 先更 DB 再删缓存；延迟双删；订阅 binlog 异步删 |
| 雪花 ID 问题？ | 时钟回拨、机器 ID 配置；号段模式替代 |

## 七、易错点

- [ ] `WHERE column + 1 = 2` 索引失效
- [ ] 大 key、大 value 导致 Redis 阻塞和网络抖动
- [ ] 缓存不设过期 → 雪崩；热点不设互斥 → 击穿
- [ ] 事务里长查询占锁 → 死锁/阻塞
